# 📚 Study Timer — AI 공부 타이머

> **Python + AI 바이브 코딩으로 나만의 웹앱 만들기** 프로젝트 결과물
>
> Study Timer는 학생들이 과목별 공부 시간을 측정하고, 일별·주별 학습 통계를 대시보드로 확인할 수 있는 웹앱입니다.
> Flask(Python 웹 프레임워크)와 SQLite(경량 데이터베이스)를 사용하여 별도의 서버 설치 없이 내 컴퓨터에서 바로 실행할 수 있습니다.

## 📋 수업 요약 (1~4일차)

### 1일차 · 7/22 (화) — OT + 팀 빌딩 + 바이브 코딩 체험

#### ① OT + 바이브 코딩 실전 사례

4명 1팀으로 웹앱을 완성하는 프로젝트 방식을 안내하고, 코드 한 줄 없이 바이브 코딩만으로 만든 상용 서비스 **"링고팡"** 사례를 시연하였습니다. 코드 저장소·프롬프트 기록·서비스 화면을 순서대로 보여주며, "AI에게 잘 요청하면 실제 서비스를 만들 수 있다"는 신뢰를 형성하였습니다. AI 시대에는 코드 문법보다 **기획·문제 정의 능력**이 핵심임을 강조하였습니다.

#### ② 팀 빌딩 + 10가지 앱 주제 선택

4명씩 팀을 구성하고 역할(팀장·서기·발표자·시연자)을 배분한 뒤, **10가지 웹앱 주제**(공부 타이머, 할 일 관리, 가계부, 습관 트래커, 독서 기록장, 운동 기록, 감정 일기, 급식 메뉴 알리미, 학급 투표, 미니 게시판)를 소개하였습니다. 각 주제별로 "누구를 위한 앱인지, 어떤 문제를 해결하는지"를 설명하고, 팀별 토론을 거쳐 **study-timer(공부 타이머)**를 최종 주제로 선정하였습니다.

#### ③ 다 함께 바이브 코딩 체험 + study-timer 구상

선생님 화면에서 "간단한 공부 타이머 웹앱을 만들어 줘" 프롬프트를 학생들과 함께 만들어 Claude에 입력하고, 실시간으로 코드가 생성되는 과정을 관찰하였습니다. 학생들이 즉석으로 낸 아이디어("버튼 색 변경", "알림 소리 추가")를 추가 프롬프트로 반영하며 **study-timer를 어떻게 만들지 함께 구상**하였습니다. 자신들의 의견이 바로 화면에 반영되는 것을 보며 "AI에게 요청하는 감각"을 체감하였습니다.

> **활동소감**: 링고팡 사례를 통해 "코딩보다 기획이 중요하다"는 메시지가 자연스럽게 전달되었고, 학생들의 몰입도가 매우 높았습니다. 프롬프트 체험에서 자신들의 아이디어가 즉시 반영되는 것을 보며, 다음 시간에 직접 해보고 싶다는 기대감이 형성되었습니다.

> **특이사항 및 요청사항**: 링고팡 사례가 몰입도를 크게 높여, 이후 회차에도 실제 상용 서비스 사례를 짧게 삽입하는 방식을 이어가겠습니다. Python·VS Code 설치 가이드 사전 배포 및 Claude AI 계정 생성 관련 학부모 동의 안내문 발송을 요청드립니다.

### 2일차 · 7/24 (목) — 주제 구체화 + 바이브 코딩 개발론

#### ① 주제 깊이 있게 정리 + 팀별 발표

선정한 study-timer 주제를 3가지 기준(**①우리 팀이 직접 쓸 수 있는가 ②4회차 안에 만들 수 있는 규모인가 ③기존 앱과 뭐가 다른가**)으로 깊이 있게 토론하였습니다. "왜 이 주제를 골랐는가", "누가 쓸 것인가", "핵심 기능 3가지"를 A4 한 장에 정리하고 팀별 1분 발표로 공유한 뒤, 화이트보드에 전체 정리하였습니다.

#### ② 바이브 코딩 5단계 프로세스 시연

전통 개발(설계→코딩→테스트)과 바이브 코딩의 차이를 체계적으로 설명하고, **기획→프롬프트→생성→실행→수정**의 5단계를 실시간 시연하였습니다. 선생님 화면에서 프롬프트를 던지고, AI가 코드를 생성하고, 실행하고, 추가 요청으로 수정하는 전체 사이클을 보여주었습니다. 좋은 프롬프트의 핵심 요소(**맥락·역할·목표·제약**)를 예시와 함께 설명하고, 모호한 프롬프트 vs 구체적 프롬프트의 결과 차이를 비교하였습니다.

#### ③ 유저 시나리오 작성 실습

팀별로 **유저 시나리오 문서**를 작성하였습니다: **누가 쓸까?**(예: 시험 기간에 공부 시간을 체크하고 싶은 중학생) → **뭐가 불편할까?**(예: 기존 타이머 앱은 기록이 안 남고 광고가 많음) → **비슷한 건 뭐가 있을까?**(예: 통계 기록 + 무료 앱). 이 문서가 3·4회차에서 AI에게 전달할 프롬프트의 기초 자료가 됨을 강조하였습니다.

> **활동소감**: "무엇을 만들 것인가"를 직접 결정하고 "어떻게 만들 것인가"의 프로세스를 이해하는 시간이었습니다. 바이브 코딩 5단계 실시간 시연 후, 아직 코드를 작성하지 않았지만 "다음 시간에 직접 해보고 싶다"는 기대감이 형성되었습니다.

> **특이사항 및 요청사항**: 일부 팀이 주제 범위를 넓게 잡아 4회차 내 구현이 어려울 수 있어, 3회차 초반에 핵심 기능 3개로 범위를 재조정할 예정입니다. 개발 환경 미설치 학생을 위해 사전 설치 가이드를 사무국을 통해 배포 요청드리며, 유저 시나리오 문서는 결과 보고서 기초 자료로 별도 보관합니다.

### 3일차 · 7/29 (화) — 프론트엔드 개발 (HTML, CSS, JS)

#### ① 완성 제품 시연 + 화면 설계

2회차 유저 시나리오를 팀별로 재확인하고, 선생님이 사전에 완성한 참고 웹앱(**공부 타이머, AI 공부 매니저**)의 프론트엔드를 시연하며 HTML·CSS·JS 각각의 역할을 코드와 화면을 나란히 비교해 설명하였습니다. 팀별로 준비해 온 스케치를 바탕으로 **메인·입력·결과 화면의 와이어프레임**을 손그림으로 정리하고, 버튼·입력창·표시 영역을 라벨링하였습니다.

#### ② 다 함께 프롬프트 + 팀별 프론트엔드 생성

선생님 화면에서 "Flask 기반 index.html, 상단에 앱 이름, 중앙에 타이머, 하단에 시작·정지·리셋 버튼" 프롬프트를 함께 만든 뒤, 각 팀이 자기 와이어프레임을 바탕으로 **Claude에게 직접 프롬프트를 작성**하여 HTML을 생성하였습니다. 생성된 코드를 노트북에서 실행하고, 원하는 결과가 나오지 않으면 "버튼을 더 크게", "다크 모드로" 같은 자연어 요청으로 반복 개선하며 **"구체적인 프롬프트일수록 결과가 좋다"**는 것을 체감하였습니다.

#### ③ CSS/JS 기능 추가 + 중간 발표

CSS는 "미니멀 디자인으로 바꿔줘"처럼 추상적 요청도 실험하며 색상·폰트·여백을 다듬고, JavaScript는 **"시작 버튼을 누르면 25분 카운트다운, 0이 되면 알림음"**처럼 기능 단위로 요청하여 붙여 나갔습니다. 오류가 나면 오류 메시지를 그대로 Claude에 붙여넣어 원인을 파악·수정하는 **디버깅 흐름**을 함께 익혔습니다. 팀별로 완성된 화면을 1분씩 공유하고, 4회차에 붙일 백엔드에 필요한 데이터를 미리 생각해 오도록 안내하였습니다.

> **활동소감**: 학생들이 자기 팀만의 화면을 처음으로 브라우저에 띄운 시간으로, "한 문장으로 화면이 바뀐다"는 경험에 몰입도가 매우 높았습니다. 프롬프트를 짧고 모호하게 쓴 팀은 시행착오를 겪으며 "왜 구체적으로 써야 하는가"를 자연스럽게 체득하였습니다.

> **특이사항 및 요청사항**: 팀별 진도 차이가 벌어져, 다음 회차에서 진도가 빠른 팀에게는 추가 기능(로그인, 데이터 시각화)을 도전 과제로 부여할 예정입니다. 우수 팀의 프롬프트 사례를 사무국을 통해 정리·공유하면 이후 기수에도 참고 자료로 활용할 수 있을 것 같습니다.

### 4일차 · 7/31 (목) — 백엔드 개발 (Flask + SQLite) + 최종 발표

#### ① 백엔드 개념 + DB 설계

완성된 "AI 공부 매니저"의 **SQLite DB 파일을 직접 열어** 데이터가 어떻게 저장·조회되는지 보여주며 백엔드의 역할을 설명하였습니다. 프론트엔드와 백엔드의 차이를 **식당의 홀(화면)·주방(서버) 비유**로 압축하고, SQLite의 테이블·컬럼·행 구조를 시각적으로 설명하였습니다. 팀별로 자기 앱에 필요한 데이터 목록을 빠르게 정리하였습니다(예: `study_records(id, 날짜, 과목, 공부시간, 메모)`).

#### ② 다 함께 프롬프트 + CRUD 구현 + 프론트-백 연동

선생님 화면에서 "Flask에서 SQLite DB를 연결하고 공부 기록을 저장·조회하는 코드를 만들어 줘" 프롬프트를 함께 만들고, **CRUD(생성·조회·수정·삭제)** 흐름을 시연하였습니다. 각 팀이 자기 앱의 백엔드 코드를 생성·실행하고 DB Browser로 저장을 확인한 뒤, 3회차 프론트엔드와 **fetch()로 연동**하여 완전히 동작하는 웹앱을 완성하였습니다. 팀원 간 **페어 테스트**로 버그와 개선점을 즉석에서 수정하였습니다.

#### ③ 최종 발표 + 회고 + 수료

팀별 **3분 시연 발표**(앱 이름·해결한 문제·핵심 기능 시연·인상 깊었던 프롬프트·개선하고 싶은 점)를 진행하였습니다. 4회차 여정을 돌아보며 "가장 어려웠던 순간", "가장 뿌듯했던 순간", "AI와 함께 코딩하며 배운 것"을 나누는 **회고** 시간을 가졌습니다. GitHub에 최종 커밋·푸시하고 README.md를 정리하여 포트폴리오로 남기는 방법을 안내하고, 다음 단계 도전 과제(모바일 앱, 배포, 데이터 시각화)를 소개하며 수료하였습니다.

> **활동소감**: "백엔드는 어렵다"는 처음의 두려움이 Claude와 함께 한 줄씩 만들어 가면서 "이해할 수 있는 코드"로 바뀌었습니다. 최종 발표에서 학생들이 자기 앱을 소개하는 모습에서 "지식 소비자에서 생산자로"라는 프로젝트 목표가 실현되었습니다.

> **특이사항 및 요청사항**: 팀별 완성도가 예상보다 높아 학교 축제나 학급 활동에서 실제 활용 가능한 앱들이 나왔으며, 내부 공유회 개최를 검토 요청드립니다. 심화 과정(2기)에 대한 학생·학부모 요청이 다수 있어 별도 기획 논의를 요청드리며, GitHub 저장소와 발표 자료는 별도 제출하겠습니다.

## 🚀 실행 방법 (초보자용 가이드)

### STEP 1. Python 설치

Python은 이 프로젝트를 실행하는 프로그래밍 언어입니다. 컴퓨터에 Python이 없으면 코드를 실행할 수 없습니다.

1. [python.org](https://www.python.org/downloads/) 에 접속합니다.
2. **Download Python 3.x.x** 버튼을 클릭하여 다운로드합니다.
3. 설치 시 **반드시** ✅ `Add Python to PATH` 체크박스를 체크한 뒤 Install을 누릅니다.
4. 설치가 완료되면 터미널(또는 명령 프롬프트)을 열고 아래 명령어로 확인합니다:

```bash
python --version
```

> `Python 3.x.x` 처럼 버전이 표시되면 성공입니다.
> Mac에서는 `python3 --version`으로 확인할 수 있습니다.

### STEP 2. VS Code 설치

VS Code는 코드를 보고 편집할 수 있는 편집기입니다. 메모장보다 훨씬 편리합니다.

1. [code.visualstudio.com](https://code.visualstudio.com/) 에 접속합니다.
2. **Download** 버튼을 눌러 설치합니다.
3. 설치 후 VS Code를 열고, 왼쪽 확장(Extensions) 탭에서 **Python** 확장을 검색하여 설치합니다.

### STEP 3. 프로젝트 폴더로 이동

터미널(Mac) 또는 명령 프롬프트(Windows)를 열고, `cd` 명령어로 study-timer 폴더로 이동합니다.

> 💡 `cd`는 **C**hange **D**irectory의 약자로, "이 폴더로 이동해줘"라는 뜻입니다.

```bash
cd Documents/GitHub/with_python_streamlit/study-timer
```

> 📌 **VS Code에서 더 쉽게 하는 방법**: VS Code에서 `파일 → 폴더 열기`로 study-timer 폴더를 열면, 내장 터미널(`` Ctrl+` `` 또는 `터미널 → 새 터미널`)이 자동으로 해당 폴더에서 시작됩니다.

### STEP 4. 필요한 패키지 설치 (pip)

> 💡 `pip`는 Python의 **패키지 관리자**입니다. 앱스토어에서 앱을 설치하듯이, pip으로 Python 라이브러리를 설치합니다.

```bash
python -m pip install -r requirements.txt
```

**이 명령어의 의미:**

| 부분 | 뜻 |
|------|-----|
| `python -m pip` | Python에 내장된 pip를 실행해줘 |
| `install` | 설치해줘 |
| `-r requirements.txt` | requirements.txt 파일에 적힌 목록을 읽어서 (`-r` = read) |

> 이 프로젝트는 `flask`만 필요합니다. Flask는 Python으로 웹 서버를 만드는 프레임워크입니다.

> ⚠️ Mac 사용자는 `python3 -m pip install -r requirements.txt`로 실행하세요.

### STEP 5. 서버 실행

```bash
python app.py
```

**이 명령어의 의미:**

| 부분 | 뜻 |
|------|-----|
| `python` | Python으로 |
| `app.py` | app.py 파일을 실행해줘 |

> ⚠️ Mac 사용자는 `python3 app.py`로 실행하세요.

실행하면 터미널에 아래와 같은 메시지가 나타납니다:

```
 * Running on http://0.0.0.0:5055
 * Debugger is active!
```

### STEP 6. 브라우저에서 확인

웹 브라우저(Chrome 등)를 열고 주소창에 입력합니다:

```
http://localhost:5055
```

> 💡 `localhost`는 "내 컴퓨터"를 뜻하고, `5055`는 서버가 열린 포트(문) 번호입니다.
> 즉, "내 컴퓨터의 5055번 문으로 접속해줘"라는 의미입니다.

🎉 **공부 타이머 화면이 나타나면 성공입니다!**

### 서버 종료

터미널에서 `Ctrl + C`를 누르면 서버가 종료됩니다.

## 🔧 문제가 생겼을 때

| 증상 | 해결 방법 |
|------|-----------|
| `python: command not found` | Python 설치 시 `Add to PATH`를 체크하지 않은 경우. Python을 재설치하고 체크해주세요. Mac은 `python3`으로 시도하세요. |
| `ModuleNotFoundError: No module named 'flask'` | Step 4의 pip install을 실행하지 않은 경우. `python -m pip install -r requirements.txt`를 실행하세요. |
| `Address already in use` | 이미 서버가 실행 중입니다. 터미널에서 `Ctrl+C`로 종료 후 다시 실행하세요. |
| 브라우저에 아무것도 안 나옴 | 주소가 `http://localhost:5055`인지 확인하세요. `https`가 아닌 `http`입니다. |
