# PPT 4
# OECD가 말하는 미래 인재상

OECD(경제협력개발기구)는 전 세계 **38개 선진국**이 모인 곳이다.
"2030년에 어떤 사람이 필요한가?"를 연구한 것이 **OECD Education 2030**이다.

### 핵심 역량 3가지

| 역량 | 쉽게 말하면 |
|---|---|
| **새로운 가치 창조** (Creating New Value) | 남이 안 해본 것을 만들어내는 능력 |
| **긴장과 딜레마 조정** (Reconciling Tensions) | 서로 다른 의견을 조율하는 능력 |
| **책임감** (Taking Responsibility) | 내가 한 일에 대해 끝까지 책임지는 태도 |

그리고 이 모든 것의 바탕에 **학생 주도성(Student Agency)**이 있다.
"내가 내 학습의 주인공이 되는 것."

# PPT 7
# BG vs AG — AI 이전과 이후, 모든 것이 바뀌었다

**BG** = Before Gen-AI (AI가 나오기 전)
**AG** = After Gen-AI (AI가 나온 후)

| 구분 | BG (AI 이전) | AG (AI 이후) |
|---|---|---|
| **목표** | 좋은 직장에 취업 | 직접 직업을 만든다 (**창직**) |
| **무기** | 스펙 (학점, 토익, 자격증) | 포트폴리오 (내가 만든 것) |
| **학습 방식** | 강의 듣기 → 암기 → 시험 | 문제 발견 → 만들기 → 런칭 |
| **실패 해석** | 좌절, 경로 이탈 | 데이터 수집, 다시 도전 |
| **AI 활용** | AI에 질문 1개 (수동적) | 여러 AI를 동시에 지휘 (능동적) |
| **수익 구조** | 월급 (고정, 한정적) | 내가 만든 것의 수익 (확장 가능) |
| **핵심 역량** | 지식 암기량 | 문제 정의력 + AI 활용력 |
| **코딩** | 문법을 외워서 직접 짠다 | AI한테 말해서 만든다 (바이브 코딩) |

# 교육 패러다임 전환 3단계

### 1단계: 산업화 시대 (1970~2010)
- 암기 중심, 객관식 평가
- 교사가 정답을 알려준다
- **"외워라, 시험에 나온다"**

### 2단계: 정보화 시대 (2010~2022)
- 자기주도학습, 수행평가 도입
- 학생이 정보를 검색한다
- **"검색해봐, 답이 있다"**

### 3단계: AI 시대 (2023~현재)
- 프로젝트 기반, 논술/서술/구술
- 학생이 AI를 지휘하여 가치를 만든다
- **"질문해라, 만들어라, 보여줘라"**

# PPT 9
# AI가 대체하는 것 vs 대체 못 하는 것

### 위험 영역 — AI가 대체하는 능력
- 정보 검색/요약
- 번역/문법 교정
- 단순 코딩
- 데이터 정리/분석
- 객관식 문제 풀이

> 전통 수능 교육이 주로 가르치는 것. AI에 의해 **가치가 사라지는 중.**

### 안전 영역 — AI가 대체 못 하는 능력
- **문제 정의** — "무엇이 문제인가?"
- **윤리적 판단** — "이것이 옳은가?"
- **공감/설득** — "왜 해야 하는가?"
- **AI 오케스트레이션** — "어떤 AI를 어떻게 쓸까?"
- **가치 판단** — "무엇을 만들 것인가?"

> IB/KB/프로젝트 교육이 가르치는 것. AI 시대에 **가치가 폭등하는 중.**

# PPT 12
# 학생의 역할이 바뀐다 — 소비자에서 생산자로

| 시대 | 학생의 역할 | 주요 활동 | 평가 방식 |
|---|---|---|---|
| **과거** (수능 시대) | 지식의 **소비자** | 읽기, 듣기, 외우기 | 객관식 (정답 맞히기) |
| **현재** (전환기) | 지식의 **탐구자** | 읽기 + 질문하기 + 정리하기 | 서술형 + 수행평가 |
| **미래** (AI 시대) | 지식의 **생산자** | **쓰기, 말하기, 만들기, 발표하기** | 논술 + 구술 + 프로젝트 |

### 과거: 읽고 듣는 문화
교과서 읽기 → 강의 듣기 → 필기 → 암기 → 시험
- 학생 발언 시간: 하루 **5~10분**
- 주인공: **선생님**
- 정보 방향: 선생님 → 학생 (**일방향**)

### 미래: 쓰고 말하는 문화
질문 만들기 → 토론 → 에세이 쓰기 → 발표 → 피드백 → 다시 쓰기
- 학생 발언 시간: 하루 **120~180분**
- 주인공: **학생**
- 정보 방향: 학생 ↔ 학생 ↔ 선생님 (**다방향**)

# PPT 14
# 지식의 벽이 무너지고 있다

### 과거 — 지식에는 벽이 있었다
- 좋은 대학 교수님만 아는 지식이 있었다
- 비싼 교과서를 사야 배울 수 있었다
- 영어를 못하면 해외 논문을 읽을 수 없었다
- 지식을 **"가진 사람"**이 이겼다. 그래서 **"암기"**가 중요했다.

### 현재 — 지식의 벽이 사라졌다
- AI한테 물어보면 대학 교수 수준의 설명을 받을 수 있다
- 한국어로 물어봐도 영어 논문을 요약해준다
- 서울이든 제주든, 인터넷만 되면 같은 수준의 정보를 얻는다
- **무료다.**

### 지식의 가치 변화

| 과거에 가치 있던 것 | 미래에 가치 있는 것 |
|---|---|
| 많이 외운 사람 | **잘 질문하는 사람** |
| 영어 잘하는 사람 | **문제를 정의하는 사람** |
| 코드 잘 짜는 사람 | **AI를 지휘하는 사람** |
| 정보를 가진 사람 | **정보를 가치로 바꾸는 사람** |

> **지식을 아는 것은 더 이상 힘이 아니다.**
> **지식을 가지고 뭘 만드느냐가 힘이다.**

# PPT 15
# AI로 맞춤형 질문과 답변이 가능한 시대

### 학원/과외 vs AI 학습

| 구분 | 학원/과외 | AI 학습 |
|---|---|---|
| 비용 | 월 30~100만원 | 무료~월 2만원 |
| 시간 | 정해진 시간에만 | 24시간 아무 때나 |
| 수준 | 반 전체 같은 수준 | **나에게 맞춘 수준** |
| 질문 횟수 | 제한적 | **무제한** |
| 반복 설명 | 눈치 보임 | **100번 물어봐도 OK** |
| 언어 | 한국어만 | 모든 언어 가능 |
| 실습 | 제한적 | AI가 코드까지 만들어줌 |

### 과거 vs AI 시대 공부 흐름

**과거**: 모르면 → 선생님(수업 시간에만) → 학원(돈) → 교과서 다시 읽기 → **포기**

**AI 시대**: 모르면 → AI에 바로 질문(24시간, 무료) → "더 쉽게 설명해줘" → "그럼 이건?" → "파이썬으로 만들어봐" → **포기할 이유가 사라진다**

# PPT 16
# 하루 100개 질문 — AI 시대의 새로운 공부법

### 피타고라스 정리 하나로 100개 질문이 가능하다

| 질문 번호 | 질문 내용 | 확장 분야 |
|---|---|---|
| 1 | "피타고라스 정리가 뭐야? 12살이 이해할 수 있게" | 수학 기초 |
| 2 | "왜 직각삼각형에서만 성립해?" | 수학 원리 |
| 3 | "실생활에서 이걸 어디에 써?" | 실생활 연결 |
| 5 | "게임에서 캐릭터 사이 거리 구할 때 쓴다고?" | 게임 개발 |
| 6 | "파이썬으로 거리 계산 코드 보여줘" | 코딩 |
| 7 | "그 코드를 앱으로 만들 수 있어?" | 앱 개발 |
| 8 | "피타고라스는 누구야?" | 역사 |
| 50 | "3D로 확장하면?" | 심화 수학 |
| 100 | "이 개념으로 앱 기획서 만들어줘" | 기획 |

> **10개 질문 만에** 수학 공식 → 실생활 → 역사 → 코딩 → 앱 아이디어까지 갔다.
> 매일 100개씩 하면 1달이면 **3,000개 질문.**
> **질문하는 능력 자체가 실력이 되는 시대다.**

# PPT 17
# AI한테 잘 물어보는 법

| 나쁜 질문 | 좋은 질문 | 왜 다른가 |
|---|---|---|
| "피타고라스 알려줘" | "피타고라스 정리를 12살이 이해할 수 있게 비유로 설명해줘" | **구체적**일수록 답이 좋다 |
| "코드 짜줘" | "급식 별점 앱인데, 별점은 1~5점이고, 제출 버튼이 있어. Python Streamlit으로" | **맥락과 조건**을 알려줘야 |
| "이거 왜 안 돼?" | "이 에러 메시지가 떴는데, 원인이 뭐고 어떻게 고쳐?" | **문제를 정확히** 설명해야 |
| "작문해줘" | "환경 문제 찬반 논점 3개씩, 내 입장 논증하는 에세이 구조 잡아줘" | AI를 도구로 쓰되 **생각은 내가** |

> **AI는 네가 물어보는 만큼만 알려준다.**
> 잘 물어보는 사람이 더 많이 배운다.
> 이건 시험 공부만이 아니라, 코딩할 때도, 프로젝트 만들 때도, 직장에서도 똑같다.

# PPT 19
# IB(국제 바칼로레아)란 무엇인가?

| 항목 | 내용 |
|---|---|
| 만든 곳 | 스위스 IBO (1968년 설립) |
| 사용 국가 | 전 세계 **160개국**, 5,700개+ 학교 |
| 핵심 | 시험 점수가 아니라 **직접 연구하고 결과물을 만들어서 제출** |
| 평가 방식 | **서술형 100%** — 객관식이 단 하나도 없다 |
| 한국 현황 | 전국 386교 도입 (인증 106교) |

### IB의 핵심 3가지

| 이름 | 무엇인가 | 쉽게 말하면 |
|---|---|---|
| **EE** (Extended Essay) | 4,000단어 연구 논문 | 대학 졸업 논문의 고등학생 버전 |
| **TOK** (Theory of Knowledge) | "우리는 어떻게 아는가?" 탐구 | 정답이 아니라 **"좋은 질문"을 만드는 훈련** |
| **CAS** (Creativity, Activity, Service) | 18개월 창의/활동/봉사 | 만들고, 움직이고, 도우며 성장하기 |

### 왜 IB에 열광하나?
- IB 졸업생의 대학 중퇴율이 일반 학생보다 **30~40% 낮다**
- IB 졸업생의 대학 1학년 GPA가 **0.3~0.5점 높다**
- 수능 없이 서울대에 합격한 사례가 나왔다 (표선고)

### KB(한국형 바칼로레아)란?

IB의 **"정신"**은 가져오고 **"껍데기"**는 벗겨낸 것

- IBO 인증비, 영어 장벽, 1% 엘리트 구조 → **버림**
- **한국어 100%, 비용 0원, 전 학교 대상**

> **IB** = 명품 수입차. 성능은 검증됐지만 비싸고 매뉴얼이 영어
> **KB** = 그 수입차를 뜯어보고 만든 국산차. 값은 무료, 매뉴얼은 한국어

# PPT 31
# 바이브 코딩 — 말하면서 만드는 시대

### 바이브 코딩(Vibe Coding)이란?
코드를 외워서 치는 것이 아니라, **AI에게 "원하는 것"을 정확히 설명하고 → 결과를 확인하고 → 다시 요청하며 다듬는** 개발 방식

### 옛날 코딩 vs 바이브 코딩

**옛날 코딩**: 파이썬 문법 공부 → for문 → if문 → 에러 → 구글링 → 수정 → **몇 달. 대부분 포기.**

**바이브 코딩**: "급식 별점 앱 만들어줘. 별점 1~5점, 제출 버튼 있어" → AI가 코드 생성 → 실행 → "버튼 색 바꿔줘" → **몇 시간이면 완성. 코딩 몰라도 됨.**

### 바이브 코딩에서 사람 vs AI

| 사람이 하는 것 | AI가 하는 것 |
|---|---|
| "뭘 만들지?" 정하기 | 코드 작성 |
| "누가 쓸 건데?" 생각하기 | 에러 수정 |
| "이거 쓰기 편해?" 판단하기 | 반복 작업 |
| "왜 안 되지?" 원인 찾기 | 빠른 검색 |
| 전체 구조 설계 | 세부 구현 |

> 코딩은 AI가 해준다.
> 근데 **"뭘 만들지 정하고, 써보고, 더 좋게 고치는 건 사람만 할 수 있다."**

# PPT 33
# 아키텍처 — 전체 구조를 그리는 능력

건물을 짓기 전에 설계도를 그리듯, 앱을 만들기 전에 **전체 구조를 설계하는 것**이다.

### 예시: 급식 별점 앱 아키텍처

사용자 → 메인 화면 → 급식 메뉴 선택 → 별점 입력(1~5) → 한줄평 입력 → 제출(데이터 저장) → 통계 대시보드(인기 메뉴 TOP 5, 별점 추이, 한줄평 모음)

> 이 구조를 그릴 줄 아는 사람이 AI한테 **"이거 만들어줘"**라고 말할 수 있다.
> 구조를 모르면 AI한테 **뭘 시켜야 하는지도 모른다.**

### 코딩 능력 vs 아키텍처 능력

| 코딩 능력 | 아키텍처 능력 |
|---|---|
| `for i in range(10):` 같은 문법 | "데이터가 어디서 어디로 흘러가는가?" |
| 변수 이름 짓기 | "사용자가 어떤 순서로 화면을 보는가?" |
| AI가 **대체 가능** | AI가 **대체 불가능** |

# PPT 34
# 전공 지식 + AI = 진짜 실력

### 핵심 공식

> 전공 지식(내가 잘 아는 것) + AI(코드를 짜주고, 분석해주는 도구) + 기획력(뭘 만들지, 누가 쓸지, 왜 필요한지) = **나만의 서비스, 나만의 직업, 나만의 포트폴리오**

| 전공/관심 분야 | + AI 하면 | 가능한 결과물 | 수익 모델 |
|---|---|---|---|
| 축구 | 경기 데이터 분석 | 전술 분석 앱 | 구독 서비스 |
| 웹툰 | 캐릭터/스토리 생성 | AI 웹툰 도우미 | 프리미엄 기능 |
| 요리 | 레시피 추천 알고리즘 | 냉장고 재료 추천 앱 | 광고 + 협찬 |
| 환경 | 이미지 인식 AI | 쓰레기 분류 도우미 | 환경 포인트 |
| 음악 | 화성학 + 멜로디 생성 | AI 작곡 보조 앱 | 건당 과금 |
| 동물 | 자연어 처리 | 펫 증상 AI 상담 | 병원 연계 수수료 |
| 학교생활 | 설문/분석 AI | 학교 설문 조사 앱 | 학교 구독 |

> **AI만 잘 쓰는 사람?** — 남들도 다 쓴다. 차별화 안 됨.
> **전공만 깊은 사람?** — AI 없으면 만드는 데 시간이 너무 오래 걸림.
> **전공 + AI?** — 이건 **나만 할 수 있다.** 이게 미래의 경쟁력이다.

| 외워서 공부 | 만들면서 공부 |
|---|---|
| 시험 끝나면 까먹음 | 한 번 만들면 안 까먹음 |
| 혼자 함 | 팀이랑 함 |
| 정답이 정해져 있음 | 정답이 없음 (내가 정함) |
| 재미없음 | 내가 만든 거라 재미있음 |
| 교과서 → 시험 → 끝 | 기획 → 만들기 → 피드백 → 개선 → 런칭 |
| 수동적 | 능동적 |
| AI가 대체할 수 있는 능력 | AI가 대체할 수 없는 능력 |

### 프로젝트식 공부의 흐름

"이걸로 뭘 만들 수 있지?" → 팀이랑 기획 → AI한테 물어보며 만들기 → 안 되는 거 발견 → 고치기 → 다른 사람한테 보여주기 → 피드백 받기 → 더 좋게 만들기

> **프로젝트를 만드는 과정 자체가 공부다.**
> 급식 앱을 만들면서 데이터를 배우고,
> 추천 테스트를 만들면서 알고리즘을 배우고,
> 발표를 준비하면서 글쓰기를 배운다.

# PPT 37
# 만드는 4단계 — 프로와 똑같은 과정

| 단계 | 뭘 하나 | 누가 하나 | 예시 |
|---|---|---|---|
| **1. 정하기** | "누구한테, 어떤 문제를 풀어줄 건데?" | **사람** | "우리 반 친구들이 급식 별점을 매기는 앱" |
| **2. 그리기** | "화면이 어떤 순서로 넘어가?" | **사람** | 종이에: 시작 화면 → 별점 → 차트 |
| **3. 만들기** | AI한테 설명해서 코드를 받는다 | **AI** | "별점 슬라이더 만들어줘" |
| **4. 고치기** | 직접 써보고 불편한 곳을 고친다 | **사람** | "버튼이 너무 작아" → "크게 해줘" |

> 4단계 중 AI가 하는 건 **3단계 하나뿐.**
> 나머지 3개는 전부 사람이 한다.
> 그래서 코딩 실력보다 **"뭘 만들지 정하는 힘"이 더 중요하다.**

### 수업 프로젝트를 상업용까지 가져간다면?

| 프로젝트 | 수업에서 끝내면 | 한 단계 더 가면 (상업용) |
|---|---|---|
| 급식 별점 앱 | 우리 반만 씀 | 전국 학교에 배포 → 광고 수익 |
| 취향 추천 테스트 | 친구들끼리 공유 | SNS 바이럴 → 브랜드 협찬 |
| AI 과목 튜터 | 수업 때만 | 구독 서비스 → 월 수익 |

> **"학생이니까 돈 얘기는 나중에"가 아니다.**
> "누가 쓸까? 돈을 낼까?"를 생각하는 게 **진짜 기획**이다.

| 급식 | 평가 | 급식 별점 + 리뷰 앱 |
