# 파이썬 × Streamlit × AI 바이브 코딩 프로젝트 수업 커리큘럼

> **대상** : 중학교 2학년
> **구성** : 2시간 × 4회 = 총 8시간 (매주 2회 수업, 2주 완성)
> **팀 구성** : 5명 = 1팀 (하나의 프로젝트를 함께 완성)
> **도구** : Python, Streamlit, AI 코딩 도구(바이브 코딩)
> **운영 철학** : 주입식 강의 ❌ → 하나의 프로젝트를 팀이 "함께 만들어가는 과정" ⭕

---

## 1. 수업 설계의 핵심 아이디어

### 1-1. 개발 방법론 공식

```
백엔드(Python) + 프론트엔드(Streamlit) + 전공·관심 분야 + AI
= 어떤 분야든 나만의 서비스를 만들 수 있다
```

- **파이썬은 백엔드 언어**다. 그 자체로는 화면이 없어 재미가 없다.
- 하지만 **Streamlit**을 쓰면 데이터 사이언스 기반의 프론트 페이지를 아주 쉽게 만들고, 간단한 입출력(버튼, 입력창, 차트)을 바로 붙일 수 있다.
- 여기에 **자신의 관심 분야**(게임, 음악, 웹툰, 학교생활…)와 **AI**를 더하면, 모든 분야에서 통하는 개발 방법이 된다.

### 1-2. "서버가 필요할까?" 판단 기준

| 무엇을 만드는가 | 공간의 성격 | 서버 필요 여부 |
|---|---|---|
| 나 혼자 쓰는 툴 | 개인만의 공간 | ❌ 내 컴퓨터에서 실행하면 끝 |
| 친구·반 친구와 함께 쓰는 툴 | 공유의 공간 | ⭕ 배포/서버 필요 (Streamlit Cloud 등) |

→ OT에서 이 기준을 먼저 세우고, 우리 팀 프로젝트가 어느 쪽인지 **팀이 스스로 판단**하게 한다.

### 1-3. 바이브 코딩(Vibe Coding)이란?

- 코드를 한 줄씩 외워서 치는 것이 아니라, **AI에게 "원하는 것"을 정확히 설명하고 → 결과를 확인하고 → 다시 요청하며 다듬는** 개발 방식.
- 이 수업에서 학생이 배우는 진짜 능력은 문법 암기가 아니라 **"무엇을 만들지 정의하고, AI와 대화하며 완성해가는 개발 프로세스"**다.

## 2. 공통 1회차 — OT : 개발 방법론 (2시간)

> 3가지 버전 모두 1회차는 동일하게 진행합니다.

| 시간 | 내용 | 운영 방식 |
|---|---|---|
| 0:00 ~ 0:20 | **아이스브레이킹 & 팀 빌딩** — 5명 1팀, 역할 정하기 (PM / 기획 / 디자인·화면 / 데이터 / 발표) | 팀 활동 |
| 0:20 ~ 0:50 | **개발 방법론 강의** — 백엔드 + 프론트엔드 + 전공(관심 분야) + AI 공식 설명. "개발자는 특별한 사람이 아니라, 문제를 정의하는 사람" | 미니 강의 |
| 0:50 ~ 1:10 | **서버 유무 판단하기** — 툴인가? 개인 공간인가? 공유 공간인가? 실제 서비스 예시로 함께 분류해보기 | 토론 |
| 1:10 ~ 1:40 | **바이브 코딩 라이브 데모** — 교사가 AI에게 요청해서 5분 만에 Streamlit 앱이 뜨는 과정을 실시간 시연 ("와, 이게 된다고?") | 라이브 코딩 |
| 1:40 ~ 2:00 | **팀 프로젝트 킥오프** — 우리 팀이 만들 프로젝트 주제 확정, 한 줄 기획서 작성 ("누가 / 무엇을 / 왜 쓰는가") | 팀 활동 |

**1회차 산출물** : 팀 역할표 + 한 줄 기획서 + 서버 필요 여부 판단 결과

## 3. 버전 A — 「감정 방탈출 게임」 (스토리·게임형)

> **컨셉** : 사용자의 선택과 감정 입력에 따라 스토리가 갈라지는 텍스트 방탈출 게임.
> **관심 분야 연결** : 게임, 스토리텔링, 심리
> **서버 판단** : 혼자 즐기는 게임이면 로컬 실행, 친구들에게 공유하려면 배포

| 회차 | 주제 | 세부 내용 (2시간) | 산출물 |
|---|---|---|---|
| 1회차 | OT : 개발 방법론 | 공통 OT (위 참조) + 주제 확정 : "우리 팀의 방탈출 세계관은?" | 한 줄 기획서 |
| 2회차 | 기획 & 첫 화면 | ① 스토리 분기도(플로우차트) 그리기 — 방 3개, 선택지 2개씩 ② 바이브 코딩으로 시작 화면 만들기 : 제목, 스토리 도입부, "입장하기" 버튼 ③ `st.button`, `st.radio`, `st.session_state`로 화면 전환 익히기 | 스토리 분기도 + 게임 시작 화면 |
| 3회차 | 핵심 기능 완성 | ① 감정 입력 기능 — "지금 기분을 한 단어로?" 입력에 따라 다른 방으로 이동 ② AI에게 요청해 스토리 텍스트·힌트 생성 ③ 팀원별 담당 방(스테이지)을 각자 바이브 코딩 → 하나로 합치기 | 3개 방이 연결된 플레이 가능 게임 |
| 4회차 | 완성 & 발표 | ① 엔딩 화면 + 클리어 시간/선택 기록 표시 ② 서로의 게임 플레이 테스트 & 버그 수정 ③ 팀 발표 : 기획 의도 → 시연 → 만들며 배운 것 | 완성된 게임 + 팀 발표 |

## 4. 버전 B — 「우리 학교 리서치 툴」 (설문·데이터형, 몽키서베이 스타일)

> **컨셉** : 급식 만족도, 최애 과목, 시험 스트레스 등 우리 학교 이슈를 직접 설문으로 만들고, 결과를 차트로 보여주는 리서치 툴.
> **관심 분야 연결** : 학교생활, 데이터, 사회 조사
> **서버 판단** : 여러 명이 응답해야 하므로 **공유의 공간 → 배포 필요** (서버 개념을 자연스럽게 체험)

| 회차 | 주제 | 세부 내용 (2시간) | 산출물 |
|---|---|---|---|
| 1회차 | OT : 개발 방법론 | 공통 OT + 주제 확정 : "우리 학교에서 진짜 궁금한 것은?" | 한 줄 기획서 |
| 2회차 | 설문 기획 & 입력 화면 | ① 좋은 질문 만들기 — 객관식/척도/주관식 설계 ② 바이브 코딩으로 설문 입력 화면 제작 : `st.radio`, `st.slider`, `st.text_input`, 제출 버튼 ③ 응답을 CSV 파일로 저장하는 구조 이해 | 설문 5문항 + 응답 입력 화면 |
| 3회차 | 결과 대시보드 | ① 저장된 응답을 불러와 `st.bar_chart`, `st.metric`으로 결과 시각화 ② AI에게 "응답 요약 코멘트" 생성 요청 (예 : "응답자의 70%가 급식에 만족…") ③ 실제로 다른 팀·친구들에게 응답받아 데이터 모으기 | 실시간 결과 대시보드 |
| 4회차 | 배포 & 발표 | ① Streamlit Cloud로 배포 → QR코드 공유 → 진짜 응답 수집 ② 결과 데이터로 "우리 학교 리서치 리포트" 정리 ③ 팀 발표 : 조사 결과 발표회 형식 | 배포된 설문 툴 + 리서치 리포트 |

## 5. 버전 C — 「나만의 취향 추천기」 (테스트·추천형)

> **컨셉** : 몇 가지 질문에 답하면 나에게 맞는 웹툰/노래/공부법을 추천해주는 MBTI 스타일 테스트 앱.
> **관심 분야 연결** : K-pop·음악, 웹툰, 성향 테스트 (중2가 가장 좋아하는 콘텐츠 형식)
> **서버 판단** : 혼자 쓰면 툴, SNS로 친구에게 공유하고 싶다면 배포 — 팀이 선택

| 회차 | 주제 | 세부 내용 (2시간) | 산출물 |
|---|---|---|---|
| 1회차 | OT : 개발 방법론 | 공통 OT + 주제 확정 : "무엇을 추천해주는 테스트를 만들까?" (웹툰/플레이리스트/공부법/여행지 등) | 한 줄 기획서 |
| 2회차 | 질문 설계 & 테스트 화면 | ① 성향을 가르는 질문 5개 설계 — "왜 이 질문이 취향을 알려주지?" 논리 세우기 ② 바이브 코딩으로 질문 화면 제작 : `st.radio` 단계별 진행, 진행률 바(`st.progress`) ③ 답변 점수를 합산하는 로직 이해 | 질문 5개 + 테스트 진행 화면 |
| 3회차 | 추천 로직 & 결과 화면 | ① 점수별 결과 유형 4가지 만들기 (유형 이름·설명·추천 목록) ② AI에게 유형별 소개 문구, 추천 이유 문구 생성 요청 ③ 결과 화면 꾸미기 : 이미지, 유형 카드, "친구에게 공유하기" 문구 | 끝까지 작동하는 테스트 앱 |
| 4회차 | 완성 & 발표 | ① 서로의 테스트 해보기 → "결과가 납득되는가?" 피드백으로 로직 개선 ② (선택) 배포해서 다른 반 친구들 참여시키기 ③ 팀 발표 : 시연 + 가장 많이 나온 유형 통계 공개 | 완성된 추천 앱 + 팀 발표 |

## 6. 팀 운영 방식 (5명 1팀, 공통)

| 역할 | 하는 일 |
|---|---|
| PM (진행) | 회차별 목표 체크, 시간 관리, 의견 조율 |
| 기획 | 스토리/질문/설문 문항 설계, 한 줄 기획서 관리 |
| 화면 담당 | Streamlit 화면 구성, 꾸미기 (이모지·색·배치) |
| 데이터 담당 | 저장·불러오기·점수 계산 로직, 차트 |
| 발표 담당 | 매 회차 산출물 기록, 최종 발표 준비 |

- 역할은 있지만 **바이브 코딩은 전원이 직접 한다.** (역할 = 책임 영역이지 코딩 면제가 아님)
- 매 회차 마지막 10분은 **팀 회고** : "오늘 된 것 / 안 된 것 / 다음 시간에 할 것"

## 7. 평가 및 결과물 (공통)

- **결과물 평가가 아닌 과정 평가** : 기획서 → 중간 산출물 → 완성본 → 발표의 성장 과정을 본다.
- 최종 발표 형식 : **"기획 의도(왜) → 라이브 시연(무엇을) → 배운 점(어떻게)"** 3분 발표
- 수업 후 학생에게 남는 것
  1. "백엔드 + 프론트 + 관심 분야 + AI"라는 **평생 쓰는 개발 공식**
  2. 서버가 필요한 순간을 판단하는 **서비스 감각**
  3. AI와 대화하며 만들어가는 **바이브 코딩 경험**
  4. 팀으로 하나의 프로젝트를 완성해 본 **협업 경험**
