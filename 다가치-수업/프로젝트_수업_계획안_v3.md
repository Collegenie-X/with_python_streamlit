## 이 수업은 뭘 하는 수업인가?

코딩을 배우는 수업이 **아니다.**

AI한테 **"이런 거 만들어줘"라고 말해서** 진짜 앱을 만들어보는 수업이다.

```
"급식 별점 앱 만들어줘. 별점은 1~5점이고, 제출 버튼이 있어."
```

이렇게 말하면 AI가 코드를 만들어준다. 이걸 **바이브 코딩**이라고 부른다.

코드를 한 글자도 칠 줄 몰라도 된다. **내가 원하는 걸 말로 설명할 줄 알면** 앱을 만들 수 있다.

## 이 수업에서 나오는 단어 정리

처음 듣는 단어가 나올 수 있으니까 미리 정리한다. 지금 다 외울 필요 없다.

| 단어 | 뭔데? | 비유 |
|---|---|---|
| **바이브 코딩** | AI한테 말로 설명해서 앱을 만드는 방식 | "이런 집 지어줘"라고 말하면 AI가 지어주는 것 |
| **Python** | 컴퓨터한테 일을 시키는 언어 | 외국어 같은 건데, 이 수업에선 AI가 대신 해줌 |
| **Streamlit** | 코드를 "눈에 보이는 앱 화면"으로 바꿔주는 도구 | 코드를 앱으로 바꿔주는 변환기 |
| **배포** | 앱을 인터넷에 올려서 다른 사람도 쓸 수 있게 하는 것 | 내 방에 있던 작품을 전시회에 내놓는 것 |
| **JSON** | 데이터를 정리하는 형식. `{"메뉴":"비빔밥", "별점":4}` | 엑셀 표를 컴퓨터가 읽기 쉽게 적는 방법 |

## 앱을 만드는 과정은 딱 4단계다

이 수업의 진짜 목표는 이 4단계를 **한 바퀴 돌려보는 것**이다.

| 단계 | 뭘 하나 | 누가 하나 | 예시 |
|---|---|---|---|
| **1. 정하기** | "누구한테, 어떤 문제를 풀어줄 건데?" | 사람 | "우리 반 친구들이 급식 별점을 매길 수 있는 앱을 만들자" |
| **2. 그리기** | "화면이 어떤 순서로 넘어가?" | 사람 | 종이에 : 시작 화면 → 별점 입력 → 결과 차트 |
| **3. 만들기** | AI한테 설명해서 코드를 받는다 | **AI** | "별점을 1~5로 매기는 슬라이더 만들어줘" |
| **4. 고치기** | 직접 써보고 불편한 곳을 찾아서 고친다 | 사람 | "버튼이 너무 작아" → "버튼 크게 해줘" |

4단계 중에 AI가 하는 건 **3단계 하나뿐**이다.

나머지 3개는 전부 사람이 한다. 그래서 코딩 실력보다 **"뭘 만들지 정하는 힘"**이 더 중요하다.

> 이 4단계는 앱을 만들 때만 쓰는 게 아니다.
> 유튜브 영상을 만들든, 학교 축제를 기획하든, 동아리 활동을 하든 — 뭔가를 처음부터 끝까지 만들어본 사람은 이 과정을 안다.
> **이 과정을 한 번이라도 경험해본 사람과, 안 해본 사람은 완전히 다르다.**

### 1회차 시간별 : 왜 만드는가 (2시간)

이 시간에는 코드를 한 줄도 안 친다. 구경만 하면 된다.

| 시간 | 활동 | 세부 내용 |
|---|---|---|
| 0:00~0:20 | **팀 만들기** | 5명이 한 팀. 역할을 고른다 (진행자/기획/화면/데이터/발표). 코딩 잘하는 애가 유리한 역할은 하나도 없다 |
| 0:20~0:50 | **AI 시대 이야기** | AI가 코드를 다 짜주면, 사람은 뭘 잘해야 하나? → "뭘 만들지 정하는 능력"이 가장 중요하다. 만드는 4단계(정하기→그리기→만들기→고치기)를 배운다 |
| 0:50~1:10 | **같이 생각해보기** | 카카오톡은 서버가 필요할까? 계산기 앱은? → "이건 나만 쓸 건가, 같이 쓸 건가?" 이 질문 하나면 서버 필요 여부를 판단할 수 있다 |
| 1:10~1:40 | **라이브 데모** | 선생님이 AI한테 "급식 별점 앱 만들어줘"라고 말한다 → Python 코드가 나온다 → Streamlit으로 실행 → 5분 뒤에 진짜 앱이 화면에 뜬다. **"어, 말만 했는데 앱이 나왔어?"** — 이 순간이 이 수업의 시작점 |
| 1:40~2:00 | **주제 정하기** | 아이디어 10개 중에서 우리 팀 것 고르기. 한 줄 기획서 쓰기 : "○○가 / ○○ 때문에 불편해서 / ○○를 만든다" |

> **이 날의 핵심** : "말만 했는데 앱이 나오네? 나도 할 수 있겠는데?"
> 이 자신감이 나머지 3일의 연료다.

### 2회차 시간별 : 그려보기 (2시간)

종이에 그림 그리고, AI한테 처음으로 Python 코드를 받아보는 날.

| 시간 | 활동 | 세부 내용 |
|---|---|---|
| 0:00~0:30 | **종이에 화면 그리기** | A4에 네모 칸을 그린다. 화살표로 연결한다. "시작 화면 → 입력 화면 → 결과 화면" — 이게 우리 앱의 설계도. 이 순서를 정하는 게 **알고리즘**이다. "다음에 뭐가 나오지?"를 정하는 것 |
| 0:30~0:50 | **데이터 정리** | "우리 앱에서 저장해야 할 정보가 뭐지?" 목록 만들기. 급식 앱이면 메뉴 이름, 별점, 한줄평. 이걸 JSON 형태로 정리하는 게 데이터 설계 |
| 0:50~1:30 | **첫 바이브 코딩** | AI한테 "제목이 있고, 시작 버튼이 있는 화면 만들어줘"라고 말한다 → Python 코드가 나온다 → 복사해서 `.py` 파일에 붙여넣기 → `streamlit run app.py`로 실행 → 화면이 뜬다 → "버튼 색 바꿔줘" 다시 말한다. 선생님이 **한 단계씩 같이 따라간다** |
| 1:30~1:50 | **Streamlit 부품 체험** | `st.button()`, `st.selectbox()`, `st.slider()`, `st.text_input()` — 이 4가지 부품만 쓸 줄 알면 앱 대부분을 만들 수 있다. AI한테 "버튼 하나 만들어줘"라고 말하면 됨 |
| 1:50~2:00 | **팀 회고** | 오늘 된 것 / 안 된 것 / 다음에 할 것. 3줄만 적기 |

> **이 날 깨닫는 것** : 알고리즘은 거창한 게 아니다.
> 종이에 네모 그리고 화살표 긋는 순간, 이미 알고리즘을 만들고 있는 거다.

### 3회차 시간별 : 만들기 (2시간)

각자 만든 조각을 하나의 Python 파일로 합쳐서, 처음부터 끝까지 돌아가게 만드는 날.

| 시간 | 활동 | 세부 내용 |
|---|---|---|
| 0:00~0:50 | **나눠서 만들기** | 각자 맡은 부분을 AI한테 설명해서 Python 코드를 받는다. 화면 담당은 "이 화면 깔끔하게 해줘", 기획은 "질문 5개 써줘", 데이터는 "별점 평균 계산하는 Python 함수 만들어줘" |
| 0:50~1:20 | **합치기** | 각자 만든 코드를 하나의 `app.py`로 연결한다. AI한테 "이 두 화면을 연결해줘"라고 말하면 됨. 막히면 선생님한테 바로 물어보기 — 혼자 끙끙거리지 말고 물어보는 게 이 수업의 규칙 |
| 1:20~1:40 | **테스트 + 디버깅** | 앱을 처음부터 끝까지 한 번 돌려본다. 에러가 나면 → AI한테 에러 메시지를 복사해서 "이거 왜 안 돼?"라고 물어보기 → 고친 코드를 받아서 다시 실행. **안 되는 걸 찾는 것 자체가 실력** |
| 1:40~1:50 | **다른 팀 피드백** | 다른 팀한테 앱을 보여주고 "이 부분 헷갈려", "여기 좋다" 피드백 주고받기 |
| 1:50~2:00 | **팀 회고** | 내일 꼭 마무리할 것 목록 작성 |

> **이 날 배우는 것** : 완벽하게 만드는 사람은 없다.
> 프로 개발자도 **"만들고 → 써보고 → 고치기"를 매일 반복**한다.

### 4회차 시간별 : 내놓기 (2시간)

앱을 인터넷에 올리고, 사람들 앞에서 보여주는 날.

| 시간 | 활동 | 세부 내용 |
|---|---|---|
| 0:00~0:30 | **UI 다듬기** | "이 앱을 처음 본 사람이, 뭘 해야 하는지 바로 알겠어?" 이 질문으로 점검. 글씨 크기, 버튼 위치, 색깔 정리. AI한테 "이 화면 더 깔끔하게 바꿔줘"라고 요청. `st.set_page_config()`으로 제목과 아이콘 설정 |
| 0:30~0:50 | **배포** | Streamlit Cloud에 앱을 올린다 → URL이 생긴다 → QR코드 만든다 → 옆 팀한테 보내서 써보게 한다. **"내가 만든 Python 앱이 인터넷에 올라갔다"** — 이 순간이 8시간 중 가장 중요 |
| 0:50~1:05 | **발표 준비** | 3가지만 정리 : ① 왜 만들었나 ② 앱 직접 보여주기(시연) ③ 뭘 배웠나. 메모 보고 해도 됨 |
| 1:05~1:45 | **팀 발표회** | 각 팀 3분 발표. 다른 팀 앱도 QR코드 찍어서 직접 써본다 |
| 1:45~2:00 | **다음 단계 안내** | 방학 때 프로젝트 2번째 도전. 지금 만든 게 나중에 포트폴리오가 된다는 이야기. GitHub에 코드 올리는 법 소개 |

> **이 날 배우는 것** : "만드는 것"과 "다른 사람한테 보여주는 것"은 완전히 다른 경험이다.

## 팀 구성 (5명이 하나를 만든다)

| 역할 | 하는 일 | 쉽게 말하면 |
|---|---|---|
| **진행자 (PM)** | 시간 관리, 의견 정리, "지금 뭐 해야 해?" 정해주기 | 감독 |
| **기획** | 질문/스토리/콘텐츠 만들기, 기획서 관리 | 작가 |
| **화면** | 앱이 보기 좋도록 배치, 색깔, 글씨 다듬기 | 디자이너 |
| **데이터** | 점수 계산, 저장, 차트 | 엔지니어 |
| **발표** | 매번 기록, 최종 발표 | 기자 |

코딩을 못해도 할 수 있는 역할이 대부분이다.
그리고 **역할에 상관없이 바이브 코딩은 5명 전원이 직접 해본다.**

## 왜 이렇게 만드는가 — AI 시대의 프로젝트

### 예전과 지금은 다르다

```
[예전]  문법 공부 → 코드 직접 타이핑 → 에러 고치기 → 완성
       몇 달 걸린다. 중간에 대부분 포기한다.

[지금]  뭘 만들지 정하기 → AI한테 말하기 → 결과 확인 → 고쳐달라고 말하기 → 완성
       몇 시간이면 된다. 코딩을 몰라도 된다.
```

달라진 건 "코드를 누가 짜느냐"이고,
달라지지 않은 건 **"뭘 만들지 정하는 건 사람"**이라는 것이다.

### 사람이 해야 할 것 vs AI가 해주는 것

```
사람이 해야 할 것               AI가 해주는 것
───────────────               ──────────────
"뭘 만들지?" 정하기             코드 작성
"누가 쓸 건데?" 생각하기        에러 수정
"이거 쓰기 편해?" 판단하기      반복 작업
"왜 안 되지?" 원인 찾기         빠른 검색
```

> 코딩은 AI가 해준다.
> 근데 **"뭘 만들지 정하고, 써보고, 더 좋게 고치는 건 사람만 할 수 있다."**
> 이 수업은 그 과정을 연습하는 수업이다.

## 평가

점수를 매기는 게 아니라, **4단계를 한 바퀴 돌렸는지** 본다.

| 본다 | 확인 |
|---|---|
| 기획서 | "누가 / 왜 / 뭘 만드는가"를 정했는가? |
| 화면 흐름도 | 종이에 그린 설계도의 앞뒤가 맞는가? |
| 중간 과정 | 안 되는 걸 찾고 고치려고 했는가? |
| 완성 앱 | 처음~끝 한 번은 돌아가는가? |
| 발표 | 왜 만들었고, 뭘 배웠는지 말했는가? |

> 완벽하게 만들었느냐가 아니다. 버그가 있어도 괜찮다.
> **"왜 안 되는지 알고 있다"가 "되긴 하는데 왜 되는지 모른다"보다 낫다.**

### 발표는 3가지만

```
① 왜 만들었나     →  "○○가 불편해서 만들었습니다"
② 어떻게 생겼나   →  앱을 직접 보여준다
③ 뭘 배웠나       →  "이게 어려웠는데 이렇게 했습니다"
```

메모 보고 해도 된다. 앱이 말해준다.
