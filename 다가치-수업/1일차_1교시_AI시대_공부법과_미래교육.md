> **대상** : 중학교 2학년 (12세 눈높이로 설명)

> **참조** : OECD Education 2030, WEF Future of Jobs 2025, IB/KB 교육 가이드, 메타 AI 벤처 블루프린트

## 1-1. OECD가 말하는 미래 인재상

OECD(경제협력개발기구)는 전 세계 38개 선진국이 모인 곳이다.
이 곳에서 "2030년에 어떤 사람이 필요한가?"를 연구했다. 그게 **OECD Education 2030**이다.

### OECD 2030 — 핵심 역량 3가지

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│   1. 새로운 가치 창조 (Creating New Value)             │
│      → 남이 안 해본 것을 만들어내는 능력               │
│                                                      │
│   2. 긴장과 딜레마 조정 (Reconciling Tensions)         │
│      → 서로 다른 의견을 조율하는 능력                  │
│                                                      │
│   3. 책임감 (Taking Responsibility)                   │
│      → 내가 한 일에 대해 끝까지 책임지는 태도           │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### OECD 2030 vs 한국 수능 — 뭘 키우나

| OECD가 말하는 미래 역량 | 수능이 측정하는 것 | 겹치나? |
|---|---|---|
| 새로운 가치 창조 | 정답 맞히기 | 안 겹침 |
| 긴장과 딜레마 조정 | 시간 내 문제 풀기 | 안 겹침 |
| 책임감 | 등급 받기 | 안 겹침 |
| **학생 주도성 (Student Agency)** | 교사가 시키는 대로 | **정반대** |
| 비판적 사고 | 4지선다에서 하나 고르기 | 안 겹침 |
| 협업과 공감 | 혼자 시험 보기 | **정반대** |

> 수능이 측정하는 능력과 OECD가 말하는 미래 역량이 **하나도 안 겹친다.**
> 이게 교육이 바뀌어야 하는 이유다.

---

### WEF(세계경제포럼)가 말하는 2030년 핵심 역량 TOP 10

WEF는 매년 다보스에서 열리는 세계 최대 경제 포럼이다.
2025년 보고서에서 **2030년에 가장 중요한 능력 10가지**를 발표했다.

| 순위 | 2030 핵심 역량 | 쉽게 말하면 | 수능으로 키울 수 있나? |
|:---:|---|---|:---:|
| 1 | **분석적 사고 (Analytical Thinking)** | "왜?"를 파고드는 능력 | 일부 |
| 2 | **회복탄력성 (Resilience)** | 실패해도 다시 일어나는 힘 | 안 됨 |
| 3 | **유연성과 민첩성 (Flexibility)** | 상황에 맞게 빠르게 바꾸는 능력 | 안 됨 |
| 4 | **리더십과 사회적 영향력** | 사람을 설득하고 이끄는 힘 | 안 됨 |
| 5 | **창의적 사고 (Creative Thinking)** | 남들이 안 한 걸 생각하는 능력 | 안 됨 |
| 6 | **동기부여와 자기 인식** | 내가 뭘 잘하는지 아는 것 | 안 됨 |
| 7 | **기술 리터러시 (Tech Literacy)** | AI 같은 기술을 이해하고 쓰는 능력 | 안 됨 |
| 8 | **호기심과 평생 학습** | 배움을 멈추지 않는 태도 | 안 됨 |
| 9 | **공감과 적극적 경청** | 남의 말을 진심으로 듣는 능력 | 안 됨 |
| 10 | **AI와 빅데이터** | AI를 도구로 쓸 줄 아는 능력 | 안 됨 |

> **10개 중 수능으로 키울 수 있는 건 1번 하나, 그것도 "일부".**
> 나머지 9개는 프로젝트, 토론, 협업, 실패 경험에서만 키울 수 있다.
> 이게 전 세계가 교육을 바꾸고 있는 이유다.

## 1-2. BG vs AG — AI 이전과 이후, 모든 것이 바뀌었다

### AI 이전(BG) vs AI 이후(AG) 마인드셋 전환

**BG** = Before Gen-AI (AI가 나오기 전)
**AG** = After Gen-AI (AI가 나온 후)

| 구분 | BG (AI 이전) | AG (AI 이후) |
|---|---|---|
| **목표** | 좋은 직장에 취업 | 직접 직업을 만든다 (**창직**) |
| **무기** | 스펙 (학점, 토익, 자격증) | 포트폴리오 (내가 만든 것) |
| **학습 방식** | 강의 듣기 → 암기 → 시험 | 문제 발견 → 만들기 → 런칭 |
| **실패 해석** | 좌절, 경로 이탈 | 데이터 수집, 다시 도전 |
| **AI 활용** | AI에 질문 1개 (수동적) | 여러 AI를 동시에 지휘 (능동적) |
| **수익 구조** | 월급 (고정, 한정적) | 내가 만든 것의 수익 (확장 가능) |
| **핵심 역량** | 지식 암기량 | 문제 정의력 + AI 활용력 |
| **코딩** | 문법을 외워서 직접 짠다 | AI한테 말해서 만든다 (바이브 코딩) |

### 교육 패러다임 전환 3단계

```
[산업화 시대 1970~2010]
  암기 중심, 객관식 평가
  교사가 정답을 알려준다
  "외워라, 시험에 나온다"

        ↓

[정보화 시대 2010~2022]
  자기주도학습, 수행평가 도입
  학생이 정보를 검색한다
  "검색해봐, 답이 있다"

        ↓

[AI 시대 2023~현재]
  프로젝트 기반, 논술·서술·구술
  학생이 AI를 지휘하여 가치를 만든다
  "질문해라, 만들어라, 보여줘라"
```

## 1-3. AI가 대체하는 것 vs 대체 못 하는 것

### AI 대체 가능성 표

| 능력 | AI가 대체할 수 있나? | 2030년 가치 | 어디서 키우나? |
|---|---|---|---|
| 지식 암기 | 100% 대체 (검색·요약 자동화) | 0% | 수능 |
| 빠른 계산 | 100% 대체 | 0% | 수능 |
| 4지선다 문제 풀이 | 90%+ 대체 (GPT-4 수준) | 5% | 수능 |
| 정형화된 서술 답안 | 80% 대체 | 20% | 수능 |
| **비판적 분석·논증** | AI가 보조하나 인간 필수 | **90%** | **IB/KB** |
| **독창적 문제 정의** | AI 대체 불가 | **100%** | **프로젝트** |
| **윤리적 가치 판단** | AI 대체 불가 | **100%** | **토론** |
| **학제 간 융합 통찰** | AI 보조, 인간 주도 | **95%** | **프로젝트** |
| **공감·설득** | AI 대체 불가 | **100%** | **협업** |
| **AI 오케스트레이션** | 인간만 가능 | **100%** | **바이브 코딩** |

### 도식 — 위험 영역 vs 안전 영역

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   [위험 영역] AI가 대체하는 능력                      │
│   ───────────────────────────────                   │
│   · 정보 검색·요약                                   │
│   · 번역·문법 교정                                   │
│   · 단순 코딩                                       │
│   · 데이터 정리·분석                                 │
│   · 객관식 문제 풀이                                 │
│                                                     │
│   → 전통 수능 교육이 주로 가르치는 것                  │
│   → AI에 의해 가치가 사라지는 중                      │
│                                                     │
│─────────────────────────────────────────────────────│
│                                                     │
│   [안전 영역] AI가 대체 못 하는 능력                   │
│   ───────────────────────────────                   │
│   · 문제 정의 — "무엇이 문제인가?"                    │
│   · 윤리적 판단 — "이것이 옳은가?"                    │
│   · 공감·설득 — "왜 해야 하는가?"                     │
│   · AI 오케스트레이션 — "어떤 AI를 어떻게 쓸까?"       │
│   · 가치 판단 — "무엇을 만들 것인가?"                 │
│                                                     │
│   → IB/KB/프로젝트 교육이 가르치는 것                 │
│   → AI 시대에 가치가 폭등하는 중                      │
│                                                     │
└─────────────────────────────────────────────────────┘
```

> **결론**: 수능이 측정하는 역량 상위 5개는 AI에 의해 대체된다.
> IB/KB가 훈련하는 역량 하위 5개는 AI가 대체할 수 없다.
> 어떤 교육을 받아야 하는지, 답은 이미 나왔다.

## 2-1. 문화의 대전환 — 소비자에서 생산자로

### 과거 vs 현재 vs 미래 — 학생의 역할 변화

| 시대 | 학생의 역할 | 주요 활동 | 평가 방식 |
|---|---|---|---|
| **과거 (수능 시대)** | 지식의 **소비자** | 읽기, 듣기, 외우기 | 객관식 (정답 맞히기) |
| **현재 (전환기)** | 지식의 **탐구자** | 읽기 + 질문하기 + 정리하기 | 서술형 + 수행평가 |
| **미래 (AI 시대)** | 지식의 **생산자** | **쓰기, 말하기, 만들기, 발표하기** | 논술 + 구술 + 프로젝트 |

### 읽기/듣기 vs 쓰기/말하기 비교

```
[과거 — 읽고 듣는 문화]

  교과서 읽기 → 선생님 강의 듣기 → 필기 → 암기 → 시험

  · 학생 발언 시간: 하루 5~10분
  · 글쓰기: 시험 답안 정도
  · 주인공: 선생님
  · 정보의 방향: 선생님 → 학생 (일방향)


[미래 — 쓰고 말하는 문화]

  질문 만들기 → 토론 → 에세이 쓰기 → 발표 → 피드백 → 다시 쓰기

  · 학생 발언 시간: 하루 120~180분
  · 글쓰기: 에세이, 연구 보고서, 프로젝트 기획서
  · 주인공: 학생
  · 정보의 방향: 학생 ↔ 학생 ↔ 선생님 (다방향)
```

### 수업이 어떻게 바뀌나 — 실제 데이터 (대구·제주 IB 학교 기준)

| 항목 | 기존 수업 | IB/KB 수업 |
|---|---|---|
| 교사 강의 비중 | **80%** | **20%** |
| 학생 탐구·토론 비중 | **20%** | **80%** |
| 객관식 평가 | **70%** | **0%** |
| 서술·논술·구술형 | **30%** | **100%** |
| 학생 발언 시간 (고2 하루) | **약 5~10분** | **약 120~180분** |
| 교사 역할 | 지식 전달자 (Instructor) | 학습 촉진자 (Facilitator) |

> 교사 강의가 80%에서 20%로, 학생 발언이 10분에서 3시간으로.
> **이게 교실의 혁명이다.**

## 2-2. 지식의 벽이 무너지고 있다

### 과거 — 지식에는 벽이 있었다

```
[과거]

  좋은 대학 교수님만 아는 지식이 있었다.
  비싼 교과서를 사야 배울 수 있었다.
  영어를 못하면 해외 논문을 읽을 수 없었다.
  서울에 사는 학생과 시골에 사는 학생의 정보 격차가 컸다.

  → 지식을 "가진 사람"과 "못 가진 사람"이 나뉘었다.
  → 지식을 많이 가진 사람이 이겼다.
  → 그래서 "암기"가 중요했다.
```

### 현재 — 지식의 벽이 사라졌다

```
[현재]

  AI한테 물어보면 대학 교수 수준의 설명을 받을 수 있다.
  한국어로 물어봐도 영어 논문의 내용을 요약해준다.
  서울에서든 제주에서든, 인터넷만 되면 같은 수준의 정보를 얻는다.
  무료다.

  → 지식을 "가진 것" 자체는 더 이상 무기가 안 된다.
  → 지식을 "어떻게 조합하고 활용하느냐"가 무기다.
  → 그래서 "질문하는 능력"이 중요해졌다.
```

### 지식의 가치 변화 — 한눈에

| 과거에 가치 있던 것 | 현재 가치 | 미래에 가치 있는 것 |
|---|---|---|
| 많이 외운 사람 | 가치 급락 | 잘 질문하는 사람 |
| 영어 잘하는 사람 | 가치 하락 (AI 번역) | 문제를 정의하는 사람 |
| 타자 빠른 사람 | 가치 소멸 | 기획하는 사람 |
| 코드 잘 짜는 사람 | 가치 하락 (AI 코딩) | AI를 지휘하는 사람 |
| 정보를 가진 사람 | 가치 소멸 (검색) | 정보를 가치로 바꾸는 사람 |

> **지식을 아는 것은 더 이상 힘이 아니다.**
> **지식을 가지고 뭘 만드느냐가 힘이다.**

## 2-3. AI로 맞춤형 질문과 답변이 가능한 시대

### 과거의 공부 vs AI 시대의 공부

```
[과거]
  모르는 게 있으면 → 선생님한테 물어본다 (수업 시간에만)
                  → 학원에 간다 (돈이 든다)
                  → 교과서를 다시 읽는다 (해결 안 될 수도)
                  → 포기한다

[AI 시대]
  모르는 게 있으면 → AI한테 바로 물어본다 (24시간, 무료)
                  → "더 쉽게 설명해줘" (무한 반복 가능)
                  → "그럼 이건?" (꼬리 질문 가능)
                  → "이걸 파이썬으로 만들어봐" (실습까지)
                  → 포기할 이유가 사라진다
```

### AI 맞춤형 학습의 실체

| 구분 | 학원/과외 | AI 학습 |
|---|---|---|
| 비용 | 월 30~100만원 | 무료~월 2만원 |
| 시간 | 정해진 시간에만 | 24시간 아무 때나 |
| 수준 | 반 전체 같은 수준 | **나에게 맞춘 수준** |
| 질문 횟수 | 제한적 | **무제한** |
| 반복 설명 | 눈치 보임 | **100번 물어봐도 OK** |
| 언어 | 한국어만 | 모든 언어 가능 |
| 실습 | 제한적 | AI가 코드까지 만들어줌 |

### 하루 100개 질문 — AI로 공부하는 새로운 방법

```
예전 공부법:
  교과서 읽는다 → 모르는 게 나온다 → 넘어간다 → 시험 때 망한다

AI 시대 공부법:
  교과서 읽는다 → 모르는 게 나온다 → AI한테 바로 물어본다
  → 이해한다 → 더 궁금한 게 생긴다 → 또 물어본다
  → 하루에 100개도 물어볼 수 있다
```

### 실제 예시 — 피타고라스의 정리 하나로 100개 질문

```
[수학 시간에 "피타고라스의 정리"를 배웠다]

질문 1  : "피타고라스의 정리가 뭐야? 12살이 이해할 수 있게 설명해줘"
질문 2  : "왜 직각삼각형에서만 성립해?"
질문 3  : "실생활에서 이걸 어디에 써?"
질문 4  : "건축에서 쓰는 예시 알려줘"
질문 5  : "게임 만들 때 캐릭터 사이 거리 구할 때 쓴다고?"
질문 6  : "그럼 파이썬으로 거리 계산하는 코드 보여줘"
질문 7  : "그 코드를 앱으로 만들 수 있어?"
질문 8  : "피타고라스는 누구야? 어떤 사람이었어?"
질문 9  : "피타고라스 정리를 증명하는 방법 몇 가지야?"
질문 10 : "가장 쉬운 증명 방법을 그림으로 설명해줘"
...
질문 50 : "피타고라스 정리를 3D로 확장하면?"
...
질문 100: "이 개념을 활용한 앱을 기획서로 만들어줘"
```

> **10개 질문 만에** 수학 공식 하나가 → 실생활 활용 → 역사 → 코딩 → 앱 아이디어까지 갔다.
> **100개 질문이면** 교과서 한 챕터를 넘어서 다른 분야까지 연결된다.
>
> 이걸 매일 하면?
> 1주일이면 700개 질문. 1달이면 3,000개.
> **질문하는 능력 자체가 실력이 되는 시대다.**

### AI한테 잘 물어보는 법

| 나쁜 질문 | 좋은 질문 | 왜 다른가 |
|---|---|---|
| "피타고라스 알려줘" | "피타고라스의 정리를 12살이 이해할 수 있게 비유로 설명해줘" | 구체적일수록 답이 좋다 |
| "코드 짜줘" | "급식 별점 앱인데, 별점은 1~5점이고, 제출 버튼이 있어. Python Streamlit으로 만들어줘" | 맥락과 조건을 알려줘야 한다 |
| "이거 왜 안 돼?" | "이 에러 메시지가 떴는데, 원인이 뭐고 어떻게 고쳐?" | 문제를 정확히 설명해야 한다 |
| "작문해줘" | "환경 문제에 대해 찬성·반대 논점을 3개씩 정리하고, 내 입장을 논증하는 에세이 구조를 잡아줘" | AI를 도구로 쓰되, 생각은 내가 한다 |

> **AI는 네가 물어보는 만큼만 알려준다.**
> 잘 물어보는 사람이 더 많이 배운다.
> 이건 시험 공부만이 아니라, 코딩할 때도, 프로젝트 만들 때도, 직장에서도 똑같다.

# PART 3. IB에 열광하고, KB로 바뀌려는 이유

---

## 3-1. IB가 뭔데? 왜 전 세계가 열광하나?

### IB(International Baccalaureate)란

| 항목 | 내용 |
|---|---|
| 만든 곳 | 스위스 IBO (1968년 설립) |
| 사용 국가 | 전 세계 **160개국**, 5,700개+ 학교 |
| 핵심 | 시험 점수가 아니라, **직접 연구하고 결과물을 만들어서 제출**하는 교육 |
| 평가 방식 | **서술형 100%** — 객관식이 단 하나도 없다 |
| 글로벌 인정 | 전 세계 Top 100 대학이 100% 인정 |
| 한국 현황 | 전국 386교 도입 (인증 106교) |

### 왜 IB에 열광하나?

```
이유 1 : IB 졸업생의 대학 중퇴율이 일반 학생보다 30~40% 낮다
이유 2 : IB 졸업생의 대학 1학년 GPA가 0.3~0.5점 높다
이유 3 : IB에서 훈련하는 역량이 OECD 2030, WEF 2025가 말하는 미래 역량과 1:1 대응
이유 4 : 실제로 수능 없이 서울대에 합격한 사례가 나왔다 (표선고)
이유 5 : AI 시대에 살아남는 능력 = IB에서 키우는 능력
```

### IB의 핵심 — EE, TOK, CAS

| 이름 | 무엇인가 | 쉽게 말하면 |
|---|---|---|
| **EE** (Extended Essay) | 4,000단어 연구 논문 | 대학 졸업 논문의 고등학생 버전 |
| **TOK** (Theory of Knowledge) | "우리는 어떻게 아는가?" 탐구 | 정답이 아니라 "좋은 질문"을 만드는 훈련 |
| **CAS** (Creativity, Activity, Service) | 18개월 창의·활동·봉사 | 만들고, 움직이고, 도우며 성장하기 |

### IB 학생의 하루 vs 일반고 학생의 하루

| 시간 | 일반고 학생 | IB 학생 |
|---|---|---|
| 오전 | 선생님 강의를 듣는다 | 토론하고 발표한다 |
| 오후 | 문제집을 푼다 | 실험하고 에세이를 쓴다 |
| 방과후 | 학원에 간다 | CAS 프로젝트를 한다 |
| 저녁 | 인강을 듣는다 | AI한테 물어보며 EE를 쓴다 |
| 시험 | 객관식을 찍는다 | 논술로 논증한다 |

## 3-2. IB의 한계 — 왜 KB가 필요한가?

IB는 좋다. 근데 문제가 있다.

### IB의 3대 한계

| 한계 | 구체적 문제 | 영향 |
|---|---|---|
| **1. 비싸다** | 학교당 연 1,000~1,500만원 IBO 인증비. 전국 8개 교육청 누적 **24.1억원** 해외 유출 | "국민 세금이 스위스에 간다" 논란 |
| **2. 1%만 접근 가능** | 인증학교(월드스쿨) 106교 = 전국 학교의 약 1% | 대다수 학생은 IB를 받을 수 없다 |
| **3. 영어 장벽** | 많은 IB 학교가 영어로 수업. 한국어 DP는 일부만 | 영어 못하면 사실상 불가능 |

### 그래서 KB가 나왔다

```
┌───────────────────────────────────────────────────┐
│                                                   │
│   KB(한국형 바칼로레아)란?                           │
│                                                   │
│   IB의 "정신"은 가져오고 "껍데기"는 벗겨낸 것         │
│                                                   │
│   · IB의 서술형 평가, 탐구 학습, 비판적 사고 → 가져옴 │
│   · IBO 인증비, 영어 장벽, 1% 엘리트 구조 → 버림     │
│   · 한국어 100%, 비용 0원, 전 학교 대상              │
│                                                   │
└───────────────────────────────────────────────────┘
```

## 3-3. IB vs KB vs 수능 — 3자 비교

| 비교 항목 | 수능 중심 교육 | IB (국제 바칼로레아) | KB (한국형 바칼로레아) |
|---|---|---|---|
| **운영 주체** | 한국 교육부 | IBO (스위스) | 한국 교육부 + 교육청 |
| **교육과정** | 국가 교육과정 | IB 자체 교육과정 | **국가 교육과정 유지** + 평가 전환 |
| **평가 방식** | 객관식 70% | 서술형 100% | **논·서·구술형 중심** (서술형 70%+) |
| **수업 언어** | 한국어 | 영어 중심 | **한국어 100%** |
| **비용** | 무상 | IBO 인증비 연 1,000만원+ | **무상** (인증비 없음) |
| **적용 범위** | 전체 학교 | 인증학교만 (~1%) | **모든 공교육 학교** 대상 |
| **수능 연계** | 수능 = 교육의 목표 | 수능 병행 사실상 불가 | **수능 개편과 연계** 가능 |
| **글로벌 인정** | 한국 내에서만 | 전 세계 160개국 | 한국 내 + 향후 글로벌 추진 |
| **AI 시대 적합성** | 낮음 (암기 중심) | 높음 (비판적 사고) | 높음 (한국어 + AI 연계) |

> 쉽게 비유하면 이렇다:
>
> **수능** = 남이 낸 문제의 정답을 빨리 찾는 시험
> **IB** = 명품 수입차. 성능은 검증됐지만 비싸고, 매뉴얼이 영어고, 아무나 못 산다
> **KB** = 그 수입차를 뜯어보고 만든 국산차. 값은 무료, 매뉴얼은 한국어, 전 국민이 탈 수 있게 하는 게 목표

```
┌─────────────────────────────────────────────────────┐
│  3층 · KB 평가 시스템 (혁신)                           │

   IB는 1층부터 통째로 교체 → 수능과 단절
   KB는 1층 유지 → 수능 개편과 연결 가능
```

## 4-4. 창직 — 직업을 "찾는" 시대에서 "만드는" 시대로

| 취직 (就職) | 창직 (創職) |

|---|---|
| 유튜버 / 크리에이터 | 영상 찍는 걸 좋아하던 사람들 |

```

# PART 5. 기획과 아키텍처가 코딩보다 중요하다

---

## 5-1. 단순 코더의 시대는 끝났다

```
2020년 : "코딩 배워라" → 파이썬 문법 외워라, for문 써라, if문 써라
2026년 : "코딩은 AI가 한다" → 그러면 사람은 뭘 해야 하나?
```

### 사람이 해야 하는 4가지

```
1. 기획    — "뭘 만들지?" "누가 쓸 건데?" "왜 필요해?"
2. 아키텍처 — "전체 구조를 어떻게 설계하지?" "데이터는 어떻게 흘러가지?"
3. 오케스트레이션 — "어떤 AI를 어떻게 조합해서 쓰지?"
4. 디버깅/판단 — "이게 잘 되고 있나?" "뭘 고쳐야 하나?"
```

### 단순 코더 vs 기획자+오케스트레이터

| 능력 | 단순 코더 (BG) | 기획자+오케스트레이터 (AG) |
|---|---|---|
| 코드 작성 | 직접 타이핑 | AI한테 말로 설명 (바이브 코딩) |
| AI 사용 | ChatGPT에 질문 1개 | Claude + v0 + Kling AI 동시 지휘 |
| 결과물 | 코드 파일 | 런칭 가능한 서비스 + 마케팅 영상 |
| 핵심 능력 | 문법 암기 | 문제 정의 + 전체 구조 설계 |
| 비유 | 피아노 한 대 연주 | **오케스트라 지휘** |
| 가치 | AI에 의해 가치 하락 | AI 시대에 가치 폭등 |

---

## 5-2. 바이브 코딩 — 말하면서 만드는 시대

### 바이브 코딩(Vibe Coding)이란?

코드를 한 줄씩 외워서 치는 것이 아니라,
**AI에게 "원하는 것"을 정확히 설명하고 → 결과를 확인하고 → 다시 요청하며 다듬는** 개발 방식.

```
[옛날 코딩]
  파이썬 문법 공부 → for문 써보기 → if문 써보기 → 에러 → 구글링 → 수정
  → 몇 달 걸린다. 중간에 대부분 포기한다.

[바이브 코딩]
  "급식 별점 앱 만들어줘. 별점은 1~5점이고, 제출 버튼이 있어."
  → AI가 코드를 만들어준다 → 실행 → "버튼 색 바꿔줘" → 다시 실행
  → 몇 시간이면 된다. 코딩을 몰라도 된다.
```

### 바이브 코딩에서 사람이 하는 것 vs AI가 하는 것

```
사람이 하는 것                AI가 하는 것
──────────────              ──────────────
"뭘 만들지?" 정하기          코드 작성
"누가 쓸 건데?" 생각하기      에러 수정
"이거 쓰기 편해?" 판단하기    반복 작업
"왜 안 되지?" 원인 찾기       빠른 검색
전체 구조 설계               세부 구현
사용자 피드백 반영            코드 최적화
```

> 코딩은 AI가 해준다.
> 근데 **"뭘 만들지 정하고, 써보고, 더 좋게 고치는 건 사람만 할 수 있다."**

---

## 5-3. 아키텍처 — 전체 구조를 그리는 능력

### 아키텍처란?

건물을 짓기 전에 설계도를 그리듯,
앱을 만들기 전에 **전체 구조를 설계하는 것**이다.

```
[아키텍처의 예시 — 급식 별점 앱]

사용자 → [메인 화면]
           ↓
        [급식 메뉴 선택]
           ↓
        [별점 입력 (1~5)]
           ↓
        [한줄평 입력]
           ↓
        [제출] → 데이터 저장
           ↓
        [통계 대시보드]
           ├── 이번 주 인기 메뉴 TOP 5
           ├── 별점 추이 차트
           └── 한줄평 모음
```

이 구조를 그릴 줄 아는 사람이 AI한테 "이거 만들어줘"라고 말할 수 있다.
구조를 모르면 AI한테 뭘 시켜야 하는지도 모른다.

### 코딩 능력 vs 아키텍처 능력

| 코딩 능력 | 아키텍처 능력 |
|---|---|
| `for i in range(10):` 같은 문법 | "데이터가 어디서 어디로 흘러가는가?" |
| 변수 이름 짓기 | "사용자가 어떤 순서로 화면을 보는가?" |
| 에러 메시지 읽기 | "이 기능과 저 기능이 어떻게 연결되는가?" |
| AI가 대체 가능 | **AI가 대체 불가능** |

---

## 5-4. 오케스트레이션 — 여러 AI를 동시에 지휘하는 능력

### 단일 AI 사용자 vs AI 오케스트레이터

| 차원 | 단일 AI 사용자 | AI 오케스트레이터 |
|---|---|---|
| 사용 패턴 | ChatGPT에 질문 1개 | Claude + v0 + Kling AI + CapCut 동시 지휘 |
| 결과물 | 텍스트 답변 | 런칭 가능한 서비스 + 마케팅 영상 |
| AI 관계 | 일문일답 (수동적) | 비교·토론·경쟁 (능동적) |
| 비유 | 피아노 한 대 연주 | **오케스트라 지휘** |

### AI 오케스트레이션의 실제

```
[1인 오케스트라 시스템]

나(지휘자)
  ├── Claude → 기획서 작성, 코드 로직 설계, 디버깅
  ├── v0 → UI/UX 디자인, 웹앱 화면 생성
  ├── Freepik → 마케팅 이미지, 로고 생성
  ├── Kling AI → 정지 이미지 → 15초 광고 영상 변환
  ├── CapCut → 영상 편집, 자막, BGM 추가
  └── YouTube → 배포, 수익화
```

| 회사 부서 | 대신하는 AI | 하는 일 |
|---|---|---|
| CEO / 기획 | **나** | 문제 정의, 의사결정 |
| 기획팀 | Claude | 기능 명세서, 데이터 설계 |
| 개발팀 | v0 + Claude | UI 생성 + 프론트엔드 로직 |
| 디자인팀 | Freepik | 이미지, 썸네일, 로고 |
| 영상팀 | Kling AI | 광고 영상 제작 |
| 마케팅팀 | CapCut | 영상 편집, 최적화 |
| 사업부 | YouTube / Ads | 배포 + 수익화 |

> 예전에는 이걸 하려면 **7명짜리 회사**가 필요했다.
> 지금은 AI를 지휘할 줄 아는 **1명**이면 된다.
> 이게 창직의 실체다.

## 5-5. 디버깅 — 안 되는 걸 찾는 것 자체가 실력

### 디버깅이란?

앱을 만들면 반드시 에러가 난다. 프로 개발자도 매일 에러를 만난다.
에러를 찾고 고치는 것을 **디버깅(Debugging)**이라고 한다.

### 디버깅 오케스트레이션 전략

```
에러 발생
  → Claude에게 에러 메시지 보여주고 설명 요청
  → 해결 안 됨?
  → ChatGPT에 같은 에러 질문 (다른 관점)
  → 두 답변 비교 → 최적 솔루션 적용
  → 여전히 안 됨?
  → 검색 → Claude에게 재질문
  → 해결!
```

> **"안 되는 걸 찾는 것 자체가 실력"이다.**
> 프로 개발자도 **"만들고 → 써보고 → 고치기"를 매일 반복**한다.
> 완벽하게 만드는 사람은 없다.

## 5-6. 전공 지식 + AI = 진짜 실력

### 핵심 공식

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   전공 지식 (내가 잘 아는 것)                          │
│       +                                             │
│   AI (코드를 짜주고, 분석해주는 도구)                   │
│       +                                             │
│   기획력 (뭘 만들지, 누가 쓸지, 왜 필요한지)            │
│       =                                             │
│   나만의 서비스, 나만의 직업, 나만의 포트폴리오         │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 전공별 AI 결합 예시

| 전공/관심 분야 | + AI 하면 | 가능한 결과물 | 수익 모델 |
|---|---|---|---|
| 축구를 좋아함 | 경기 데이터 분석 | 전술 분석 앱 | 구독 서비스 |
| 웹툰을 좋아함 | 캐릭터/스토리 생성 | AI 웹툰 도우미 | 프리미엄 기능 |
| 요리를 좋아함 | 레시피 추천 알고리즘 | 냉장고 재료 기반 추천 앱 | 광고 + 식품사 협찬 |
| 게임을 좋아함 | 밸런스 데이터 분석 | 게임 공략 자동 생성기 | 광고 수익 |
| 음악을 좋아함 | 화성학 + 멜로디 생성 | AI 작곡 보조 앱 | 건당 과금 |
| 과학을 좋아함 | 실험 데이터 시각화 | 과학 실험 대시보드 | 교육 기관 계약 |
| 환경에 관심 | 이미지 인식 AI | 쓰레기 분류 도우미 | 환경 포인트 + 광고 |
| 동물을 좋아함 | 자연어 처리 | 펫 증상 AI 상담 | 병원 연계 수수료 |
| 학교생활 | 설문·분석 AI | 학교 설문 조사 앱 | 학교 구독 |
| 역사를 좋아함 | 텍스트 분석 AI | 역사 인물 대화 챗봇 | 교육 앱 수익 |

> **AI만 잘 쓰는 사람?** — 남들도 다 쓴다. 차별화가 안 된다.
> **전공만 깊은 사람?** — AI 없으면 만드는 데 시간이 너무 오래 걸린다.
> **전공 지식 + AI?** — 이건 나만 할 수 있다. 이게 미래의 경쟁력이다.

# PART 6. 함께 발전하는 프로젝트식 공부

---

## 6-1. 외워서 공부 vs 만들면서 공부

| 외워서 공부 | 만들면서 공부 |
|---|---|
| 시험 끝나면 까먹음 | 한 번 만들면 안 까먹음 |
| 혼자 함 | 팀이랑 함 |
| 정답이 정해져 있음 | 정답이 없음 (내가 정함) |
| 재미없음 | 내가 만든 거라 재미있음 |
| 교과서 → 시험 → 끝 | 기획 → 만들기 → 피드백 → 개선 → 런칭 |
| 수동적 | 능동적 |
| AI가 대체할 수 있는 능력 | AI가 대체할 수 없는 능력 |

### 프로젝트식 공부의 흐름

```
"이걸로 뭘 만들 수 있지?"
  → 팀이랑 기획
  → AI한테 물어보며 만들기
  → 안 되는 거 발견
  → 고치기
  → 다른 사람한테 보여주기
  → 피드백 받기
  → 더 좋게 만들기
  → (이 과정에서 개념이 머리에 박힌다)
```

> **프로젝트를 만드는 과정 자체가 공부다.**
> 급식 앱을 만들면서 데이터를 배우고,
> 추천 테스트를 만들면서 알고리즘을 배우고,
> 발표를 준비하면서 글쓰기를 배운다.

---

## 6-2. 프로 개발자도 너와 같은 과정을 밟는다

```
구글 개발자도 :     기획 → 설계 → 개발 → 테스트 → 배포
스타트업 대표도 :   아이디어 → 프로토타입 → 검증 → 출시
너희도 :          정하기 → 그리기 → 만들기 → 고치기

과정이 똑같다.
다른 건 규모뿐이다.
```

### 만드는 4단계

| 단계 | 뭘 하나 | 누가 하나 | 예시 |
|---|---|---|---|
| **1. 정하기** | "누구한테, 어떤 문제를 풀어줄 건데?" | 사람 | "우리 반 친구들이 급식 별점을 매길 수 있는 앱을 만들자" |
| **2. 그리기** | "화면이 어떤 순서로 넘어가?" | 사람 | 종이에: 시작 화면 → 별점 입력 → 결과 차트 |
| **3. 만들기** | AI한테 설명해서 코드를 받는다 | **AI** | "별점을 1~5로 매기는 슬라이더 만들어줘" |
| **4. 고치기** | 직접 써보고 불편한 곳을 찾아서 고친다 | 사람 | "버튼이 너무 작아" → "버튼 크게 해줘" |

> 4단계 중에 AI가 하는 건 **3단계 하나뿐**이다.
> 나머지 3개는 전부 사람이 한다.
> 그래서 코딩 실력보다 **"뭘 만들지 정하는 힘"**이 더 중요하다.

---

## 6-3. 수업에서 만드는 것 → 진짜 상업용 제품까지

### 수업 프로젝트 vs 상업용 제품

학교에서 프로젝트를 만들면 보통 여기서 끝난다:

```
만들었다 → 선생님한테 보여줬다 → 점수 받았다 → 끝
```

근데 진짜 세상에서는 이렇다:

```
만들었다 → 사람들이 쓴다 → 피드백을 받는다 → 더 좋게 만든다 → 돈을 번다
```

### 12살도 만들 수 있는 상업용 서비스

| 프로젝트 | 수업에서 끝내면 | 한 단계 더 가면 (상업용) |
|---|---|---|
| 급식 별점 앱 | 우리 반만 씀 | 전국 학교에 배포 → 광고 수익 |
| 취향 추천 테스트 | 친구들끼리 공유 | SNS 바이럴 → 브랜드 협찬 |
| 공부 타이머 | 나만 씀 | 앱스토어 출시 → 유료 전환 |
| AI 과목 튜터 | 수업 때만 | 구독 서비스 → 월 수익 |
| 환경 데이터 대시보드 | 학교 게시 | 지자체 납품 → 계약 수익 |

### 왜 상업용까지 생각해야 하나?

```
이유 1 : 진짜 사용자를 생각하면, 프로젝트 퀄리티가 완전히 달라진다
이유 2 : 포트폴리오에 "500명이 쓴 서비스"라고 적을 수 있다
이유 3 : 2032년 대입에서 "만들어서 실제로 배포했다"는 엄청난 스토리다
이유 4 : 창직의 첫걸음이다 — 내가 만든 걸 세상에 내놓는 경험
이유 5 : 수익이 생긴다 — "고등학생이 직접 만든 서비스로 첫 수입"
```

> **"학생이니까 돈 얘기는 나중에"가 아니다.**
> 지금부터 "누가 쓸까? 돈을 낼까?"를 생각하는 게 진짜 기획이다.

# PART 7. 실제 사례 — 학력이 아니라 "뭘 만들었느냐"의 시대

---

## 7-1. 고졸이 OpenAI에 들어갔다

```
사례: 대학을 안 가고 OpenAI에 입사한 사람들

OpenAI (ChatGPT 만든 회사)에는 대학 졸업장 없이 들어간 사람이 있다.
그들이 가진 건 학벌이 아니라 —

    "내가 직접 만든 프로젝트"
    "GitHub에 올린 코드"
    "사람들이 실제로 쓴 서비스"

이것이었다.
```

### 왜 이런 일이 가능한가?

| 예전에 회사가 본 것 | 지금 회사가 보는 것 |
|---|---|
| 어느 대학 나왔어? | **뭘 만들어봤어?** |
| 성적이 몇 점이야? | **만든 걸 누가 써봤어?** |
| 자격증 있어? | **문제를 어떻게 풀었어?** |
| 인턴 했어? | **네가 만든 서비스 보여줘** |

> 이건 특별한 천재 이야기가 아니다.
> **"만들고, 공유하고, 개선한 경험"**이 학력을 이긴 사례다.

---

## 7-2. 표선고 — 사교육비 0원으로 서울대 합격

```
표선고등학교 (제주도 서귀포시 표선면)

· 2019년: 학생 240명, 폐교 위기
· IB 도입 후: 학생 461명, 지역 인구 500명+ 증가
· 사교육비: 0원 (학원 인프라 부재)
· 수능: 안 봄

결과:
· 2024 대입: 서울대 1, 연세대 1, 고려대 1, UNIST 2, DGIST 2
· 2025 대입: 서울대 1, 연세대 2, 고려대 2, KAIST 1

수능 없이, 학원 없이, 학종(학생부종합전형)만으로.
```

> 이건 우연이 아니라 구조적 성과다.

# 부록 D. Two-Word Test — 프로젝트 아이디어를 만드는 최고의 방법

## "두 단어"면 아이디어가 나온다

프로젝트를 시작할 때 가장 어려운 건 "뭘 만들지?" 정하는 거다.
이때 쓸 수 있는 게 **Two-Word Test**다.

### 방법

```
1단계: "내가 좋아하는 것" 한 단어 → 예: 축구
2단계: "해결하고 싶은 문제" 한 단어 → 예: 전술

두 단어를 합치면 → "축구 전술" → 프로젝트 아이디어가 나온다
```

### Two-Word Test 예시 30개

| 내가 좋아하는 것 | 해결하고 싶은 문제 | 프로젝트 아이디어 |
|---|---|---|
| 축구 | 전술 | 경기 데이터 기반 전술 분석 앱 |
| 음악 | 작곡 | AI 멜로디 생성 도우미 |
| 웹툰 | 캐릭터 | AI 캐릭터 디자인 생성기 |
| 요리 | 레시피 | 냉장고 재료 기반 레시피 추천 |
| 게임 | 밸런스 | 게임 캐릭터 능력치 밸런스 계산기 |
| 패션 | 코디 | 날씨·장소별 코디 추천 AI |
| 영화 | 추천 | 기분 기반 영화 추천 앱 |
| 강아지 | 건강 | 펫 증상 체크 AI 상담 |
| 환경 | 분리수거 | 사진 찍으면 분리수거 방법 알려주는 앱 |
| 수학 | 공식 | 수학 공식 시각화 도구 |

| 여행 | 경비 | 여행 예산 자동 계산기 |

| 운동 | 루틴 | 체력 수준별 운동 루틴 생성기 |
| 급식 | 평가 | 급식 별점 + 리뷰 앱 |

| 뉴스 | 요약 | 오늘의 뉴스 3줄 요약 대시보드 |
| 지도 | 맛집 | 학교 근처 맛집 지도 |
| 시험 | 계획 | AI 시험 공부 계획 생성기 |

| 수면 | 관리 | 수면 패턴 분석 + 추천 |
| 과학 | 실험 | 가상 실험 시뮬레이터 |
| 글쓰기 | 첨삭 | AI 에세이 구조 피드백 도구 |

| 친구 | 일정 | 팀 프로젝트 일정 관리 도구 |
| 학교 | 건의 | 학교 건의 사항 투표 플랫폼 |

### 팀 Two-Word Test 워크숍

```
[5분 활동]

1. 팀원 5명이 각자 종이에 "좋아하는 것 + 문제" 두 단어를 쓴다 (1분)
2. 5장의 종이를 모은다 (30초)
3. 가장 재미있는 조합에 투표한다 (1분)
4. 선택된 조합을 한 줄 기획서로 만든다 (2분30초)

한 줄 기획서 양식:
"[누가] [무엇을] [왜] 쓰는 앱을 만든다"

예시:
"우리 반 친구들이 / 급식 별점을 매기고 리뷰를 쓸 수 있는 / 
 어떤 급식이 인기 있는지 알기 위한 앱을 만든다"
```

# 부록 H. KB 핵심 원칙 5가지 상세

## KB의 5대 핵심 원칙

### 원칙 1: 교육과정 주권 (한국 교육과정 유지)

```
IB와 결정적으로 다른 점:
IB = 스위스 IBO가 만든 교육과정을 쓴다
KB = 한국 2022 개정 교육과정을 그대로 쓴다

→ 교과서, 성취기준, 수업 내용은 그대로
→ 바뀌는 건 "평가 방식"뿐
```

### 원칙 2: 평가 혁신 (논·서·구술형 전환)

```
기존: 객관식 70% + 서술형 30%
KB:   논술형 40~50% + 서술형 30~40% + 구술형 10~20%

"정답을 고르는" 시험에서
"자기 생각을 논리적으로 쓰고 말하는" 시험으로
```

### 원칙 3: 경제적 접근성 (무상)

```
IB: 학교당 연 1,000~1,500만원 IBO 인증비 → 세금 해외 유출
KB: 인증비 0원 → 모든 학교가 신청 가능

전국 8개 교육청이 IBO에 지불한 비용: 누적 약 24.1억원
KB는 이 비용이 0원
```

### 원칙 4: 언어 접근성 (한국어 100%)

```
IB: 많은 학교가 영어로 수업 → 영어 못하면 사실상 배제
KB: 한국어 100% → 모든 학생이 접근 가능
```

### 원칙 5: 수능 연계 가능

```
IB: 수능 병행이 사실상 불가능 (교육과정 자체가 다름)
KB: 수능 개편과 연계 가능 (교육과정이 같으므로)

→ "수시도 하고 정시도 하고" 가 가능한 구조
→ IB 학생들의 가장 큰 불안 요소를 해결
```

# 부록 I. 수익 파이프라인 — 학생 프로젝트가 돈이 되는 경로

## 수익화 5단계 로드맵

```
Level 0 : 학교 프로젝트 (수익 0원)
  → 만들고, 발표하고, 점수 받기
  → 여기서 대부분 멈춘다

Level 1 : 무료 배포 (수익 0원, 사용자 확보)
  → Streamlit Cloud / Vercel로 무료 배포
  → 친구·SNS에 공유 → 사용자 100명 모으기

Level 2 : 광고 수익 (월 1~5만원)
  → Google AdSense 연동
  → 사용자가 많아지면 광고 수익 발생

Level 3 : 프리미엄 기능 (월 5~20만원)
  → 기본 기능은 무료
  → 고급 분석·커스텀 기능은 유료
  → Gumroad / 스토어 결제 연동

Level 4 : B2B 계약 (건당 50~200만원)
  → 다른 학교·기관이 "우리도 쓰고 싶다" 요청
  → 맞춤형 버전 제작 → 계약 수익

Level 5 : SaaS (월 반복 수익)
  → 구독 모델로 전환
  → 매월 자동으로 수익 발생
```

## 학생 수익화 실전 예시

| 프로젝트 | 대상 | 수익 경로 | 예상 수익 (6개월) |
|---|---|---|---|
| 급식 별점 앱 | 전국 중학교 | 학교별 구독 | 월 10~30만원 |
| 취향 추천 테스트 | SNS 사용자 | 브랜드 협찬 + 광고 | 건당 5~20만원 |
| AI 과목 튜터 | 중학생 | 월 구독 | 월 20~50만원 |
| 환경 데이터 대시보드 | 지자체 | B2B 계약 | 건당 100~200만원 |
| 감정 일기 앱 | 10대 | 프리미엄 구독 | 월 5~15만원 |

> **포인트**: 금액이 중요한 게 아니다.
> "내가 만든 것으로 누군가가 돈을 냈다"는 경험 자체가
> 포트폴리오, 대입 면접, 미래 창업의 원천 자산이 된다.

# 부록 L. OECD 학생 주도성(Student Agency) 상세

## 학생 주도성이란?

OECD Education 2030에서 가장 핵심적인 개념.

```
"학생이 자기 학습의 주인공이 되어,
 목표를 설정하고, 과정을 선택하고, 결과에 책임지는 것"
```

### 수동적 학습자 vs 주도적 학습자

| 차원 | 수동적 학습자 | 주도적 학습자 (Student Agency) |
|---|---|---|
| 목표 | 선생님이 정해줌 | **내가 정한다** |
| 내용 | 교과서에 있는 것만 | **내가 궁금한 것까지** |
| 방법 | 강의 듣기 | **직접 찾고, 만들고, 발표** |
| 평가 | 점수를 받는다 | **성장을 확인한다** |
| 실패 | 감점 | **배움의 기회** |
| AI 관계 | 없음 | **AI를 도구로 활용** |

### 학생 주도성의 3단계 성장

```
Level 1 : 선택 (Choice)
  "무엇을 공부할지 내가 고른다"
  예: 프로젝트 주제를 내가 정한다

Level 2 : 행동 (Action)
  "어떻게 할지 계획하고 실행한다"
  예: AI한테 물어보며 직접 만든다

Level 3 : 성찰 (Reflection)
  "왜 이 결과가 나왔는지 돌아보고 개선한다"
  예: 발표 후 피드백을 받고 다시 고친다
```

### 공동 주도성 (Co-Agency)

```
학생 혼자만의 주도성이 아니다.
선생님, 친구, AI와 함께 성장하는 것이 "공동 주도성"이다.

학생 ← 협업 → 교사 (멘토)
학생 ← 협업 → 동료 (팀원)
학생 ← 협업 → AI (도구)
학생 ← 협업 → 학부모 (지원)
학생 ← 협업 → 지역사회 (실전)
```

> **이 수업 전체가 학생 주도성을 훈련하는 과정이다.**
> 주제를 내가 정하고, AI한테 내가 물어보고, 내가 만들고, 내가 발표한다.
> 선생님은 정답을 알려주는 사람이 아니라, 질문을 던지는 사람이다.

# 부록 M. 학부모를 위한 안내문

## "왜 이런 수업을 하나요?"

```
학부모님께,

이 수업은 2032년 대입을 준비하는 수업입니다.

2028학년도부터 수능이 5등급제로 바뀌고,
세특(세부능력 및 특기사항) 비중이 35~40%로 높아집니다.
"시험 점수"만이 아니라 "무엇을 탐구하고 만들었는가"가
대입의 핵심이 됩니다.

이 수업에서 학생은:
· AI를 도구로 활용하는 방법을 배웁니다
· 팀으로 프로젝트를 기획하고 만듭니다
· 직접 발표하고 피드백을 받습니다
· 실패하고 다시 시도하는 경험을 합니다

이것이 2032년 입학사정관이 보고 싶어하는 역량입니다.

## 가치관 스펙트럼 활동

교실의 한쪽을 "강력 동의", 반대쪽을 "강력 반대"로 정하고,
학생들이 자기 입장에 따라 서서 이유를 말하는 활동.

```
질문: "2032년에 수능 점수보다 포트폴리오가 더 중요해질 것이다"

[강력 동의] ←─────────────────────→ [강력 반대]

학생 A: (강력 동의 쪽) "세특 비중이 35~40%면 이미 그렇잖아요"
학생 B: (약간 반대 쪽) "부모가 도와줄 수 있는 애들만 유리한 거 아니에요?"
학생 C: (중간) "둘 다 중요하지 않을까요?"

→ 서로 다른 입장을 듣고, 자기 생각을 정리하는 훈련
→ 이게 KB에서 하는 "구술형 평가"의 기초
```
