## 이 수업의 핵심 운영 방식

### "학생이 머리, 교사가 손"

이 수업에서 AI 도구는 **교사만** 사용한다. 학생은 AI를 직접 조작하지 않는다.

왜?

```
학생 5명이 각자 AI를 쓰면 :
  → 각자 따로 만든다
  → 토론이 사라진다
  → "같이 만드는 경험"이 없어진다
  → 코딩을 아는 1~2명만 주도한다

교사가 AI를 대신 써주면 :
  → 학생 5명이 "뭘 만들지"를 같이 논의한다
  → 토론으로 결정한 것을 교사가 AI로 실행한다
  → 모든 학생이 결과를 보고 의견을 낸다
  → 코딩 경험 없는 학생도 동등하게 참여한다
```

### 수업 진행 사이클

이 수업은 아래 사이클을 계속 반복한다.

```
  ┌──────────────────────────────────────────────────────┐
  │                                                      │
  │   ① 학생 토론    "뭘 만들지?", "어떻게 바꿀까?"      │
  │        ↓                                             │
  │   ② 학생 결정    "이걸로 하자", "버튼 색은 파란색"     │
  │        ↓                                             │
  │   ③ 교사 실행    AI한테 학생이 정한 내용을 전달         │
  │        ↓                                             │
  │   ④ 결과 확인    빔프로젝터/큰 화면으로 같이 본다       │
  │        ↓                                             │
  │   ⑤ 학생 평가    "이거 좋다" / "여기 좀 이상한데?"     │
  │        ↓                                             │
  │   ① 로 돌아간다                                      │
  │                                                      │
  └──────────────────────────────────────────────────────┘
```

### 교사의 위치

```
교사는 "강의하는 사람"이 아니다.
교사는 "AI를 대신 조작해주는 사람"이다.

학생 : "제목을 크게 하고, 배경을 연두색으로 해주세요"
교사 : (AI한테) "st.title을 크게 하고, 배경색을 연두색으로 바꿔줘"
AI   : (코드 수정)
교사 : (실행해서 보여준다)
학생 : "오, 근데 글씨가 안 보여요. 글씨 색도 바꿔주세요"
교사 : (AI한테) "배경이 연두색이니까 글씨가 잘 보이게 색 바꿔줘"

→ 이 과정에서 학생은 "내가 말한 대로 바뀌는" 경험을 한다.
→ 코드를 직접 안 쳐도, "내가 만들고 있다"는 감각을 느낀다.
```

## 수업 운영 원칙

### 교사가 지켜야 할 7가지 원칙

```
원칙 1. 교사는 답을 알려주지 않는다
        "이렇게 하면 돼"가 아니라 "어떻게 하면 좋을까?"로 질문한다.
        학생이 틀린 방향을 갈 때만 힌트를 준다.

원칙 2. AI 조작은 교사가 하되, 결정은 학생이 한다
        "뭘 만들지", "어떻게 바꿀지"는 학생이 토론으로 정한다.
        교사가 "이게 더 낫지 않아?"라고 유도하지 않는다.

원칙 3. 모든 학생이 발언한다
        한 명이 독주하면 "다른 팀원은 어떻게 생각해?"라고 물어본다.
        특히 조용한 학생에게 구체적 역할을 부여한다.

원칙 4. 실패를 허용한다
        학생이 "이건 좀 이상한데..."라고 하는 결과가 나와도
        바로 고치지 말고 "뭐가 이상해? 왜 이상한 것 같아?"를 먼저 물어본다.

원칙 5. 시간을 지킨다
        토론이 길어지면 "지금까지 나온 것 중에서 하나 고르자"로 끊는다.
        완벽한 결정보다 빠른 실행 → 확인 → 수정이 이 수업의 방식이다.

원칙 6. 코드를 설명하지 않는다 (물어볼 때만)
        학생이 "이거 뭐예요?"라고 물어보면 한 줄로만 설명한다.
        "st.button은 버튼을 만드는 코드야" — 이 정도면 충분하다.
        문법 강의를 시작하지 않는다.

원칙 7. 과정을 기록한다
        매 회차 끝에 팀 회고를 반드시 한다.
        "오늘 된 것 / 안 된 것 / 다음에 할 것" 3줄만 적게 한다.
```

### 토론 운영 규칙 (학생에게 1회차에 안내)

```
1. 아이디어에 "그건 안 돼"라고 하지 않는다
   → 대신 "그건 어떻게 하면 될까?"로 바꿔 말한다

2. 한 사람이 30초 이상 말하지 않는다
   → "핵심만 한 문장으로" 습관을 들인다

3. 결정은 다수결이 아니라 합의
   → "다들 이걸로 괜찮아?" 전원 동의를 목표로 한다
   → 안 되면 각자 이유를 한 마디씩 말하고 PM이 정한다

4. "일단 해보자"가 기본
   → 토론만 30분 하는 것보다, 5분 토론 + 만들어보기 + 수정이 낫다
```

## 1회차 교사 지시서 : "왜 만드는가" (2시간)

### 이 시간의 목표

```
학생이 느껴야 할 것 :
  "말만 했는데 앱이 나오네? 우리도 할 수 있겠는데?"

교사가 해야 할 것 :
  - 팀을 만들고 역할을 배분한다
  - 이 수업의 방식(학생 토론 + 교사 AI 실행)을 명확히 설명한다
  - AI로 앱을 만드는 과정을 라이브로 보여준다
  - 팀 주제를 토론으로 정하게 한다
```

#### 0:00~0:10 | 수업 소개 + 분위기 만들기

**교사 행동 :**
- 빔프로젝터에 수업 제목을 띄워놓는다
- "오늘부터 4일간 앱을 하나 만들 거예요"로 시작한다

**교사 멘트 예시 :**
```
"여러분, 혹시 앱 하나 만들어본 적 있어요?

#### 0:25~0:40 | 수업 방식 설명 + "AI 시대에 사람은 뭘 하나?" 토론

**교사 행동 :**

**교사 멘트 예시 (수업 방식 설명) :**
```

 보통 수업은 선생님이 알려주고, 학생이 따라 하잖아요.
 이 수업은 반대예요.

 여러분이 '이런 거 만들어주세요'라고 말하면,
 선생님이 AI한테 전달해서 만들어요.
 결과가 나오면 여러분이 보고 '여기 좀 이상한데?'라고 말하면,
 선생님이 다시 AI한테 고쳐달라고 해요.

 즉, 여러분이 감독이고, 선생님은 카메라를 돌리는 사람이에요.
 감독이 '여기서 잘라'라고 해야 카메라맨이 자를 수 있잖아요.
 그러니까 여러분이 '뭘 해야 하는지'를 정해야 해요."
```

**토론 활동 : "AI가 코드를 다 짜주면, 사람은 뭘 잘해야 할까?"**

```
진행 방법 :
  1. 각 팀에게 A4 1장을 준다
  2. 3분 동안 팀끼리 이야기한다
  3. A4에 "사람이 해야 할 것" 3가지를 적는다
  4. 각 팀 발표 담당이 1가지씩 발표한다

교사가 정리해줄 핵심 :
  → "뭘 만들지 정하기" (기획)
  → "쓰기 편한지 판단하기" (UX)
  → "왜 이걸 만들어야 하는지 이유 찾기" (문제 정의)
  → "안 되는 걸 발견하기" (테스트)
```

**유의사항 :**
- 학생 답변이 "코딩을 배워야 한다"로 나올 수 있다 → "그것도 맞지만, 코딩은 AI가 해줄 수 있잖아. AI가 못하는 건 뭘까?"로 유도
- 정답을 바로 말하지 않고, 학생 답변을 칠판에 적은 뒤 정리한다

#### 0:55~1:25 | 라이브 데모 — 교사가 AI로 5분 만에 앱 만들기

**이 순간이 이 수업 전체에서 가장 중요한 순간이다.**

학생이 "어, 말만 했는데 앱이 나오네? 우리도 할 수 있겠는데?" — 이 감각을 느끼는 것이 1회차의 핵심 목표.

**교사 사전 준비 :**
- AI 도구를 미리 열어놓는다
- 터미널(명령 프롬프트)을 미리 열어놓는다
- `app.py` 파일을 만들 폴더를 미리 준비한다
- 빔프로젝터로 교사 화면 전체를 보여준다

**교사 진행 순서 :**

```
Step 1. 학생한테 물어보기 (1분)
  "자, 선생님이 지금 앱 하나를 만들어볼 건데,
   뭘 만들면 좋겠어요?
   ...좋아요, 급식 별점 앱 만들어볼게요."

   (학생이 아이디어를 말하면 그걸로 하면 가장 좋다.
    아무도 안 말하면 "급식 별점 앱" 또는 "취향 테스트"로 한다)

Step 2. AI한테 말하기 (2분)
  교사가 AI 도구에 아래와 같이 입력한다.
  (학생이 화면을 보고 있으므로 천천히, 크게 보이게)

  프롬프트 예시 :
  ──────────────────────────────────────────────
  "Python Streamlit으로 급식 별점 앱을 만들어줘.
   - 제목이 '오늘 급식 어땠어?'
   - 메뉴 이름을 입력하는 칸이 있어
   - 별점을 1~5로 매기는 슬라이더가 있어
   - 제출 버튼이 있어
   - 제출하면 '감사합니다!' 메시지가 나와"
  ──────────────────────────────────────────────

  (이때 학생들한테 : "보세요, 선생님이 한국어로 말하고 있죠?
   코드를 하나도 안 쳤어요. 그냥 '이런 거 만들어줘'라고 했어요.")

Step 3. 코드 받아서 실행하기 (2분)
  - AI가 준 코드를 복사한다
  - app.py에 붙여넣는다
  - 터미널에서 streamlit run app.py 실행
  - 브라우저에 앱이 뜬다

  (이때 학생 반응을 기다린다.
   "오..." / "와..." 같은 반응이 나오면 성공이다)

Step 4. 학생 의견 받아서 수정하기 (5분)
  "자, 이 앱 어때요? 뭐 바꾸고 싶은 거 있어요?"

  학생이 말하는 것을 AI한테 전달한다.

  예시 :
  학생 : "배경이 좀 밋밋해요"
  교사 → AI : "배경색을 밝은 노란색으로 바꿔줘"
  (수정 후 다시 실행)

  학생 : "별점 옆에 이모지 넣어주세요"
  교사 → AI : "별점 슬라이더 옆에 별 이모지를 넣어줘"
  (수정 후 다시 실행)

  → 이 "말하면 바뀌는" 과정을 2~3번 반복한다
  → 학생이 "아, 말만 하면 되는구나"를 체감하는 게 핵심
```

**교사 마무리 멘트 :**
```
"지금 선생님이 한 걸 정리하면요,

 1. 뭘 만들지 정했어요 → 급식 별점 앱
 2. 어떻게 생겼으면 좋겠는지 말했어요 → 제목, 슬라이더, 버튼
 3. AI한테 만들어달라고 했어요 → 코드가 나왔어요
 4. 써보고 이상한 데를 고쳤어요 → 배경색, 이모지

 이게 4단계예요 : 정하기 → 그리기 → 만들기 → 고치기.
 이걸 앞으로 3일 동안 여러분 팀이 직접 해볼 거예요.
 다만 AI는 선생님이 대신 써줄 거고,
 여러분은 '뭘 만들지', '어떻게 바꿀지'를 팀끼리 의논해서 정하는 거예요."
```

**예상 트러블 :**

| 상황 | 대처 |
|---|---|
| AI가 에러 나는 코드를 줌 | "어, 에러가 났네요. 이것도 실제로 자주 일어나는 일이에요." → 에러 메시지를 AI한테 보내서 고치기 |
| Streamlit이 안 뜸 | 터미널을 닫고 다시 `streamlit run app.py` 실행. 미리 백업 코드를 준비해둔다 |
| 학생 반응이 없음 | "이 앱에 뭘 더 넣으면 좋겠어요? 아무거나 말해봐요. 이모지? 색깔? 소리?" 구체적으로 물어본다 |
| 한 학생이 독주함 | "좋은 아이디어! 다른 친구들은 뭘 넣고 싶어요?" |

**팀 토론 가이드 (PM이 진행) :**

  - 화면 안에 "뭐가 있는지"를 글자로 적는 게 중요
```

## 토론 운영 가이드 (교사용)

### 토론이 안 될 때 대처법

| 상황 | 원인 | 대처 |
|---|---|---|
| 아무도 안 말함 | 뭘 말해야 할지 모름 | "A와 B 중에 뭐가 나아?" 선택지를 준다 |
| 한 명이 독주 | 나머지가 위축됨 | "좋은 아이디어! ○○는 어떻게 생각해?" 지목한다 |
| 토론이 산으로 감 | 주제를 벗어남 | "재밌는 얘기인데, 오늘 정할 건 이거야. 돌아오자" |
| 의견 충돌 | 두 방향이 다 괜찮음 | "둘 다 좋은데, 시간상 하나만 해야 해. 각자 이유 한마디만 하고 PM이 정하자" |
| 시간 초과 | 결정을 못 함 | "지금까지 나온 것 중에서 골라. 완벽한 답은 없어. 일단 해보고 나중에 바꿀 수 있어" |
| 분위기가 가라앉음 | 에러 반복 / 잘 안 됨 | "프로 개발자도 하루에 에러 50번 나요. 우리는 지금 진짜 개발자 체험 중이에요" |

### 질문 기법 — 생각을 이끌어내는 질문

**사용하면 좋은 질문 :**
```
"이 앱을 쓰는 사람이 제일 먼저 뭘 하고 싶을까?"
"여기서 버튼을 누르면 뭐가 나와야 할까?"
"이게 없으면 앱이 안 될까?"
"이 기능은 '있으면 좋은 것'이야, '꼭 필요한 것'이야?"
"처음 보는 사람이 이걸 보면 뭐라고 생각할까?"
"지금 이 상태로 친구한테 보여주면 뭐라고 할까?"
"왜 이게 안 됐다고 생각해?"
```

**피해야 할 질문 :**
```
"다 이해됐죠?" → 아무도 "아니오"를 못 함
"쉽죠?" → 못하는 학생이 위축됨
"이거 해볼 사람?" → 이미 잘하는 학생만 손 듦
```

## 평가 기준

### 과정 중심 평가 루브릭

점수를 매기는 게 아니라, **4단계를 한 바퀴 돌렸는지** 본다.

| 평가 항목 | 상 | 중 | 하 |
|---|---|---|---|
| **기획 (정하기)** | 문제를 명확하게 정의하고, 한 줄 기획서를 팀 토론으로 완성함 | 문제를 정의했으나 구체적이지 않음 | 주제를 정하지 못했거나 토론 없이 한 명이 결정 |
| **설계 (그리기)** | 화면 흐름도가 논리적이고 데이터 구조까지 정리됨 | 화면 흐름도를 그렸으나 빠진 부분이 있음 | 설계 없이 바로 만들기에 들어감 |
| **개발 (만들기)** | 팀원 모두가 수정 요청에 참여하고, 에러를 함께 해결한 흔적이 있음 | 수정 요청은 했으나 일부 팀원만 참여 | 교사에게 전부 맡기고 팀원이 참여하지 않음 |
| **테스트 (고치기)** | 직접 써보고 문제를 발견하여 수정 요청을 함 | 테스트는 했으나 문제 발견이 부족 | 테스트 없이 완성이라고 판단 |
| **팀워크** | 전원이 역할을 수행하고, 토론에 고르게 참여함 | 대부분 참여했으나 참여도 편차가 큼 | 1~2명만 주도하고 나머지가 방관 |
| **발표** | 왜 만들었는지, 뭘 배웠는지를 전달. 시연이 매끄러움 | 발표는 했으나 내용이 부족하거나 시연이 불안정 | 발표를 준비하지 않았거나 시연 불가 |

### 기술적 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| `streamlit run app.py` 안 됨 | Streamlit 미설치 또는 경로 오류 | `pip install streamlit` 재실행. `cd` 명령어로 올바른 폴더 이동 |
| 코드 실행 시 에러 | AI가 잘못된 코드를 줌 | 에러 메시지를 복사해서 AI한테 "이거 왜 안 돼?"로 보내기 |
| 한글이 깨짐 | 인코딩 문제 | `# -*- coding: utf-8 -*-`를 코드 맨 위에 추가 요청 |
| 차트가 안 나옴 | matplotlib/plotly 미설치 | `pip install matplotlib` 또는 Streamlit 내장 차트(`st.bar_chart`) 사용 |
| JSON 저장이 안 됨 | 파일 경로 또는 권한 문제 | 같은 폴더에 `data.json` 파일을 미리 만들어둠 |
| 배포 실패 | requirements.txt 누락 또는 오류 | AI한테 "이 코드에 필요한 requirements.txt 만들어줘" 요청 |
| AI 응답이 느림 | 서버 과부하 | 잠시 기다렸다가 재시도. 백업 AI 도구 준비 |
| AI가 영어로 답함 | 프롬프트에 한국어 지시 누락 | "한국어로 설명해줘"를 프롬프트 끝에 추가 |

### 수업 운영 문제

| 문제 | 대처 |
|---|---|
| 팀 구성 후 분위기가 안 좋음 | 역할을 먼저 정하게 한다. "역할이 있으면 할 일이 명확해져서 편해져요" |
| 주제를 30분 넘게 못 정함 | "3개 후보 중 가위바위보로 정하자. 아니면 선생님이 추천해줄게" |
| 한 학생이 전혀 참여 안 함 | 1:1로 조용히 물어본다. "뭐가 어려워? 관심 있는 역할 있어?" 구체적 작은 일을 배정 |
| 팀 간 진도 차이가 큼 | 빠른 팀에게 "추가 기능 1개를 더 만들어보세요" 또는 "느린 팀을 도와줘" |
| 학생이 "이거 왜 해요?" 물어봄 | "이 앱을 인터넷에 올리면 진짜 친구들이 쓸 수 있어요. 그게 이 수업의 목표예요" |
| 발표를 극도로 싫어하는 학생 | "앱이 대신 말해줘요. 메모 보고 해도 되고, 짧게 해도 돼요" |
