# 바이브 코딩의 탄생

2025년 2월, **안드레이 카파시** (테슬라·OpenAI 공동 창업자)

> "나는 요즘 새로운 종류의 코딩을 하고 있다. 바이브 코딩이라고 부른다. AI에게 말로 설명하고, 코드는 AI가 쓴다."

> 이미지: 안드레이 카파시의 실루엣이 거대한 모니터 앞에 서 있고, 모니터에서 코드가 자동으로 쏟아져 나오는 장면. 보라색과 파란색 네온 톤. 미래적이고 테크 느낌의 일러스트.

### 핵심 정의

**바이브 코딩 = 원하는 것을 말로 설명하면, AI가 코드를 만들어주는 방식**

---

# 전통적 코딩 vs 바이브 코딩

> 이미지: 왼쪽에는 지쳐 보이는 사람이 어두운 화면의 코드 앞에 앉아 있고, 오른쪽에는 밝은 표정의 사람이 AI 로봇과 대화하며 완성된 앱 화면을 보고 있는 대비 일러스트. 좌측은 어두운 톤, 우측은 밝은 톤으로 명확한 대비.

| 비교 항목 | 전통적 코딩 | 바이브 코딩 |
|---|---|---|
| 코드를 누가 쓰나? | 사람이 직접 타이핑 | **AI가 대신 작성** |
| 문법을 외워야 하나? | 반드시 외워야 함 | **몰라도 됨** |
| 필요한 능력 | 프로그래밍 언어 문법 | **원하는 것을 설명하는 능력** |
| 에러가 나면? | 코드를 읽고 직접 수정 | **AI에게 에러를 알려주고 수정 요청** |
| 걸리는 시간 | 며칠~몇 주 | **몇 시간~하루** |
| 비유 | 외국어를 배워서 직접 말하기 | **통역사에게 한국어로 설명하기** |

# 왜 바이브 코딩을 배워야 할까?

> 이미지: 4개의 아이콘이 나란히 있는 인포그래픽. 1) 미래 직업 아이콘(로봇과 사람이 악수), 2) 전구 아이콘(아이디어 실현), 3) 퍼즐 아이콘(문제 해결), 4) 열린 문 아이콘(진입 장벽 제거). 밝은 파스텔 색상, 깔끔한 아이콘 스타일.

| 이유 | 설명 | 예시 |
|---|---|---|
| **미래 직업** | 2030년까지 직업의 60%가 AI와 협업 필요 | 디자이너도 AI로 프로토타입 제작 |
| **아이디어 실현** | 머릿속 아이디어를 즉시 앱으로 | "급식 별점 앱" → 당일 완성 |
| **문제 해결력** | "뭘 만들지"를 정의하는 게 핵심 능력 | 코드를 외우는 것보다 중요 |
| **진입 장벽 제거** | 코딩 경험 0이어도 시작 가능 | 이 수업에서 증명할 것! |

# 바이브 코딩 5단계 방법론

> 이미지: 5개의 계단을 올라가는 사람의 일러스트. 각 계단에 1)기획 2)설명 3)확인 4)수정 5)반복 이 적혀 있고, 꼭대기에는 빛나는 완성된 앱이 있다. 계단마다 색이 다른 그라데이션. 밝고 동기부여가 되는 톤.

| 단계 | 하는 일 | 누가 하나 | 비유 |
|---|---|---|---|
| **1. 기획하기** | 뭘 만들지 정한다 | 사람 | 건축 설계도 그리기 |
| **2. 설명하기** | AI에게 원하는 것을 말한다 | 사람 → AI | 건축가에게 주문하기 |
| **3. 확인하기** | 결과를 실행해서 본다 | 사람 | 완성된 집 둘러보기 |
| **4. 수정하기** | 마음에 안 드는 부분을 고친다 | 사람 → AI | "이 벽 색깔 바꿔주세요" |
| **5. 반복하기** | 2~4를 반복해서 완성도를 높인다 | 사람 + AI | 인테리어 하나씩 추가 |

> 이 5단계는 코딩뿐만 아니라 영상, 디자인, 마케팅에도 **똑같이** 적용됩니다!

# 좋은 프롬프트 vs 나쁜 프롬프트

> 이미지: 좌우 대비 일러스트. 왼쪽에는 흐릿한 말풍선 "타이머 만들어"에 혼란스러운 AI 로봇, 오른쪽에는 상세한 말풍선 "25분 카운트다운, 시작/정지/리셋 버튼, 파란색 배경"에 자신감 있는 AI 로봇. 왼쪽은 회색 톤, 오른쪽은 초록 톤으로 대비.

### 프롬프트 공식: **무엇을 + 어떻게 + 제약 조건**

| 구분 | 나쁜 프롬프트 | 좋은 프롬프트 |
|---|---|---|
| 기능 | "타이머 만들어" | "25분 카운트다운 타이머. 시작, 일시정지, 리셋 버튼" |
| 디자인 | "이쁘게 해줘" | "배경은 연한 파란색, 버튼은 둥근 모서리, 글자 60px" |
| 수정 | "이상해, 다시 해" | "시작 버튼을 눌러도 타이머가 안 움직여. 에러 발생" |
| 추가 | "다 추가해줘" | "타이머 위에 과목 드롭다운 추가. 수학, 영어, 국어" |

### 프롬프트 레벨

| 레벨 | 예시 | AI의 반응 |
|---|---|---|
| 초보 | "타이머 만들어" | 기본 타이머 (원하는 것과 다를 수 있음) |
| 중급 | "25분 타이머, 시작 버튼 있게" | 꽤 괜찮은 타이머 |
| **고급** | "25분 타이머, 시작/정지/리셋, Flask+HTML, 가운데 정렬, 60px, 초록 시작 버튼" | **거의 완벽한 타이머!** |

# 바이브 코딩 도구의 3가지 유형

> 이미지: 3개의 카테고리를 보여주는 인포그래픽. 왼쪽에 로봇 아이콘(AI 에이전트), 가운데에 브라우저 아이콘(웹 빌더), 오른쪽에 코드 에디터 아이콘(어시스턴트). 각 카테고리 아래에 대표 도구 로고들이 나열. 깔끔한 테크 스타일, 밝은 배경.

| 유형 | 특징 | 대표 도구 | 누구에게? |
|---|---|---|---|
| **AI 코딩 에이전트** | AI에게 말하면 파일을 직접 생성/수정 | Claude Code, Replit Agent | 처음 시작하는 사람 |
| **웹 빌더** | 브라우저에서 바로 앱 완성 | V0, Bolt.new, Lovable, Create.xyz | 빠른 프로토타입 |
| **코딩 어시스턴트** | 코드 에디터에서 AI가 옆에서 도움 | Cursor, GitHub Copilot, Windsurf | 코딩 경험 있는 사람 |

### Cursor (Anysphere)

# 코딩 이외의 AI 창작 도구

> 이미지: 6개 카테고리 아이콘이 원형으로 배치된 인포그래픽. 중심에 "AI 창작 도구"라고 적혀 있고, 주변에 1)붓(디자인) 2)카메라(영상) 3)음표(음악) 4)펜(글쓰기) 5)메가폰(마케팅) 6)코드(개발). 각 카테고리 아이콘은 파스텔 색상의 원 안에 있다.

### 이미지/디자인 AI

| 도구 | 하는 일 | 프롬프트 예시 |
|---|---|---|

# AI 오케스트라란?

> 이미지: 오케스트라 지휘자가 무대 위에서 지휘봉을 들고 있는데, 악단석에 사람 대신 AI 로봇들이 각각 다른 악기(바이올린=코딩, 첼로=디자인, 플루트=영상, 드럼=마케팅, 트럼펫=글쓰기, 하프=음악, 피아노=기획)를 연주하고 있다. 장엄하지만 밝고 유쾌한 일러스트 스타일. 보라+금색 톤.

오케스트라 지휘자는 악기를 직접 연주하지 않는다.
대신 **어떤 악기가 언제, 어떻게 연주할지** 결정한다.

AI 오케스트라의 지휘자도 마찬가지!
코드를 직접 쓰지 않고, **어떤 AI가 언제, 무엇을 만들지** 결정한다.

# 127.0.0.1:5000 — 이 숫자의 의미

> 이미지: 아파트 건물 일러스트. 건물 전체가 "127.0.0.1 (내 컴퓨터)" 이고, 5000호 방에 불이 켜져 있으며 문에 "Flask 서버 영업 중" 간판이 걸려 있다. 택배 기사(브라우저)가 5000호 문 앞에 서서 주문서를 들고 있다. 아기자기한 일러스트 스타일.

| 부분 | 의미 | 비유 |
|---|---|---|
| **127.0.0.1** | 내 컴퓨터 자체를 가리키는 주소 | 우리 집 주소 |
| **:** | 주소와 포트를 구분하는 기호 | 동(棟) 표시 |
| **5000** | Flask가 사용하는 포트 번호 | 5000호 (방 번호) |

> **"내 컴퓨터의 5000번 방에서 Flask 서버가 손님을 기다리고 있다"**

# GET vs POST — 두 가지 주문 방식

> 이미지: 좌우 대비 일러스트. 왼쪽에 웨이터가 음식을 가져다주는 모습(GET - 정보를 가져온다), 오른쪽에 손님이 주문서를 건네는 모습(POST - 정보를 보낸다). 왼쪽은 파란 톤, 오른쪽은 초록 톤으로 구분. 깔끔한 플랫 일러스트.

| 비교 | GET 요청 | POST 요청 |
|---|---|---|
| **뜻** | "정보를 **가져와라**" | "정보를 **보내라**" |
| **방향** | 서버 → 브라우저 (읽기) | 브라우저 → 서버 (쓰기) |
| **언제?** | 주소창에 URL 입력 | 기록 저장할 때 |
| **우리 앱** | 홈페이지 보기, 기록 불러오기 | 공부 기록 저장 |
| **식당 비유** | 메뉴판 달라고 하기 | 주문서 제출하기 |

# 타이머 동작 알고리즘

> 이미지: 큰 원형 타이머(디지털 시계 스타일)가 화면 중앙에 있고, 아래에 3개 버튼(초록-시작, 노랑-일시정지, 빨강-리셋)이 있다. 타이머 주변에 숫자가 줄어드는 애니메이션 효과(25:00 → 24:59 → 24:58). 미래적인 네온 파란 톤.

### 시작 버튼 → 카운트다운 알고리즘

| 순서 | 동작 | 설명 |
|:---:|---|---|
| 1 | 사용자가 '시작' 클릭 | 이벤트 발생 |
| 2 | 1초마다 반복 실행 예약 | JavaScript가 담당 |
| 3 | 매 1초마다 남은 시간 - 1 | 1500초 → 1499초 → ... |
| 4 | 분:초로 변환해서 화면 업데이트 | 1499초 → 24:59 |
| 5 | 남은 시간 = 0이면 정지 | 반복 실행 멈춤 |
| 6 | "수고했어!" 메시지 | 사용자에게 알림 |
| 7 | 서버에 기록 저장 요청 (POST) | Flask가 records.json에 저장 |

### 각 버튼의 역할

| 버튼 | 동작 |
|---|---|
| **▶ 시작** | 1초마다 반복 실행 시작 |
| **⏸ 일시정지** | 반복 실행 멈춤 (시간은 유지) |
| **🔄 리셋** | 반복 실행 멈춤 + 시간을 25:00으로 되돌림 |

# 요청과 응답 — 전체 흐름 따라가기

> 이미지: 왼쪽에 브라우저 창(사용자 아이콘), 오른쪽에 서버(Flask 로고). 둘 사이에 4개의 화살표가 순서대로 그려져 있다. ①→ GET 요청, ②← HTML 응답, ③→ POST 기록 저장, ④← "저장 완료" 응답. 각 화살표에 번호와 설명 라벨. 택배 상자가 오가는 느낌의 밝은 일러스트. 파란+초록 배경.

### 시나리오: 민수가 공부 타이머를 사용하는 과정

| 순서 | 누가 | 무엇을 | 비유 |
|:---:|---|---|---|
| ① | 민수 (브라우저) | `127.0.0.1:5000` 접속 → **GET /** 요청 보냄 | 식당 문을 열고 "메뉴판 주세요" |
| ② | Flask (서버) | `templates/index.html`을 찾아서 브라우저에 전달 | 주방장이 메뉴판(화면)을 건넴 |
| ③ | 민수 (브라우저) | 타이머 25분 완료 → **POST /save** 기록 전송 | "이 주문서 접수해 주세요" |
| ④ | Flask (서버) | `records.json`에 과목·시간·날짜 저장 → "OK" 응답 | 냉장고에 재료 넣고 "접수 완료!" |
| ⑤ | 민수 (브라우저) | **GET /records** 요청 → 기록 목록 불러오기 | "지금까지 주문 내역 보여주세요" |
| ⑥ | Flask (서버) | `records.json` 읽어서 JSON 목록 전달 | 냉장고에서 재료 꺼내서 보여줌 |

> **핵심:** 모든 통신은 **요청 → 응답** 쌍이다. 브라우저가 먼저 요청해야 서버가 응답한다. 서버가 먼저 말을 거는 법은 없다!

# HTML 화면 구조 — 무엇이 어디에?

> 이미지: 웹 브라우저 안에 공부 타이머 앱 화면이 있고, 화면의 각 영역에 빨간 점선 박스와 번호가 매겨져 있다. ①제목 영역(h1 태그), ②과목 선택 영역(select 태그), ③타이머 숫자 영역(div, 60px), ④버튼 3개 영역(button 태그), ⑤기록 목록 영역(table 태그). 옆에 화면설계서(와이어프레임) 느낌의 설명 노트. 깔끔한 청사진 스타일, 연한 파란 배경.

### 타이머 앱 화면 구성 요소

| 번호 | 영역 | HTML 역할 | 사용자가 보는 것 | 식당 비유 |
|:---:|---|---|---|---|
| ① | **제목** | 앱 이름 표시 | "공부 타이머" 글씨 | 간판 |
| ② | **과목 선택** | 드롭다운 메뉴 | 수학, 영어, 국어... 고르기 | 메뉴 카테고리 |
| ③ | **타이머 숫자** | 카운트다운 표시 | 25:00 → 24:59 → ... | 조리 시간 표시판 |
| ④ | **버튼 3개** | 시작/정지/리셋 | 클릭하면 동작 | 주문/취소/변경 버튼 |
| ⑤ | **기록 목록** | 공부 이력 표 | 과목, 시간, 날짜 리스트 | 주문 영수증 |
| ⑥ | **디자인 (CSS)** | 색상, 크기, 정렬 | 예쁜 화면 | 인테리어 |

|---|---|---|

| 제목 아래 | 과목 선택 드롭다운 | "과목을 고를 수 있는 드롭다운, 수학/영어/국어/과학" |
| 중앙 | 타이머 숫자 (60px, 큰 글씨) | "25:00 형식의 큰 숫자, 가운데 정렬" |
| 숫자 아래 | 시작/일시정지/리셋 버튼 | "초록 시작, 노랑 정지, 빨강 리셋 버튼 3개" |
| 맨 아래 | 공부 기록 표 | "날짜, 과목, 시간이 나오는 기록 테이블" |

# JavaScript가 하는 일 — 화면을 움직이는 마법

> 이미지: 마법사 모자를 쓴 JavaScript 로고 캐릭터가 지팡이를 휘두르고 있다. 지팡이에서 나온 마법이 화면 속 타이머 숫자를 움직이게 하고, 버튼에 빛을 내고, 서버로 편지(데이터)를 날리고 있다. 배경에 코드 줄들이 반투명하게 떠다닌다. 보라+금색의 마법 느낌 일러스트.

### JavaScript의 4가지 역할

| 역할 | 하는 일 | 비유 | 예시 |
|---|---|---|---|
| **1. 이벤트 감지** | 버튼 클릭을 감지 | 초인종이 울리면 반응 | "시작 버튼 클릭" 감지 |
| **2. 시간 계산** | 1초마다 숫자 줄이기 | 모래시계 뒤집기 | 1500 → 1499 → 1498... |
| **3. 화면 업데이트** | 계산 결과를 화면에 표시 | 전광판 숫자 바꾸기 | "24:59" 표시 |
| **4. 서버 통신** | Flask에 기록 전송 | 편지 보내기 | POST /save 요청 |

### HTML vs JavaScript 역할 구분

| 질문 | 담당 | 이유 |
|---|---|---|
| 버튼이 화면에 **보이는** 것 | HTML | HTML은 "뭐가 있는지" 정한다 |
| 버튼을 **클릭하면 반응**하는 것 | JavaScript | JS는 "무슨 일이 일어나는지" 정한다 |
| 타이머 숫자가 **표시**되는 것 | HTML | 숫자를 담는 그릇 |
| 타이머 숫자가 **줄어드는** 것 | JavaScript | 매 초 숫자를 바꾸는 역할 |
| 기록 표의 **틀**이 있는 것 | HTML | 표(table)의 구조 |
| 기록이 표에 **추가**되는 것 | JavaScript | 서버에서 가져와서 넣음 |

> **쉬운 구분법:** HTML은 "무대 세트" (고정), JavaScript는 "배우" (움직임)

# 데이터가 저장되는 과정 — records.json

> 이미지: 냉장고(records.json) 문이 열려 있고, 안에 칸칸이 정리된 선반이 보인다. 각 선반에 "수학 25분 2025-03-15", "영어 15분 2025-03-15" 같은 라벨이 붙은 식재료 상자가 놓여 있다. 냉장고 옆에 Flask 요리사가 새 상자를 넣는 모습. 아기자기한 일러스트, 밝은 민트+노란 배경.

### 저장 데이터 구조

| 필드 | 의미 | 예시 값 | 식당 비유 |
|---|---|---|---|
| **subject** | 과목 이름 | "수학" | 요리 종류 |
| **duration** | 공부한 시간 (분) | 25 | 조리 시간 |
| **date** | 날짜 | "2025-07-23" | 주문 날짜 |
| **time** | 시각 | "14:30:00" | 주문 시각 |

### 저장 과정 단계별

| 순서 | 어디서 | 무슨 일이? | 비유 |
|:---:|---|---|---|
| 1 | 브라우저 (JS) | 과목, 시간, 날짜를 묶어서 서버에 보냄 | 주문서 작성해서 전달 |
| 2 | 서버 (Flask) | 받은 데이터를 읽음 | 주문서 내용 확인 |
| 3 | 서버 (Flask) | 기존 records.json을 열어서 데이터 추가 | 냉장고 열고 재료 추가 |
| 4 | 서버 (Flask) | 파일 저장 후 "성공!" 응답 | 냉장고 문 닫고 "접수 완료!" |
| 5 | 브라우저 (JS) | 성공 응답 받으면 기록 목록 새로고침 | 영수증 업데이트 |

### records.json 데이터 예시

| # | 과목 | 시간 | 날짜 | 시각 |
|:---:|---|---|---|---|
| 1 | 수학 | 25분 | 2025-07-23 | 09:30 |
| 2 | 영어 | 15분 | 2025-07-23 | 10:15 |
| 3 | 국어 | 25분 | 2025-07-23 | 14:00 |
| 4 | 과학 | 20분 | 2025-07-24 | 08:30 |

> **파일이 없으면?** 걱정 마세요! Flask가 자동으로 빈 파일을 만들어줍니다.

# 에러가 나면? — 흔한 실수 TOP 5

> 이미지: 5개의 경고 표지판이 도로에 세워져 있는 일러스트. 각 표지판에 흔한 에러 상황이 적혀 있다. 표지판 옆에 민수가 메모장을 들고 체크하고 있는 모습. 표지판은 노란색 삼각형 경고 스타일, 도로는 코드 줄 무늬. 밝지만 주의를 주는 노란+빨간 톤.

### 실습할 때 자주 만나는 에러 5가지

| 순위 | 에러 상황 | 원인 | 해결 방법 | AI에게 말하는 프롬프트 |
|:---:|---|---|---|---|
| 1 | 페이지가 안 열림 (연결 거부) | Flask 서버를 안 켰음 | 터미널에서 `python app.py` 실행 | "서버가 안 켜져. 에러 메시지 보여줄게" |
| 2 | 화면이 안 보임 (404 Not Found) | `templates` 폴더 이름 오타 | `templates` 철자 확인 (s 필수!) | "404 에러가 나와. 폴더 구조 확인해줘" |
| 3 | 타이머가 안 움직임 | JavaScript 로직 오류 | 브라우저 콘솔(F12)에서 에러 확인 | "시작 버튼 눌러도 반응 없어. 콘솔 에러 보여줄게" |
| 4 | 기록이 안 저장됨 | POST 요청 경로 불일치 | app.py의 라우트 주소와 JS의 요청 주소 비교 | "기록 저장이 안 돼. app.py와 JS 코드 확인해줘" |
| 5 | 한글이 깨짐 | 파일 인코딩 문제 | UTF-8로 저장 | "한글이 깨져 보여. 인코딩 수정해줘" |

### 에러 해결의 3단계 공식

| 단계 | 하는 일 | 비유 |
|:---:|---|---|
| 1 | **에러 메시지 읽기** — 빨간 글씨를 무시하지 마세요! | 의사의 진단서 읽기 |
| 2 | **에러 메시지 복사해서 AI에게 붙여넣기** | 진단서를 전문가에게 보여주기 |
| 3 | **AI가 알려준 수정 사항 적용 → 다시 실행** | 처방대로 약 먹고 다시 검사 |

> **가장 중요한 것:** 에러는 **실패가 아니라 힌트**다! 에러 메시지는 컴퓨터가 "여기가 문제야"라고 알려주는 것!

# 각 언어의 역할 정리

> 이미지: 3명의 캐릭터가 팀을 이루고 있는 일러스트. 1) 파이썬 뱀 캐릭터(Flask/주방장) - 앞치마 착용, 2) HTML 블록 캐릭터(뼈대/접시) - 사각형 몸체, 3) JavaScript 번개 캐릭터(움직임/서빙 로봇) - 번개 모양. 셋이 팔짱을 끼고 한 팀이라는 것을 보여줌. 밝고 귀여운 캐릭터 스타일.

| 언어 | 역할 | 실행 장소 | 이 프로젝트에서 | 식당 비유 |
|---|---|---|---|---|
| **Python (Flask)** | 서버 | 내 컴퓨터 | HTML 전달, 기록 저장 | 주방장 |
| **HTML + CSS** | 화면 뼈대 + 디자인 | 브라우저 | 타이머, 버튼, 색상 | 접시 + 데코 |
| **JavaScript** | 화면 움직임 | 브라우저 | 카운트다운, 서버 통신 | 서빙 로봇 |

> **민수의 깨달음:** "Flask는 **배달부**, HTML은 **상품**, JavaScript는 상품 안에서 **움직이는 부분**, records.json은 **창고**구나!"

# 왜 Flask + HTML 조합인가?

> 이미지: 체크리스트 일러스트. 7개 항목이 있고, "HTML만"으로는 3개에 X표시(못 함), "Flask+HTML"로는 7개 전부 체크(가능). 체크 표시는 초록, X 표시는 빨강. 깔끔한 체크리스트 UI 스타일.

| 기능 | HTML만 | Flask+HTML | 이유 |
|---|:---:|:---:|---|
| 타이머 보여주기 | ✅ | ✅ | 화면 표시는 HTML/JS 역할 |
| 버튼 클릭 반응 | ✅ | ✅ | JavaScript가 처리 |
| 공부 기록 저장 | ❌ | ✅ | 서버 없이는 파일에 쓸 수 없다 |
| 다음 접속 시 기록 유지 | ❌ | ✅ | 서버가 데이터를 영구 보관 |
| 여러 기기에서 접속 | ❌ | ✅ | 서버는 네트워크로 접근 가능 |
| 통계/분석 계산 | ⚠️ | ✅ | Python의 데이터 처리 능력 |
| 사용자 구분 (로그인) | ❌ | ✅ | 서버가 세션 관리 |

# 폴더 구조 & 주의사항

> 이미지: 파일 탐색기(Finder/Explorer) 스타일의 일러스트. study-timer 폴더가 열려 있고, 안에 app.py(파이썬 아이콘), templates 폴더(안에 index.html), records.json(데이터 아이콘)이 보인다. templates 폴더에 빨간 느낌표가 떠 있고 "이름 틀리면 안 돼!" 말풍선. 깔끔한 UI 스타일.

| 폴더/파일 | 역할 | 중요도 |
|---|---|---|
| **app.py** | Flask 서버 코드 | 필수 |
| **templates/** | HTML 저장 폴더 (Flask는 **여기서만** 찾음) | 필수 |
| **static/** | CSS, JS, 이미지 (우리는 HTML 안에 넣어서 생략) | 선택 |
| **records.json** | 공부 기록 데이터 (앱 실행 후 자동 생성) | 자동 |

> ⚠️ **자주 나는 실수:** `templates`를 `template` (s 빠짐)으로 쓰면 안 됩니다!

### 핵심 공식

> **기획 → 설명 → 확인 → 수정 → 반복**

이 공식은 코딩에도, 영상에도, 디자인에도, 음악에도, 사업에도 통한다.
도구만 바뀔 뿐, 방법은 같다.

> **"코딩을 잘하는 사람"이 아니라 "설명을 잘하는 사람"이 만드는 시대.**
> **"혼자서 다 할 수 있는 사람"이 아니라 "AI를 잘 지휘하는 사람"이 이기는 시대.**
