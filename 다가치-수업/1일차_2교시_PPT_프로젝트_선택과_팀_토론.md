# PPT 4
# "말만 했는데 앱이 나왔어?"

2교시 시작하자마자, 선생님이 직접 보여준다.

> **선생님**: "급식 별점 앱 만들어줘.
> 오늘 메뉴가 위에 보이고,
> 별점을 1~5점으로 매기는 슬라이더가 있고,
> 제출 버튼이 있어.
> Python Streamlit으로 만들어줘."

- AI가 코드를 만든다 **(30초)**
- 터미널에서 실행한다 **(10초)**
- 브라우저에 앱이 뜬다

> **학생 반응**: "와, 말만 했는데 앱이 나왔어?"
> 이 순간이 이 수업 전체의 시작점이다.
> **"나도 할 수 있겠는데?"** — 이 자신감이 나머지 3일의 연료다.

# PPT 5
# 바이브 코딩이란 — 30초 복습

AI에게 **"원하는 것"을 말로 설명**하면 AI가 코드를 만들어주는 것

| 사람이 하는 것 | AI가 하는 것 |
|---|---|
| "뭘 만들지?" 정하기 | 코드 작성 |
| "누가 쓸 건데?" 생각 | 에러 수정 |
| "이거 괜찮아?" 판단 | 반복 작업 |
| 전체 구조 설계 | 세부 구현 |

> 코딩 문법을 외울 필요 없다. **한국어로 말하면 된다.**
> 대신 **"뭘 만들지 정확히 정하는 것"**이 중요하다.
> 그래서 지금부터 할 것이 → **프로젝트를 고르는 것**이다.

# PPT 6
# 우리가 쓸 도구 — Python + Streamlit

| 도구 | 뭔데? | 비유 |
|---|---|---|
| **Python** | 프로그래밍 언어 | 요리 재료 |
| **Streamlit** | Python으로 웹앱을 쉽게 만드는 도구 | 레고 블록 (조립만 하면 앱이 됨) |
| **AI (Claude / ChatGPT)** | 코드를 대신 짜주는 도우미 | 전문 요리사 (메뉴만 정하면 만들어줌) |

- Python만 쓰면 → 까만 화면에 글자만 나옴 **(재미없음)**
- Python + Streamlit → 버튼, 슬라이더, 차트가 있는 웹앱 **(재미있음)**
- Python + Streamlit + AI → 말만 하면 웹앱이 나옴 **(마법)**

# PPT 7
# 프론트엔드만으로 할 수 있는 것 vs 서버가 필요한 것

프로젝트를 고르기 전에, 하나만 알면 된다.

> **"나만 쓰고, 내 컴퓨터에만 저장하면 되면"** → 서버 없이 만들 수 있다
> **"여러 사람이 동시에 쓰고, 데이터를 모아야 하면"** → 서버가 필요하다

| 상황 | 서버 필요? | 이유 |
|---|---|---|
| 나만 공부 기록 볼래 | 필요 없음 | 내 브라우저에 저장하면 끝 |
| 친구랑 공부 시간 비교 | 필요함 | 친구 데이터를 모아야 하니까 |
| 혼자 하는 방탈출 게임 | 필요 없음 | 내 화면에서만 돌아가면 됨 |
| 전교생 급식 별점 수집 | 필요함 | 여러 명의 별점을 합쳐야 하니까 |

> **이 수업에서는 서버 없이 만들 수 있는 프로젝트를 한다.**
> 핵심 기능을 먼저 만들고 → 나중에 서버를 붙이면 진짜 서비스가 된다.

# 아이디어 ① 감정 방탈출 게임

**한 줄 설명**: 감정을 입력하면 스토리가 갈라지는 텍스트 방탈출 게임
**누가 쓰나**: 쉬는 시간에 3분 놀이를 찾는 친구들
**서버 필요**: 아니오

| 항목 | 내용 |
|---|---|
| 화면 수 | 3~5개 (인트로 → 방 2~3개 → 엔딩) |

# 10개에 없는 아이디어를 만들고 싶다면?

**Two-Word Test**를 써봐.

### 방법
1단계: "내가 좋아하는 것" 한 단어 → 예: 축구
2단계: "해결하고 싶은 문제" 한 단어 → 예: 전술

두 단어를 합치면 → **"축구 전술"** → 프로젝트 아이디어

| 좋아하는 것 | 문제 | 프로젝트 아이디어 |
|---|---|---|
| 축구 | 전술 | 경기 데이터 전술 분석 앱 |
| 웹툰 | 캐릭터 | AI 캐릭터 디자인 생성기 |
| 요리 | 레시피 | 냉장고 재료 기반 추천 앱 |
| 게임 | 밸런스 | 게임 캐릭터 능력치 계산기 |

> **규칙: Python + Streamlit으로 만들 수 있어야 한다.**
> 잘 모르겠으면 AI한테 물어봐: "이 아이디어를 Streamlit으로 만들 수 있어?"

# PPT 35
# 화면 흐름도 스케치 — 종이에 그리기

프로젝트를 정했으면, **종이에 화면 흐름을 그린다.**
코드를 짜기 전에 "어떤 화면이 어떤 순서로 나오는지"를 먼저 정해야 한다.

### 그리는 법
1. A4 종이를 가로로 놓는다
2. **네모칸**을 그린다 = 화면 1개
3. 화면 안에 **"뭐가 보이는지"** 간단히 적는다
4. 화면과 화면 사이에 **화살표**를 그린다
5. 화살표 위에 **"어떤 행동을 하면 넘어가는지"** 적는다
