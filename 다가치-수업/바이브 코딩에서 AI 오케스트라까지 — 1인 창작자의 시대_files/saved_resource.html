Flask란 정확히 무엇인가?

Flask는 Python으로 웹 서버를 만드는 프레임워크(도구 모음)다. "마이크로 프레임워크"라고 불리는데, 이유가 있다:

● Flask (마이크로)

  • 필요한 것만 가볍게
  • 파일 2~3개로 시작
  • 배우기 쉽다
  • 작은 프로젝트에 최적
  • 코드가 단순하고 읽기 쉽다

◯ Django (풀스택)

  • 기능이 매우 많다
  • 파일이 10개 이상 필요
  • 배우는 데 오래 걸린다
  • 대형 프로젝트에 적합
  • 구조가 복잡하다
왜 Flask를 선택하나?

바이브 코딩에서 가장 중요한 원칙은 "빠르게 만들고, 빠르게 확인한다"이다. Flask는 app.py 파일 하나로 서버를 시작할 수 있고, 코드 5줄이면 웹 페이지를 띄울 수 있다. 복잡한 설정 없이 아이디어 → 실행까지 가장 빠른 경로를 제공한다.

Flask 서버의 동작 알고리즘

python app.py를 실행하면 정확히 어떤 일이 벌어지는가?

⚙ 서버 시작 알고리즘

  1. python app.py 실행 — Python이 app.py 파일을 읽기 시작한다
  2. app = Flask(__name__) — Flask 앱 객체를 생성한다. 이 객체가 "주방장"이다
  3. @app.route('/') — "누군가 / 주소로 오면 이 함수를 실행해라"라는 규칙을 등록한다
  4. app.run(debug=True) — 서버가 127.0.0.1:5000 에서 대기 상태로 진입한다
  5. 서버는 꺼지지 않고 계속 대기한다 — 손님(브라우저)이 올 때까지

서버가 켜진 뒤, 브라우저가 접속하면 요청-응답 사이클이 시작된다:

1
브라우저가 요청을 보낸다

주소창에 http://127.0.0.1:5000 을 입력하면, 브라우저가 Flask 서버에 GET / 요청을 보낸다. "홈페이지를 보여달라"는 주문서다.

2
Flask가 라우트를 찾는다

@app.route('/') 와 일치하는 함수 home()을 찾는다. 마치 주방장이 "이 주문에 맞는 레시피가 뭐지?" 하고 찾는 것과 같다.

3
HTML 파일을 읽는다

render_template('index.html') 이 templates/ 폴더에서 index.html 파일을 찾아서 읽는다. 요리 재료를 냉장고에서 꺼내는 과정이다.

4
브라우저에 HTML을 보낸다

완성된 HTML을 HTTP 응답으로 브라우저에 돌려보낸다. 완성된 요리를 접시에 담아 손님에게 내주는 것이다.

5
브라우저가 화면을 그린다

받은 HTML을 해석해서 화면에 타이머, 버튼, 기록 영역을 그린다. 이제부터 JavaScript가 타이머 동작을 담당한다.

127.0.0.1:5000 — 이 숫자는 뭘까?

부분의미비유
127.0.0.1내 컴퓨터 자체를 가리키는 주소 (localhost)우리 집 주소
:주소와 포트를 구분하는 기호동(棟) 표시
5000Flask가 사용하는 포트 번호5000호 (방 번호)

즉, "내 컴퓨터의 5000번 방에서 Flask 서버가 손님을 기다리고 있다"는 뜻이다. 다른 프로그램이 이미 5000번을 쓰고 있으면, app.run(port=5001) 처럼 방 번호를 바꿀 수 있다.

app.py 코드 완전 해부

GET vs POST — 두 가지 주문 방식

HTTP에는 여러 "주문 방식"이 있다. 우리 앱에서는 두 가지를 쓴다:

📥 GET 요청

  • "정보를 가져와라"
  • 데이터를 읽기만 한다
  • 주소창에 URL 입력 = GET
  • 예: 홈페이지 보기, 기록 불러오기

📤 POST 요청

  • "정보를 보내라"
  • 데이터를 저장/수정한다
  • JavaScript에서 fetch()로 전송
  • 예: 공부 기록 저장하기

데이터 저장 알고리즘: 기록이 저장되는 전체 과정

25분 타이머가 끝나는 순간부터, 기록이 파일에 저장되기까지의 전체 흐름:

💾 기록 저장 전체 알고리즘

  1. 타이머가 00:00에 도달 — JavaScript의 setInterval이 감지
  2. JavaScript가 저장할 데이터를 JSON으로 만든다: {"subject":"수학", "minutes":25}
  3. fetch('/save', {method:'POST', body:JSON}) — Flask 서버에 POST 요청 전송
  4. Flask가 request.json으로 데이터를 받는다
  5. records.json 파일을 열어서 기존 기록을 읽는다
  6. 새 기록에 날짜를 추가하여 목록 끝에 덧붙인다
  7. 업데이트된 전체 기록을 records.json에 다시 저장한다
  8. {"status":"ok"}를 브라우저에 돌려보낸다
  9. JavaScript가 응답을 받고 화면에 "저장 완료!" 메시지를 표시한다

타이머 동작 알고리즘: JavaScript의 역할

타이머의 카운트다운은 Flask가 아니라 JavaScript가 담당한다. 브라우저 안에서 돌아가는 코드다.

⏱ 카운트다운 타이머 알고리즘

  1. 사용자가 "시작" 버튼을 클릭한다
  2. setInterval(함수, 1000) — 1초(1000ms)마다 함수를 반복 실행하도록 예약
  3. 매 1초마다: 남은 시간에서 1을 뺀다
  4. 남은 시간을 분:초 형식으로 계산한다 — Math.floor(seconds/60) + seconds%60
  5. 계산 결과를 화면의 타이머 영역에 업데이트한다 — element.textContent = "24:59"
  6. 남은 시간이 0이 되면: clearInterval로 반복을 멈추고, "수고했어!" 표시 + 기록 저장 요청
let timeLeft = 25 * 60; // 25분 = 1500초 let timer = null; function startTimer() { timer = setInterval(() => { timeLeft--; const min = Math.floor(timeLeft / 60); const sec = timeLeft % 60; document.getElementById('timer').textContent = `${min}:${sec < 10 ? '0'+sec : sec}`; if (timeLeft <= 0) { clearInterval(timer); // 타이머 멈춤 saveRecord(); // 기록 저장 alert('수고했어! 쉬는 시간!'); } }, 1000); // 1000ms = 1초마다 실행 } function pauseTimer() { clearInterval(timer); // 반복 실행을 멈춤 } function resetTimer() { clearInterval(timer); timeLeft = 25 * 60; // 시간을 원래대로 document.getElementById('timer').textContent = '25:00'; }
함수역할핵심 명령
setInterval지정한 시간마다 함수를 반복 실행1초마다 시간 빼기
clearInterval반복 실행을 멈춤일시정지, 리셋, 종료 시
Math.floor소수점을 버림 (내림)초를 분으로 변환
% (나머지)나눗셈의 나머지 계산남은 초 계산
textContent화면의 텍스트를 바꿈타이머 숫자 업데이트

왜 Flask + HTML 조합인가?

다른 방법도 있지만, 이 수업에서 Flask + HTML을 선택한 이유가 있다.

배움의 효율성

파일 2개(app.py + index.html)로 서버와 화면의 전체 구조를 이해할 수 있다. 복잡한 프레임워크 없이 웹의 핵심 원리를 배운다.

데이터 저장 가능

순수 HTML만으로는 데이터를 파일에 저장할 수 없다. Flask가 있으면 공부 기록을 영구 저장하고, 다음에 접속해도 볼 수 있다.

확장이 쉽다

나중에 사용자 로그인, 데이터베이스, 실시간 기능을 추가할 때 Flask의 구조를 그대로 확장하면 된다.

실제 서비스와 같은 구조

네이버, 유튜브 같은 실제 서비스도 "서버 + 클라이언트" 구조다. 작은 앱에서 이 구조를 체험하면 큰 서비스의 원리도 이해된다.

바이브 코딩과 궁합

Flask의 코드가 직관적이라 AI가 만든 코드를 읽고 이해하기 쉽다. 바이브 코딩의 "확인→수정" 단계가 수월해진다.

무료 + 가볍다

설치가 pip install flask 한 줄이면 끝. 무겁지 않아서 학교 컴퓨터에서도 잘 돌아간다.

Flask 서버가 HTML 파일을 찾는 규칙

Flask는 HTML 파일을 아무 데서나 찾지 않는다. 정해진 폴더 구조가 있다:

# Flask가 기대하는 폴더 구조 study-timer/ ├── app.py # Flask 서버 코드 (여기서 python app.py 실행) ├── records.json # 공부 기록 데이터 파일 ├── templates/ # ⚠ Flask는 이 폴더에서만 HTML을 찾는다 │ └── index.html # 타이머 화면 └── static/ # (선택) CSS, JS, 이미지 파일 ├── style.css └── logo.png
폴더역할중요도
templates/HTML 파일 저장 — render_template()이 여기서 찾음필수
static/CSS, JS, 이미지 등 정적 파일선택 (우리는 HTML 안에 CSS/JS를 넣어서 생략)
records.json데이터 저장 파일 (처음엔 없고, 앱 사용 중 자동 생성)앱 실행 후 생김
자주 나는 실수

templates 폴더 이름을 template (s 빠짐)으로 쓰거나, HTML 파일을 app.py와 같은 폴더에 넣으면 Flask가 파일을 못 찾는다. 이때 에러 메시지: jinja2.exceptions.TemplateNotFound: index.html — 이 에러가 나면 폴더 이름과 위치를 확인하자!

민수의 깨달음
"아... 그러니까 Flask는 배달부고, HTML은 상품이고, JavaScript는 상품 안에서 움직이는 부분이고, records.json은 창고인 거구나. 각자 역할이 다른데 같이 일하는 거네!"

민수는 코드를 한 줄도 직접 쓰지 않았지만, 앱이 어떻게 돌아가는지는 완전히 이해했다. 그래서 AI에게 수정을 요청할 때도 "서버 쪽을 고쳐줘" 또는 "JavaScript에서 타이머 로직을 바꿔줘"라고 정확하게 말할 수 있게 됐다.

Chapter 3

코딩을 넘어서: AI는 코드만 쓰는 게 아니다

민수는 앱을 만들고 나서 깨달았다. "AI가 코드를 만들 수 있다면... 다른 것도 만들 수 있지 않을까?"

전환점
앱은 완성됐지만, 아무도 안 쓴다. 민수는 생각했다.
"앱을 만드는 건 시작일 뿐이구나. 사람들에게 알려야 하고, 보여줘야 하고, 매력적으로 만들어야 해."

Chapter 5

왜 "상업용"으로 생각해야 하는가

민수의 두 번째 질문
민수의 공부 타이머 앱을 본 친구가 말했다.
"야, 이거 진짜 좋다. 돈 내고 쓸래. 근데... 이걸 어떻게 팔아?"

민수는 처음으로 생각했다 — "만드는 것"과 "사업이 되는 것"은 다르구나.

취미 프로젝트 vs 상업용 프로젝트

🏠 취미 프로젝트

  • "내가 쓰려고 만든다"
  • 아무도 안 써도 괜찮다
  • 디자인은 대충
  • 에러가 좀 있어도 OK
  • 성장이 없다

🚀 상업용 프로젝트

  • "다른 사람의 문제를 해결한다"
  • 사용자가 있어야 의미가 있다
  • 첫인상이 중요하다
  • 안정적으로 작동해야 한다
  • 피드백 → 개선 → 성장

상업적 사고가 중요한 세 가지 이유

1

"다른 사람"을 위해 만들면 더 잘 만든다

내가 쓸 앱은 대충 만들어도 된다. 하지만 "누군가 돈을 내고 쓸 앱"이라고 생각하면, 자연스럽게 사용자 경험, 디자인, 안정성을 고민하게 된다. 이 고민이 실력을 키운다.

2

문제 해결 능력 = 미래의 핵심 역량

AI 시대에 가장 중요한 능력은 "코드를 잘 쓰는 것"이 아니라 "사람들의 문제를 발견하고 해결하는 것"이다. 상업적 사고는 이 능력을 훈련시킨다.

3

시작이 쉬워진 만큼, 시작하지 않을 이유가 없다

예전에는 사업을 시작하려면 최소 수천만 원이 필요했다. 지금은 AI와 노트북 한 대면 된다. 진입 장벽이 사라진 시대에, "일단 만들어보는 것"이 가장 큰 경쟁력이다.

Chapter 6

아이디어를 사업으로: 생각을 발전시키는 기술

좋은 아이디어는 처음부터 완성되지 않는다. 계속 생각하고, 조사하고, 수정하면서 날카로워진다.

아이디어 발전의 4단계

1단계: 씨앗 — "이런 거 있으면 좋겠다"

일상에서 불편한 점을 발견한다. 민수의 경우: "공부할 때 시간 관리가 안 돼."

관찰

2단계: 검증 — "나만 그런 건가?"

같은 문제를 가진 사람이 얼마나 있는지 조사한다. 인스타, 유튜브 댓글, 커뮤니티를 뒤져본다. "공부 타이머" 검색량: 월 12,000건. 비슷한 불편을 가진 사람이 많다.

조사

3단계: 벤치마킹 — "다른 사람은 어떻게 풀었지?"

경쟁 앱을 분석한다. 강점과 약점을 파악하고, "내가 더 잘할 수 있는 부분"을 찾는다.

분석

4단계: 차별화 — "내 것만의 무기는 뭐지?"

"학생 전용 + 과목별 기록 + 친구와 경쟁" — 기존 앱에 없는 조합을 찾아낸다.

창의

벤치마킹: 경쟁자에게서 배우기

벤치마킹은 "베끼기"가 아니다. 다른 사람의 해결책에서 배우고, 내 것에 적용하는 것이다.

Chapter 10

지휘자의 마인드셋: 기술보다 중요한 것

AI 오케스트라 지휘자의 5가지 원칙

1

문제부터 시작하라

"이 기술로 뭘 만들지?"가 아니라 "이 문제를 어떻게 풀지?"가 먼저다. 기술은 문제를 풀기 위한 도구일 뿐이다.

2

완벽보다 시작이 먼저다

첫 버전은 항상 부족하다. 하지만 시작하지 않으면 피드백도, 개선도, 성장도 없다. 50%짜리를 내놓고, 나머지 50%는 피드백으로 채워라.

3

계속 물어봐라

사용자에게, AI에게, 경쟁자의 제품에게 계속 질문하라. "왜 이렇게 했지?" "더 나은 방법은?" "사용자가 정말 원하는 건?"

4

AI의 한계를 알아라

AI는 훌륭한 도구이지만, 판단은 사람의 몫이다. AI가 만들어준 것을 무조건 수용하지 말고, 항상 검증하고 수정하라.

5

나만의 이야기를 만들어라

AI 도구는 누구나 쓸 수 있다. 차이를 만드는 건 "무엇에 관심을 갖느냐"와 "어떤 문제를 풀고 싶으냐"다. 나만의 관점, 나만의 경험이 곧 차별화다.

마지막 장면
30일이 지난 뒤, 민수의 책상 위에는 노트북 한 대뿐이었다.
하지만 그 안에는 — 앱이 돌아가고 있었고, 유튜브에 영상이 올라와 있었고, 인스타에 광고가 돌고 있었고, 50명의 사용자가 매일 공부 기록을 남기고 있었다.

민수가 혼자서 다 만들었을까? 아니다. AI와 함께 만들었다.
민수가 천재였을까? 아니다. 문제를 발견하고, 설명하고, 확인하고, 고치고, 반복했을 뿐이다.

바이브 코딩의 5단계. 그게 전부였다.
"코딩을 잘하는 사람"이 아니라 "설명을 잘하는 사람"이 만드는 시대.
"혼자서 다 할 수 있는 사람"이 아니라 "AI를 잘 지휘하는 사람"이 이기는 시대.
그 시대가 — 지금이다.
바이브 코딩에서 AI 오케스트라까지 기획 → 설명 → 확인 → 수정 → 반복 — 이 공식 하나로 무엇이든 만들 수 있다.
