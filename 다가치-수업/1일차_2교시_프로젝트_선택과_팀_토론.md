# 1일차 2교시 — 10가지 프로젝트 중 하나를 고르자

> **대상** : 중학교 2학년 (12세 눈높이)
> **시간** : 2교시 (1교시에서 AI 시대 교육 이야기를 들은 직후)
> **목표** : 10가지 아이디어를 살펴보고, 팀이 직접 토론해서 "우리가 만들 프로젝트"를 결정한다
> **산출물** : 팀별 한 줄 기획서 + 역할 분담표
> **핵심** : 선생님이 정해주는 게 아니라, **팀원이 직접 토론해서 고른다** (학생 주도성)

---

## 이 시간의 흐름

```
[1교시에서 배운 것]
  세상이 바뀌고 있다 / AI 시대 공부법 / 기획 > 코딩

        ↓

[2교시 — 지금]
  "그래서 우리가 직접 만들어볼 거야"
  10가지 아이디어 소개 → 팀 토론 → 프로젝트 확정

        ↓

[2~4일차]
  선택한 프로젝트를 바이브 코딩으로 실제로 만든다
```

# PART 1. 바이브 코딩 라이브 데모 (10분)

---

## 1-1. "말만 했는데 앱이 나왔어?"

2교시 시작하자마자, 선생님이 직접 보여준다.

```
선생님: "급식 별점 앱 만들어줘. 
        오늘 메뉴가 위에 보이고, 
        별점을 1~5점으로 매기는 슬라이더가 있고, 
        제출 버튼이 있어. 
        Python Streamlit으로 만들어줘."

→ AI가 코드를 만든다 (30초)
→ 터미널에서 실행한다 (10초)
→ 브라우저에 앱이 뜬다

학생 반응: "와, 말만 했는데 앱이 나왔어?"
```

> 이 순간이 이 수업 전체의 시작점이다.
> "코딩 몰라도 되네? 나도 할 수 있겠는데?"
> 이 자신감이 나머지 3일의 연료다.

---

## 1-2. 바이브 코딩이란 — 30초 복습

```
바이브 코딩 = AI에게 "원하는 것"을 말로 설명하면 AI가 코드를 만들어주는 것

사람이 하는 것          AI가 하는 것
──────────────        ──────────────
"뭘 만들지?" 정하기    코드 작성
"누가 쓸 건데?" 생각   에러 수정
"이거 괜찮아?" 판단    반복 작업
전체 구조 설계         세부 구현
```

> 코딩 문법을 외울 필요 없다.
> 한국어로 말하면 된다.
> 대신 **"뭘 만들지 정확히 정하는 것"**이 중요하다.
> 그래서 지금부터 할 것이 → **프로젝트를 고르는 것**이다.

---

## 1-3. 우리가 쓸 도구 — Python + Streamlit

| 도구 | 뭔데? | 비유 |
|---|---|---|
| **Python** | 프로그래밍 언어 | 요리 재료 |
| **Streamlit** | Python으로 웹앱을 쉽게 만드는 도구 | 레고 블록 (조립만 하면 앱이 됨) |
| **AI (Claude / ChatGPT)** | 코드를 대신 짜주는 도우미 | 전문 요리사 (내가 메뉴만 정하면 만들어줌) |

```
Python만 쓰면 → 까만 화면에 글자만 나옴 (재미없음)
Python + Streamlit → 버튼, 슬라이더, 차트가 있는 웹앱이 나옴 (재미있음)
Python + Streamlit + AI → 말만 하면 웹앱이 나옴 (마법)
```

---

## 1-4. 프론트엔드만으로 할 수 있는 것 vs 서버가 필요한 것

프로젝트를 고르기 전에, 하나만 알면 된다.

```
┌─────────────────────────────────────────────────────┐
│  "나만 쓰고, 내 컴퓨터에만 저장하면 되면"            │
│  → 서버 없이 만들 수 있다 (프론트엔드만)              │
│                                                     │
│  "여러 사람이 동시에 쓰고, 데이터를 모아야 하면"      │
│  → 서버가 필요하다                                   │
└─────────────────────────────────────────────────────┘
```

| 상황 | 서버 필요? | 이유 |
|---|---|---|
| 나만 공부 기록 볼래 | 필요 없음 | 내 브라우저에 저장하면 끝 |
| 친구랑 공부 시간 비교 | 필요함 | 친구 데이터를 모아야 하니까 |
| 혼자 하는 방탈출 게임 | 필요 없음 | 내 화면에서만 돌아가면 됨 |
| 전교생 급식 별점 수집 | 필요함 | 여러 명의 별점을 합쳐야 하니까 |

> **이 수업에서는 서버 없이 만들 수 있는 프로젝트를 한다.**
> 핵심 기능을 먼저 만들고 → 나중에 서버를 붙이면 진짜 서비스가 된다.

# PART 2. 10가지 프로젝트 아이디어 소개 (20분)

---

## 소개 전 안내

```
지금부터 10가지 아이디어를 보여줄 거야.
전부 Python + Streamlit으로 만들 수 있어.
전부 바이브 코딩으로 만들 거야. 코딩 몰라도 돼.

규칙:
1. 10개 중 하나를 팀이 골라도 되고
2. 10개에 없는 걸 직접 만들어도 돼
3. 2개를 합쳐도 돼
4. 중요한 건 "우리 팀이 왜 이걸 만드는가" 이유가 있어야 해
```

---

## 아이디어 ① 감정 방탈출 게임

```
한 줄 설명: 감정을 입력하면 스토리가 갈라지는 텍스트 방탈출 게임
누가 쓰나 : 쉬는 시간에 3분 놀이를 찾는 친구들
핵심 기능 : 감정 입력 → 방 이동 → 선택지 → 유형 결과
서버 필요 : 아니오
```

| 항목 | 내용 |
|---|---|
| 화면 수 | 3~5개 (인트로 → 방 2~3개 → 엔딩) |
| 핵심 로직 | 선택지를 고르면 다음 방으로 이동 (상태 머신) |
| 바이럴 포인트 | "나는 🦁 용감한 탐험가래ㅋㅋ" 결과 캡처 공유 |
| 재미 요소 | 감정에 따라 스토리가 달라짐 → 여러 번 플레이 |

```
플레이 흐름:
  "지금 기분을 한 단어로?" 입력
    → 긍정이면 밝은 방 → 모험 스토리
    → 부정이면 어두운 방 → 위로 스토리
    → 모르겠으면 미스터리 방 → 퍼즐 스토리
  방마다 선택지 2개 → 엔딩에서 "당신의 유형" 결과
```

```

| 항목 | 내용 |

```

```

```

> "이 아이디어를 Streamlit으로 만들 수 있어?"

# PART 4. 팀 토론 — 프로젝트를 정하자 (15분)

---

## 4-1. 팀 구성 (이미 되어 있다면 건너뛰기)

```
5명 = 1팀

역할:
  PM (진행)     — 토론 진행, 시간 관리, 의견 조율
  기획          — 아이디어 구체화, 한 줄 기획서 작성
  화면 담당     — 화면 구성 스케치, UI 아이디어
  데이터 담당   — 어떤 데이터를 저장하고 보여줄지 정리
  발표 담당     — 매 수업 산출물 기록, 최종 발표 준비

※ 역할은 책임 영역이지, 코딩 면제가 아님
   바이브 코딩은 전원이 직접 한다
```

---

## 4-2. 토론 진행 방법

### Step 1 — 개인 투표 (3분)

```
각자 종이에 적는다:

  1순위: ___번
  2순위: ___번
  이유: _________________________

종이를 테이블 가운데에 모은다.
```

### Step 2 — 결과 공개 & 토론 (7분)

```
PM이 진행한다.

"1순위 결과 발표합니다"
  → 같은 번호가 3표 이상이면 → 바로 확정
  → 의견이 갈리면 → 토론

토론할 때 물어볼 질문 3가지:

  1. "이거 만들면 누가 쓸까?"
     (대답 못 하면 → 그 아이디어는 빠진다)

  2. "3일 안에 핵심 기능을 만들 수 있을까?"
     (너무 어려우면 → 더 쉬운 것으로)

  3. "만들었을 때 뿌듯할까? 보여주고 싶을까?"
     (재미없으면 → 동기가 안 생긴다)
```

### Step 3 — 최종 확정 (2분)

```
PM: "그러면 우리 팀은 [___번 / 자유 아이디어]로 하겠습니다."

전원 동의하면 → 확정
동의 안 하는 팀원이 있으면 → 그 사람의 의견을 3분 더 듣고 다수결
```

## 4-3. 토론이 막힐 때 — 선생님이 써먹는 질문

| 상황 | 선생님 질문 |
|---|---|
| 아무도 의견이 없을 때 | "10개 중에서 '이건 절대 안 하고 싶다' 하는 거 하나만 말해봐" |
| 2개로 좁혀졌는데 못 고를 때 | "둘 다 만든다고 치면, 어느 쪽이 내일 친구한테 보여주고 싶어?" |
| 한 명이 강하게 밀 때 | "그 아이디어를 쓰는 사람이 누구인지 30초만 설명해봐" |
| 전혀 다른 걸 하고 싶다고 할 때 | "좋아! Two-Word Test 해보자. 좋아하는 거 + 문제, 두 단어 말해봐" |

## 5-3. 화면 흐름도 스케치 (종이에 그리기)

프로젝트를 정했으면, **종이에 화면 흐름을 그린다.**
코드를 짜기 전에 "어떤 화면이 어떤 순서로 나오는지"를 먼저 정해야 한다.

```
[화면 흐름도 그리는 법]

1. A4 종이를 가로로 놓는다
2. 네모칸을 그린다 = 화면 1개
3. 화면 안에 "뭐가 보이는지" 간단히 적는다
4. 화면과 화면 사이에 화살표를 그린다
5. 화살표 위에 "어떤 행동을 하면 넘어가는지" 적는다
```

### 예시 — 급식 별점 앱 화면 흐름도

```
┌──────────────┐     버튼 클릭    ┌──────────────┐
│  [화면 1]     │  ──────────→   │  [화면 2]     │
│  오늘 급식    │                │  대시보드     │
│  별점 입력    │                │  TOP 5 차트   │
│  제출 버튼    │   ←──────────  │  WORST 3      │
└──────────────┘     탭 전환     └──────────────┘
```

### 예시 — 방탈출 게임 화면 흐름도

```
┌──────────┐   감정 입력   ┌──────────┐   선택지A   ┌──────────┐
│ 인트로    │ ──────────→ │ 1번째 방  │ ─────────→ │ 2번째 방  │
│ 감정 입력 │             │ 선택지 2개│             │ 선택지 2개│
└──────────┘             └──────────┘             └──────────┘
                                                       │
                                                  마지막 선택
                                                       │
                                                       ↓
                                                 ┌──────────┐
                                                 │  엔딩     │
                                                 │  유형 결과 │
                                                 │  공유 버튼 │
                                                 └──────────┘
```

> **이 종이 스케치가 있으면 → AI한테 "이거 만들어줘"라고 정확하게 말할 수 있다.**
> 스케치 없이 "앱 만들어줘"라고 하면 → AI도 뭘 만들지 모른다.

## 6-2. 다음 시간 예고

```
다음 시간 (2일차)에 할 것:

1. 화면 흐름도를 바탕으로 → 첫 번째 화면을 바이브 코딩으로 만든다
2. AI에게 "이거 만들어줘"라고 말한다
3. 결과를 보고 "이거 바꿔줘"라고 다시 말한다
4. 핵심 기능 하나가 작동하는 걸 확인한다

준비물:
  · 노트북 (또는 학교 컴퓨터)
  · 오늘 작성한 한 줄 기획서 + 화면 흐름도
  · AI 도구 접속 가능해야 함 (Claude / ChatGPT)
```

---

## 6-3. 오늘 2교시 핵심 요약

```
1. 코딩 몰라도 된다
   → AI한테 한국어로 말하면 된다 (바이브 코딩)

2. 중요한 건 "뭘 만들지" 정하는 것
   → 코드는 AI가 짠다. 기획은 사람이 한다.

3. 한 줄 기획서가 프로젝트의 방향타
   → [누가] [무엇을] [왜] — 이 세 가지가 명확하면 길을 잃지 않는다

4. 종이 스케치가 있어야 AI한테 정확히 요청할 수 있다
   → 머릿속으로만 생각하면 AI도 뭘 만들지 모른다

5. 다음 시간부터 진짜 만든다
   → 오늘 정한 프로젝트를, 바이브 코딩으로, 3일 안에 완성한다
```

# 부록 B. 프로젝트별 바이브 코딩 첫 프롬프트 예시

2일차에 각 팀이 AI에게 처음으로 할 요청의 예시.

| 프로젝트 | 첫 번째 바이브 코딩 프롬프트 |
|---|---|
| ① 방탈출 | "Streamlit으로 텍스트 방탈출 게임 만들어줘. session_state로 현재 방을 관리하고, 방마다 스토리 텍스트와 선택지 2개를 st.button으로 보여줘. 선택하면 다음 방으로 이동해." |
| ② 설문 | "Streamlit으로 설문 조사 앱 만들어줘. 질문 5개를 입력받는 화면, 응답하는 화면, 결과를 바 차트로 보여주는 대시보드 3개 탭으로." |
| ③ 취향 테스트 | "Streamlit으로 취향 테스트 앱 만들어줘. 질문 5개를 하나씩 보여주고(st.radio), 선택지별로 유형 점수가 있어. 5개 다 답하면 점수 합산해서 가장 높은 유형 결과 카드를 보여줘." |
| ④ 급식 별점 | "Streamlit으로 급식 별점 앱 만들어줘. 오늘 메뉴를 위에 표시하고, 1~5점 슬라이더와 한줄평 입력, 제출 버튼. 대시보드 탭에서 메뉴별 평균 랭킹 차트." |
| ⑤ 공부 타이머 | "Streamlit으로 뽀모도로 타이머 만들어줘. 과목 선택 드롭다운, 25분 카운트다운 타이머, 시작/정지/리셋 버튼. 완료하면 기록 저장, 주간 차트." |
| ⑥ AI 튜터 | "Streamlit으로 수학 튜터 챗봇 만들어줘. st.chat_message로 채팅 UI, 시스템 프롬프트는 '중2 수학 선생님, 단계별로 설명, 격려하면서'. 대화 이력 유지." |
| ⑦ 플레이리스트 | "Streamlit으로 무드 기반 노래 추천 앱 만들어줘. 무드 4개 버튼(신남/센치/잔잔/에너지), 클릭하면 JSON에서 태그 매칭해서 5곡 추천 카드로 표시." |
| ⑧ 용돈 가계부 | "Streamlit으로 용돈 가계부 만들어줘. 월 예산 입력, 지출 추가(금액/카테고리/메모), 남은 금액 표시, 카테고리별 파이 차트." |
| ⑨ 시간표 | "Streamlit으로 시간표 앱 만들어줘. 요일별 시간표를 JSON으로 관리, 오늘/내일 자동 선택, 과목별 준비물 자동 표시, 체크리스트." |
| ⑩ 환경 대시보드 | "Streamlit으로 기후 데이터 대시보드 만들어줘. 지역 드롭다운, 10년간 월별 기온 CSV를 읽어서 꺾은선 차트, 두 지역 비교 기능." |

> 이 프롬프트가 "좋은 프롬프트"인 이유:
> **[도구] + [무엇을] + [핵심 기능 나열] + [데이터 방식] + [화면 흐름]**
> 이 공식을 따랐기 때문이다.

# 부록 C. 나쁜 프롬프트 vs 좋은 프롬프트

학생들이 AI에게 처음 요청할 때 가장 많이 하는 실수.

| 나쁜 프롬프트 | 왜 나쁜가 | 좋은 프롬프트 |
|---|---|---|
| "앱 만들어줘" | AI가 뭘 만들지 모름 | "급식 별점 앱을 Streamlit으로 만들어줘. 별점 슬라이더 + 제출 버튼 + 대시보드" |
| "게임 만들어줘" | 너무 막연함 | "텍스트 방탈출 게임 만들어줘. 방 3개, 선택지 2개씩, session_state로 방 이동" |
| "예쁘게 해줘" | "예쁘다"의 기준이 없음 | "제목을 크게, 버튼에 이모지 추가, 배경색 연한 파란색으로" |
| "이거 왜 안 돼?" | AI가 뭘 봐야 하는지 모름 | "이 에러 메시지가 떴어: [에러 내용]. 원인이 뭐고 어떻게 고쳐?" |
| "다 바꿔줘" | 뭘 바꾸는지 모름 | "버튼 색을 파란색으로, 제목 폰트 크기를 24px로, 슬라이더 범위를 1~10으로" |

### 프롬프트 작성 공식

```
[도구]  +  [무엇을]  +  [핵심 기능]  +  [데이터]  +  [화면 흐름]

예:
"Streamlit으로"           ← 도구
"급식 별점 앱을 만들어줘"  ← 무엇을
"오늘 메뉴 표시, 별점 슬라이더, 한줄평, 제출 버튼"  ← 핵심 기능
"데이터는 리스트에 저장"   ← 데이터
"탭으로 입력 화면과 대시보드 분리"  ← 화면 흐름
```

> **잘 말하면 AI가 잘 만들어준다.**
> 못 말하면 AI도 이상한 걸 만든다.
> 그래서 기획이 코딩보다 중요한 거다.

# 부록 D. 프로젝트별 핵심 데이터 구조 미리보기

2일차에 바로 쓸 수 있도록, 각 프로젝트의 데이터가 어떻게 생겼는지 미리 보여준다.

### ① 방탈출 — 방 데이터

```json
{
  "rooms": [
    {
      "id": "intro",
      "text": "어두운 복도 끝에 세 개의 문이 있습니다...",
      "choices": [
        {"label": "밝은 문", "next": "room_bright"},
        {"label": "어두운 문", "next": "room_dark"}
      ]
    }
  ]
}
```

### ③ 취향 테스트 — 질문+점수 데이터

```json
{
  "questions": [
    {
      "text": "주말 오후, 뭐 하고 싶어?",
      "choices": [
        {"label": "카페에서 음악 듣기", "scores": {"healing": 3}},
        {"label": "롤러코스터 타기", "scores": {"action": 3}}
      ]
    }
  ]
}
```

### ④ 급식 별점 — 평가 데이터

```json
[
  {"date": "2026-07-21", "menu": "비빔밥", "score": 4, "comment": "맛있었어"},
  {"date": "2026-07-21", "menu": "치킨", "score": 5, "comment": "최고!"}
]
```

### ⑤ 공부 타이머 — 기록 데이터

```json
[
  {"date": "2026-07-21", "subject": "수학", "minutes": 50},
  {"date": "2026-07-21", "subject": "영어", "minutes": 25}
]
```

### ⑧ 용돈 가계부 — 지출 데이터

```json
[
  {"date": "2026-07-21", "amount": 3000, "category": "편의점", "memo": "아이스크림"},
  {"date": "2026-07-22", "amount": 1500, "category": "교통", "memo": "버스"}
]
```

> 데이터 구조를 미리 보면 → "아, 이렇게 생긴 거구나" 감이 온다.
> 감이 오면 → AI한테 "이런 데이터로 만들어줘"라고 정확하게 요청할 수 있다.
