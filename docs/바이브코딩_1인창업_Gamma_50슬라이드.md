## 바이브 코딩이란?

**Vibe Coding** = AI에게 자연어(일상 말)로 원하는 기능을 설명하면 AI가 코드를 생성하는 새로운 개발 방식

### 기존 개발 vs 바이브 코딩

| 항목 | 기존 개발 | 바이브 코딩 |
|------|-----------|-------------|
| 필요 기술 | 프로그래밍 언어 숙달 | 자연어 프롬프트 작성 |
| 개발 시간 | 수개월 | 수일~수주 |
| 비용 | 개발자 고용 필수 | 1인 개발 가능 |
| 도구 | IDE, 프레임워크 | ChatGPT, Claude Code |

> "코딩 지식 없이도 소프트웨어를 만들 수 있다"

---

## 바이브 디자인이란?

**Vibe Design** = AI 도구를 활용하여 자연어 설명만으로 UX/UI 디자인을 자동 생성하는 방식

### 핵심 도구

- **Stitch**: AI UI 디자인 생성 → 실제 코드로 변환
- **Nano Banana**: 텍스트 설명으로 로고, 일러스트, 배경 이미지 생성

### 활용 예시

```
"깔끔한 SaaS 랜딩 페이지를 만들어줘.
히어로 섹션에 큰 제목과 CTA 버튼, 
3개의 기능 카드, 요금제 비교 섹션을 포함해줘."
```

→ AI가 완성된 UI 디자인과 코드를 생성

## 페르소나 설정 (1) — 창업자 페르소나

바이브 코딩 1인 창업의 첫 단계: **"나는 누구인가"**를 정의한다

| 항목 | 질문 | 작성 예시 |
|------|------|-----------|
| **배경** | 현재 직업/전공은? | 마케팅 직장인, 비개발자 |
| **기술 수준** | 코딩 경험이 있는가? | HTML 약간 / 전혀 없음 |
| **목표** | 왜 1인 창업을 하려는가? | 월 $1,000 사이드 수익 |
| **시간** | 하루 투입 가능 시간? | 평일 2시간, 주말 5시간 |
| **자금** | 초기 투자 가능 금액? | 0원(무료 도구만) / 월 $50 이내 |
| **강점** | 남들보다 잘 아는 분야? | 패션, 요리, 여행, 교육 등 |

## 페르소나 공감 지도 (Empathy Map)

### 페르소나 A: 민지 (28, 신입사원)

| 영역 | 내용 |
|------|------|
| **생각 & 느낌** | 매일 아침 뭘 입을지 스트레스, 동료들 시선 신경 쓰임, 패션 감각 부족 |
| **보는 것** | 인스타 패션 인플루언서, 출근길 다른 직장인 옷차림, 쇼핑몰 추천 |
| **말 & 행동** | "오늘 뭐 입지...", 옷장 앞에서 30분 고민, 무난한 옷만 반복 착용 |
| **듣는 것** | "넌 항상 비슷한 옷 입어", "오늘 옷 예쁘다!", "이 조합이면 실패 없어요" |

| Pain (고통) | Gain (이득) |

| 잘못된 조합으로 후회 | 칭찬 받는 경험 |

## 페르소나 기반 서비스 방향 결정

### 의사결정 흐름

1. **창업자 페르소나 정의** (나는 누구인가)
2. **강점 분야 도출** (패션, 요리, 교육 등)
3. **사용자 페르소나 3개 생성** (AI 프롬프트 활용)
4. **핵심 고민이 반복 발생하는가?**
   - Yes → 서비스 아이디어 확정
   - No → 다른 분야 탐색
5. **수익 모델 결정** (광고 / 건당 결제 / 구독)

> 핵심: "반복되는 고민"이 있어야 사업이 된다

## STEP 1-2 — 코드 예시: 로또 알고리즘

### 핵심 JavaScript 알고리즘

```javascript
function drawLotto() {
  const numbers = [];
  while (numbers.length < 7) {
    const num = Math.floor(Math.random() * 45) + 1;
    if (!numbers.includes(num)) numbers.push(num);
  }
  const main = numbers.slice(0, 6).sort((a, b) => a - b);
  const bonus = numbers[6];
  return { main, bonus };
}

function getColor(num) {
  if (num <= 10) return '#FBC400'; // 노랑
  if (num <= 20) return '#69C8F2'; // 파랑
  if (num <= 30) return '#FF7272'; // 빨강
  if (num <= 40) return '#AAAAAA'; // 회색
  return '#B0D840';                // 초록
}
```

> 바이브 코딩 핵심: 이 코드를 직접 작성할 필요 없다. 프롬프트를 AI에게 전달하면 완성된 코드가 생성된다.

### 배포 흐름

1. 로컬에서 테스트 완료
2. GitHub 리포지터리 생성

### 배포 명령어

```bash
git init
git add .
git commit -m "Initial commit: 로또 번호 추첨기"
git branch -M main
git remote add origin https://github.com/[유저명]/lotto-app.git
git push -u origin main
```

### 수정 후 재배포 (이 3줄이 전부)

```bash
git add .
git commit -m "버튼 색상 변경 및 모바일 반응형 수정"
git push
# Cloudflare Pages가 자동으로 30초~1분 내 반영
```

## STEP 2-2 — Carrying Capacity 계산

### 공식

```
Carrying Capacity = 일일 신규 유입 / 일일 이탈률
```

### 시나리오별 비교

| 시나리오 | 일일 유입 | 이탈률 | Capacity | 전략 |
|----------|-----------|--------|----------|------|
| 현재 | 50명 | 10% | **500명** | 기준선 |
| 마케팅 강화 | 200명 | 10% | **2,000명** | 유입 4x |
| 이탈 개선 | 50명 | 3% | **1,667명** | 이탈 1/3 |
| 동시 적용 | 200명 | 3% | **6,667명** | 유입+이탈 |

### 핵심 인사이트

> **이탈률 개선이 유입 증가보다 비용 대비 효과가 크다!**
> 이탈률 10%→3%는 UX 개선만으로 가능하지만, 유입 50→200명은 마케팅 예산이 4배 필요

## STEP 2-2 — 성장 시뮬레이션 알고리즘

### JavaScript 성장 시뮬레이션

```javascript
function simulateGrowth(dailyAcquisition, dailyChurnRate, days = 30) {
  let users = 0;
  const log = [];
  for (let day = 1; day <= days; day++) {
    const churned = Math.floor(users * dailyChurnRate);
    users = users - churned + dailyAcquisition;
    log.push({ day, users, churned });
  }
  const carryingCapacity = Math.floor(dailyAcquisition / dailyChurnRate);
  return { log, carryingCapacity, finalUsers: users };
}

// 실행: simulateGrowth(100, 0.05, 30)
// Day 1: 100명 → Day 7: 523명 → Day 30: 1,785명
// Carrying Capacity: 2,000명 (약 60일 후 안정화)
```

### 성장 전략 의사결정 트리

1. Carrying Capacity에 도달했는가?
   - 아직 → 현재 전략 유지
   - 근접 → 이탈률 5% 이상? → Yes: UX 개선 / No: 유입 채널 확대

## STEP 3-3 — AI API 코드 예시

### Cloudflare Workers 서버리스 함수

```javascript
export async function onRequestPost(context) {
  const { gender, age, occasion, style } = await context.request.json();
  
  if (!gender || !age || !occasion) {
    return new Response(JSON.stringify({ error: '필수 항목을 입력해주세요.' }),
      { status: 400 });
  }

  const prompt = `패션 스타일리스트로서 ${gender}, ${age}세, ${occasion}에
    맞는 코디 3가지를 JSON으로 추천해줘`;

  const aiResponse = await fetch('https://api.openai.com/v1/chat/completions', {
    method: 'POST',
    headers: { Authorization: `Bearer ${context.env.OPENAI_API_KEY}` },
    body: JSON.stringify({
      model: 'gpt-4o-mini',
      messages: [{ role: 'user', content: prompt }]
    })
  });

  const data = await aiResponse.json();
  return new Response(JSON.stringify({
    success: true,
    recommendations: JSON.parse(data.choices[0].message.content)
  }));
}
```

- 401: API 키 만료 → 관리자 알림
- 429: Rate Limit → 지수 백오프 후 재시도
- JSON 파싱 실패 → 기본 추천 표시 (폴백)

## STEP 4-1 — DB 스키마 설계

### 테이블 구조

**profiles**
```sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY,
  email TEXT NOT NULL,
  plan TEXT DEFAULT 'free' CHECK (plan IN ('free','pro','premium')),
  usage_count INT DEFAULT 0,
  usage_reset_date DATE DEFAULT CURRENT_DATE
);
```

**subscriptions**
```sql
CREATE TABLE subscriptions (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES profiles(id),
  polar_subscription_id TEXT UNIQUE,
  plan TEXT NOT NULL,
  status TEXT DEFAULT 'active',
  current_period_end TIMESTAMPTZ
);
```

**recommendations**
```sql
CREATE TABLE recommendations (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES profiles(id),
  input_data JSONB NOT NULL,
  output_data JSONB NOT NULL,
  model_used TEXT DEFAULT 'gpt-4o-mini',
  tokens_used INT
);
```

## STEP 4-1 — RLS 보안 & 사용량 제한

### Row Level Security (RLS) 정책

```sql
-- 사용자는 자기 데이터만 조회/수정 가능
CREATE POLICY "Users can view own profile"
  ON profiles FOR SELECT USING (auth.uid() = id);
CREATE POLICY "Users can view own recommendations"
  ON recommendations FOR SELECT USING (auth.uid() = user_id);
```

### 사용량 제한 알고리즘

1. **인증 토큰 유효성 확인** → 실패: 401 Unauthorized
2. **날짜 변경 시 카운터 리셋** → usage_count = 0
3. **플랜별 한도 확인** → free: 3회, pro/premium: 무제한
4. **한도 초과** → 429 + "업그레이드 하시겠습니까?"
5. **AI 추천 처리** → usage_count + 1 → 200 OK

## STEP 4-2 — 구독 모델 & 비즈니스 공식

### 핵심 공식

```
월 매출 = 유료 사용자 수 × ARPU
LTV = ARPU × 평균 구독 개월 수
CAC = 총 마케팅 비용 / 신규 유료 사용자 수
지속 가능 조건: LTV > 3 × CAC
```

### 실전 계산 예시

| 지표 | 값 |
|------|-----|
| 유료 사용자 | 200명 |
| ARPU | $9.99/월 |
| 월 매출 | $1,998 |
| 평균 구독 | 6개월 |
| LTV | $59.94 |
| 월 마케팅비 | $500 |
| 신규 유료/월 | 50명 |
| CAC | $10 |
| **LTV($59.94) > 3×CAC($30)** | **지속 가능** |

## STEP 4-2 — Webhook 결제 이벤트 처리

### Polar Webhook 이벤트 흐름

| 이벤트 | 트리거 | DB 처리 |
|--------|--------|---------|
| `subscription.created` | 신규 구독 결제 | subscriptions INSERT + plan 업그레이드 |
| `subscription.updated` | 구독 갱신 | period_end 갱신 |
| `subscription.canceled` | 해지 요청 | status = 'canceled' (만료일까지 사용 가능) |
| `subscription.revoked` | 만료일 도달 | plan = 'free', status = 'expired' |

### 전체 흐름

1. 사용자 → Polar: 구독 결제
2. Polar → Workers: POST /api/webhook/polar
3. Workers: 서명 검증
4. Workers → Supabase: DB 업데이트
5. Workers → Polar: 200 OK

```javascript
export async function onRequestPost(context) {
  const payload = await context.request.json();
  const { type, data } = payload;

  switch (type) {
    case 'subscription.created':
      await supabase.from('subscriptions').insert({
        user_id: data.metadata.user_id,
        polar_subscription_id: data.id,
        plan: data.product.name.toLowerCase(),
        status: 'active',
        current_period_end: data.current_period_end,
      });
      await supabase.from('profiles')
        .update({ plan: data.product.name.toLowerCase() })
        .eq('id', data.metadata.user_id);
      break;
```
