## 활동내용

### 1교시 (45분) - 완성된 프론트엔드 시연 + 화면 설계

1. **전 회차 리뷰 + 완성 제품 프론트엔드 시연 (15분)**
   - 2회차 유저 시나리오를 팀별로 30초씩 재확인하고, 이번 회차에서 만들 화면 목록(MVP 3개)을 화이트보드에 정리하였습니다.
   - 선생님이 사전에 완성해 둔 참고 웹앱(공부 타이머, AI 공부 매니저)의 프론트엔드 화면을 다시 열어, 어떤 HTML·CSS·JS 요소들이 조합되어 이런 화면이 만들어지는지 코드와 화면을 비교하며 설명하였습니다.

2. **화면 설계(와이어프레임) 작성 - 팀별 (15분)**
   - 팀별로 준비해 온 화면 스케치를 바탕으로 메인 화면·입력 화면·결과 화면의 와이어프레임을 손그림으로 정리하였습니다.
   - 각 화면에 필요한 버튼·입력창·표시 영역을 라벨링하여 이후 프롬프트 작성 시 근거 자료로 활용하도록 하였습니다.

3. **다 함께 프롬프트 만들기 - 선생님 화면 (15분)**
   - 선생님 화면에서 학생들과 함께 첫 번째 프롬프트를 만들었습니다: "Flask 기반 웹앱의 index.html. 상단에 앱 이름, 중앙에 타이머 표시, 하단에 시작·정지·리셋 버튼."
   - 생성된 HTML을 다 같이 읽고, 두 번째 프롬프트로 "버튼 색을 파란색으로, 폰트를 크게" 같은 개선 요청을 즉석에서 반영하는 과정을 시연하였습니다.

### 2교시 (45분) - 팀별 프론트엔드 제작 + 실행

4. **팀별 프론트엔드 생성 및 각자 실행 (25분)**
   - 각 팀이 자신의 와이어프레임을 바탕으로 Claude에게 프롬프트를 작성하여 자기 팀만의 HTML을 생성하였습니다.
   - 생성된 코드를 팀 대표 노트북에 저장·실행하고, 팀원들이 각자 브라우저에서 결과를 확인하였습니다.
   - 원하는 결과가 나오지 않으면 "버튼을 더 크게", "다크 모드로" 같은 자연어 요청으로 반복 개선하며, "구체적인 프롬프트일수록 결과가 좋다"는 것을 체감하였습니다.

5. **CSS 스타일링 + JavaScript 동적 기능 추가 (15분)**
   - CSS는 "요즘 유행하는 미니멀 디자인으로 바꿔줘"처럼 추상적 요청도 실험하며 색상·폰트·여백을 다듬었습니다.
   - JavaScript는 "시작 버튼을 누르면 25분 카운트다운, 0이 되면 알림음"처럼 기능 단위로 요청하여 붙여 나갔습니다.
   - 오류가 나면 오류 메시지를 그대로 Claude에게 붙여넣어 원인을 파악·수정하는 디버깅 흐름을 함께 익혔습니다.

6. **팀별 중간 발표 및 커밋 (5분)**
   - 팀별로 완성된 화면을 1분씩 짧게 공유하고, 4회차에서 붙일 백엔드에 필요한 데이터를 미리 생각해 오도록 안내하였습니다.

## 활동소감

3일차는 학생들이 자기 팀만의 화면을 처음으로 브라우저에 띄운 시간이었습니다. 선생님 화면에서 프롬프트 예시를 함께 만든 뒤 각 팀이 자기 프롬프트를 작성하고 자기 노트북에서 실행하는 방식으로 진행하여, 90분 안에도 팀별로 실질적인 결과물이 나올 수 있었습니다. "이 버튼 색깔을 바꿔줘"라는 한 문장으로 화면이 즉시 바뀌는 것을 보며 학생들의 몰입도가 매우 높았고, 프롬프트를 짧고 모호하게 쓴 팀은 시행착오를 겪으며 "왜 구체적으로 써야 하는가"를 자연스럽게 배웠습니다.
