## 활동내용

### 1교시 (45분) - 10가지 주제 제시 + 팀별 토론 및 선정

1. **10가지 앱 주제 소개 (15분)**
   - 학생들이 4회차 안에 완성할 수 있는 규모의 10가지 웹앱 주제를 하나씩 화면에 띄우며 소개하였습니다: 공부 타이머, 할 일 관리, 가계부, 습관 트래커, 독서 기록장, 운동 기록, 감정 일기, 급식 메뉴 알리미, 학급 투표, 미니 게시판.
   - 각 주제별로 "이 앱은 누구를 위한 것인지", "어떤 문제를 해결하는지", "어떤 기능이 핵심인지"를 짧게 설명하여 학생들이 선택의 기준을 가질 수 있도록 하였습니다.
   - 단순히 "만들고 싶은 것"이 아니라 "사용자의 불편을 해결하는 것"이 좋은 앱의 출발점임을 1일차 링고팡 사례와 연결하여 다시 강조하였습니다.

2. **팀별 주제 토론 및 선정 (25분)**
   - 팀별로 10가지 주제 중 관심 있는 2~3개를 먼저 추려내고, 각각의 장단점을 자유롭게 토론하는 시간을 가졌습니다.
   - 토론 시 고려할 기준을 제시하였습니다: **①우리 팀이 직접 쓸 수 있는가** ②4회차 안에 만들 수 있는 규모인가 ③기존에 비슷한 앱과 뭐가 다른가.
   - 최종 1개 주제를 팀원 합의로 선정하고, "왜 이 주제를 골랐는가", "누가 쓸 것인가", "핵심 기능 3가지"를 A4 한 장에 정리하였습니다.
   - 팀별로 선정 결과를 1분씩 짧게 발표하여 다른 팀의 선택과 이유를 서로 공유하였습니다.

3. **주제 선정 정리 (5분)**
   - 각 팀의 최종 주제와 핵심 기능 3가지를 화이트보드에 한눈에 정리하고, 3·4회차에서 이를 기반으로 개발할 것임을 확인하였습니다.

### 2교시 (45분) - 바이브 코딩 개발론 + 프롬프트 기반 개발 흐름

4. **바이브 코딩 개발론 강의 - "프롬프트로 이렇게 동작한다" (25분)**
   - 전통적 개발(설계 → 코딩 → 테스트)과 바이브 코딩 개발(기획 → 프롬프트 → 생성 → 읽고 수정 → 재요청)의 차이를 체계적으로 설명하였습니다.
   - 바이브 코딩의 개발 흐름을 단계별로 풀어 보여주었습니다:
     - **1단계**: 무엇을 만들 것인지 기획 (유저 시나리오)
     - **2단계**: AI에게 프롬프트로 코드 생성을 요청
     - **3단계**: 생성된 코드를 실행하여 결과 확인
     - **4단계**: 원하는 대로 나오지 않은 부분을 추가 프롬프트로 수정 요청
     - **5단계**: 반복하여 완성
   - 선생님 화면에서 실제 프롬프트를 던지고, AI가 코드를 생성하고, 실행하고, 추가 요청으로 수정하는 전체 사이클을 실시간으로 시연하였습니다.
   - 좋은 프롬프트의 핵심 요소(맥락·역할·목표·제약)를 예시와 함께 설명하고, 모호한 프롬프트 vs 구체적 프롬프트의 결과 차이를 비교하였습니다.

5. **유저 시나리오 작성 실습 (15분)**
   - 선정한 주제를 바탕으로 팀별 유저 시나리오를 작성하였습니다:
     - **누가 쓸까?** - 대상 사용자 구체화 (예: "시험 기간에 공부 시간을 체크하고 싶은 중학생")
     - **뭐가 불편할까?** - 현재 사용자의 불편 (예: "기존 타이머 앱은 공부 기록이 안 남고 광고가 많음")
     - **비슷한 건 뭐가 있을까?** - 차별점 도출 (예: "공부 기록이 통계로 남고 광고 없는 무료 앱")
   - 이 시나리오 문서가 3·4회차에서 AI에게 전달할 프롬프트의 기초 자료가 됨을 강조하였습니다.

6. **다음 회차 준비사항 안내 (5분)**
   - 3회차에는 본격적으로 프론트엔드 화면을 만들 예정이므로, 개발 환경(Python·VS Code·Flask)을 반드시 설치해 오도록 안내하였습니다.
   - 화면 스케치(손그림)를 준비해 오면 3회차에서 바로 프롬프트로 전환할 수 있음을 안내하였습니다.

## 활동소감

2일차는 학생들이 "무엇을 만들 것인가"를 직접 결정하고 "어떻게 만들 것인가"의 프로세스를 이해하는 시간이었습니다. 10가지 주제를 보여주자 각 팀에서 활발한 토론이 이어졌고, "우리가 직접 쓸 수 있는 앱"을 기준으로 선택하는 팀이 많았습니다. 바이브 코딩 개발론 강의에서 "프롬프트 → 생성 → 실행 → 수정"의 5단계를 실시간 시연으로 보여주니, 아직 코드를 한 줄도 작성하지 않았지만 "다음 시간에 직접 해보고 싶다"는 기대감이 형성되었습니다. 기획·시나리오가 결국 프롬프트의 품질을 좌우한다는 1일차의 메시지가 자연스럽게 이어진 회차였습니다.

## 특이사항 및 요청사항

- 일부 팀이 주제의 범위를 넓게 잡아 4회차 내 구현이 어려울 수 있어, 3회차 초반에 핵심 기능 3개로 범위를 재조정하는 시간을 짧게 잡을 예정입니다.
- 2회차까지 개발 환경을 미리 설치하지 못한 학생들이 있어, 3회차 초반에 신속한 셋팅 지원을 위해 사전 설치 가이드를 사무국을 통해 배포 요청드립니다.
- 팀별 유저 시나리오 문서는 이후 결과 보고서의 기초 자료로 활용할 예정이므로 별도 보관하겠습니다.
